# 限流修改任务清单

## 1. Verdict

部分同意：`docs/限流修改方案.md` 可以进入实施拆解，但不能直接按“修 Coinglass”开工。

已确认的阻断事实是：现有 `MongoCacheStore`、`MongoSingleFlightCoordinator`、`MongoRateLimitStore` 和 `RunProviderPlan.rate_limit_plan` 已存在，但 `ProviderExecutionEvidenceHelper.execute()` 仍直接调用 `adapter.fetch()`；`ProviderAttempt.single_flight_role` 在执行 helper 里仍写为 `none`。`memory/2026-05-26.md` 也确认 `/report AR/USDT` 的复发点不是 key 缺失或 worker 重复调用，而是 Coinglass `onchain_signals` 内部连续拆出多个 HTTP 子请求，尤其稳定币净流等子接口继续撞 429。

因此实施必须同时覆盖两层：

- provider call spec 级：cache / rate-limit / single-flight。
- HTTP 子请求级：provider 内部多次请求、429 冷却、子请求缓存、复合接口短路。

前置不阻断拆解，但阻断直接宣称完成：全仓外部出网路径、SDK 内部 HTTP 可控性、各 provider 官方限流规则和 UI probe 绕行情况仍需 Phase 0 补证据。证据不足处在任务中标为 `无法判断`，不得用 mock/stub/fake/capture-only 代替 live 证明。

## 2. Assumptions

- 本任务清单只生成实施计划；当前不实现代码，不修改除本文档外的文件。
- “所有外部出网路径”包括 `/report` 资料包路径、provider 内部显式 HTTP、OpenBB/Tushare/AKShare 等 SDK 内部出网、UI 数据源测试页、价格提醒即时 probe。
- OpenViking 只做 approved material、manifest、lineage、readback、证据索引；不做 provider cache、限流或外部 provider 调用。
- SDK 内部 HTTP 无法完全接管时，只能作为 `SDK capture only` 残余风险处理；provider-call gate 仍必须生效，capture-only 不能冒充子请求闸门完成。
- 所有 live/fresh 验收都必须按 AGENTS fixed runtime preflight 使用 `scripts/start-control-runtime.sh -- <command>`，并按 collect-first 收集失败。

## 7. Completion Standard

限流修改只有同时满足以下条件才能关闭：

- `ProviderExecutionGate` 覆盖 market、fundamental、news、social、policy、hot_money、lockup 所有 pack domain。
- `RunProviderPlan.rate_limit_plan` 在 runtime 被实际消费；缺 plan、版本不匹配、call key 不匹配显式失败。
- 所有显式 HTTP 出网路径迁移到 `ManagedHttpClient`，或在 T-11 中以人工确认的 `SDK capture only` 记录残余风险。
- Mongo 中可查 provider-call cache、single-flight owner/consumer、rate-limit reserve、provider cooldown、HTTP 子请求 cache/cooldown。
- AR/USDT live run 证明 Coinglass core 429 后不继续打 USDT/USDC stablecoin netflow 等低优先级子接口。
- WIF/USDT live run 证明 provider 不支持或覆盖不足时不重复撞远端，不伪造数据。
- BTC/USDT live run 证明 BTC 专属 AHR999/onchain 指标仍能正常取数，或真实缺口被记录。
- 600519 live run 证明 EastMoney/CNInfo/THS/Tushare/AKShare 相关路径不绕过闸门，七域 attempts/readiness/data gaps 清晰。
- AAPL live run 证明 Yahoo/OpenBB SDK/SEC/FRED/Stocktwits/Google News 相关路径不绕过闸门。
- 00700.HK 或 00005.HK live run 证明 Yahoo/Tushare/AKShare/HKEX 路径不绕过闸门，SDK capture-only 风险如实记录。
- UI 数据源测试页连续点击和价格提醒 probe 不会连续重复打远端。
- reader-facing 报告只说明真实缺口，不出现假数据、假成功、假来源、假图表。
- 不使用 mock/stub/fake/capture-only 替代 live 证明；capture-only 只能作为 SDK 内部 HTTP 残余风险证据。
- 不新增 fallback，不放松 truthfulness hard gate，不改变 PM final decision authority，不把 OpenViking 做成 provider cache。
