# 合作伙伴未知硬件测试版交付设计

日期：2026-06-22
状态：辩论评审后修订稿

## 目标

给合作伙伴一个可安装到未知 Ubuntu x86 硬件上的 claw-trade 测试版，同时降低被直接复制、长期滥用和泄露后无法归因的风险。

第一版目标是：

- 合作伙伴能在自己的硬件上完成兼容性和业务流程测试；
- 不交付源码仓库、`.git`、测试文件、开发脚本和签名私钥；
- 每个合作伙伴拿到独立授权码和签名 partner manifest；
- 测试授权可限时、绑定机器、远程吊销；如 Virbox 配置层天然支持，再启用限次；
- 泄露后能追踪到合作伙伴；
- 不承诺防 root、拆盘、内存 dump、动态调试或专业逆向。

## 结论

第一版使用 **Virbox 软许可 + 无源码安装包 + 签名 partner manifest + 短期联网授权 + 水印追踪**。

暂不把 Virbox Protector、Virbox Compiler、native loader、TPM、Secure Boot、磁盘加密放进第一版测试包。它们会提高逆向成本，但也会提高未知硬件兼容和排障成本。

## 已确定决策

- 授权底座：Virbox 软许可。
- 授权形态：每个合作伙伴一个授权码。
- 硬件场景：未知 Ubuntu x86_64 设备。
- 测试版有效期：默认 7 到 14 天。
- 离线宽限期：默认 24 到 72 小时。
- 报告次数：第一版默认不在应用内自研计数；只有 Virbox 配置层天然支持时才启用，建议默认 30 次。
- 授权失败表现：禁止报告生成、数据刷新和 OpenClaw 报告工作流；保留授权修复、网络诊断和脱敏日志导出。
- 交付方式：`.deb` 或等价离线安装包 + 授权码 + 安装说明 + 测试清单。
- 防护口径：防直接源码交付、普通复制、长期滥用，并提供泄露追踪；不承诺运行资产、prompt、模板或 Python/Node 包不可被提取。

## 来源依据

Virbox 官网公开列出软许可、授权码、Virbox Protector、Virbox Compiler 等产品能力：

- 软许可：在线/离线皆可使用，不受网络限制；
- 授权码：支持一机一码、一码多机、集团授权码；
- Virbox Protector：加壳工具；
- Virbox Compiler：编译期混淆、虚拟化、字符串加密等保护。

实施前必须用 Virbox 官方 Linux x86 SDK/API 做实机验证。官网产品介绍不能替代本项目运行时兼容验证。

## 威胁模型

第一版防：

- 合作伙伴直接复制源码仓库；
- 未授权机器生成报告；
- 授权过期后继续长期使用；
- 同一个测试包或 partner manifest 被转交给其它公司后无法追踪；
- 普通用户打开安装目录看到源码、测试文件、开发形态 prompt/agent 源目录或开发脚本；
- 前端伪造授权有效状态；
- 日志或诊断包泄露 API KEY。

第一版不防：

- 合作伙伴获得 root 后 patch 授权判断；
- 拆盘读取本地文件；
- 内存 dump；
- 动态调试 Python/Node/浏览器进程；
- 从构建产物中提取运行资产、prompt、模板或 Python/Node 包；
- 定向反编译和专业逆向；
- 授权设备运行时材料被 root 级攻击者截获。

## 交付包

第一版优先使用同一个无源码安装包，加每个合作伙伴独立的签名 partner manifest 和授权码。只有水印必须编译进二进制时，才生成合作伙伴专属 `.deb`。

```text
claw-trade-test-<version>.deb
partner-<partner_id>.manifest.json
partner-<partner_id>.manifest.json.sig
license-code-<partner_id>.txt
claw-trade-preflight
install-guide.md
test-checklist.md
sha256sums.txt
sha256sums.txt.sig
```

安装到：

```text
/opt/claw-trade/
  current/
  shared/
```

包内不放：

- `.git`；
- `src/`；
- `tests/`；
- 开发脚本；
- `.env.local`；
- 签名私钥；
- 客户 API KEY；
- 原始开发形态的 prompt/agent 目录。

包内允许包含：

- 已构建 Python 运行包或等价可执行运行资产；
- 已编译前端；
- OpenClaw 运行时所需 dist/runtime 资产；
- 打包后的 agent 运行资产；
- systemd unit；
- Virbox runtime 或安装依赖声明；
- 公共验签密钥；
- partner manifest；
- preflight 工具。

打包后的 agent 运行资产必须保留 worker 身份、prompt、skill 和 stage policy 的运行语义。它不能是开发仓库形态的 `agents/` 源目录，但也不能被 Python 改写、压缩成摘要或替换成 direct LLM/materializer 路径。

## 依赖边界

未知硬件测试版不能把依赖安装变成猜谜。实施计划必须把依赖分成三类：

- 包内自带：claw-trade 后端运行资产、已编译前端、OpenClaw runtime/dist、systemd unit、preflight 工具、公共验签密钥；
- `.deb` 依赖安装：Python 运行所需系统库、Mongo/运行时依赖、浏览器依赖、Virbox runtime 依赖；
- 设备预置要求：Ubuntu 22.04 或 24.04 x86_64、systemd、网络访问、足够磁盘和内存。

第一版不依赖 Node/pnpm 在现场构建，不依赖 `uv run`，不从源码目录启动。若某个依赖必须走 `apt`，安装说明必须写清包名、版本范围和失败处理。

glibc 和内核版本不先做细粒度适配矩阵；preflight 只报告版本，除非已知版本会硬失败。

## 测试凭证和配置

合作伙伴测试需要的模型、数据服务、行情或其它第三方凭证不进入安装包。

两种配置方式二选一：

- 合作伙伴使用自己的 API KEY；
- 我方发放专用测试 API KEY，按合作伙伴和有效期单独管理。

凭证配置只通过产品设置页或受控命令导入，写入 `/opt/claw-trade/shared/config` 或实施计划明确的等价目录。前端不能读取明文凭证。

preflight 必须区分：

- 网络不可达；
- DNS/代理错误；
- Virbox 授权服务不可达；
- 模型或数据服务不可达；
- 凭证缺失；
- 凭证无效。

诊断包只能导出凭证状态摘要，不能导出明文 API KEY。

## 本地敏感资产权限

测试版允许合作伙伴登录自己的 Ubuntu 排障，所以本地权限边界必须写清楚。

以下文件只能由后端专用服务用户读取：

- 运行期 API KEY 或 secrets store；
- 授权码缓存；
- partner manifest 原件；
- 设备指纹原始采集值；
- Virbox runtime 缓存或宽限状态文件。

诊断包只能包含：

- partner id；
- build id；
- license 状态摘要；
- 授权错误码；
- 设备指纹摘要。

诊断包不得包含原始 MAC、磁盘序列号、BIOS 序列号、完整授权码、API KEY 或 provider payload 原文。

## 授权合同

授权状态只由后端判断，前端只能展示结果。

授权有效时：

- 允许报告生成；
- 允许数据刷新；
- 允许导出报告；
- 允许授权心跳；
- 允许设置和诊断。

授权无效、过期、超过宽限期或被吊销时：

- 禁止报告生成；
- 禁止数据刷新；
- 禁止调用 OpenClaw 报告工作流；
- 禁止导出新报告；
- 保留授权页、网络诊断和脱敏日志导出。

最小检查点：

- 服务启动；
- 打开 UI 查询授权状态；
- `/report` 开始前；
- 数据刷新前；
- 后台定时心跳，默认每 6 小时一次。

测试版不使用 30 天宽限期。30 天宽限期属于正式工控机生产版，不适合合作伙伴未知硬件测试包。

## Virbox runtime 合同

实施计划必须先锁定 Virbox Linux x86 SDK/runtime 的以下内容：

- SDK/runtime 版本；
- 安装方式：随 `.deb` 依赖安装、包内附带，或要求预装；
- 调用方式：后端进程内 SDK、命令行工具，或本机服务；
- 运行用户和所需权限；
- 激活、过期、吊销、宽限期、网络失败、runtime 不可用的错误码映射；
- 离线宽限缓存位置、权限和过期语义；
- 心跳失败后的状态转换；
- 同一授权码在第二台机器激活或运行时的失败语义；
- 机器指纹漂移规则；
- 诊断包里的 Virbox 状态摘要字段。

状态映射必须至少覆盖：

- 未激活；
- 已激活；
- 宽限期内；
- 超过宽限期；
- 已过期；
- 已吊销；
- 机器不匹配；
- runtime 不可用；
- 网络不可达；
- 凭证或授权码无效。

Virbox runtime 不可用时，产品显示授权故障，只开放授权修复、网络诊断和脱敏日志导出。

## 机器绑定和限额

首次激活时绑定机器指纹。

机器指纹只用于授权判断和追踪，不作为安全承诺。未知硬件环境下，机器指纹必须允许少量硬件漂移，例如网卡变化、磁盘序列号不可读或 BIOS 信息缺失。

默认限制：

- 单授权码绑定 1 台机器；
- 报告次数限制仅在 Virbox 配置层天然支持时启用，建议 30 次；
- 有效期 7 到 14 天；
- 离线宽限 24 到 72 小时；
- 可远程吊销。

如合作伙伴需要多台机器测试，发多个授权码，不扩大单码绑定范围。

如启用报告次数限制，扣减规则为：

- 成功生成并保存最终报告后扣 1 次；
- 授权失败、preflight 失败、数据源失败、模型失败、用户取消不扣；
- 导出现有报告不扣；
- UI 必须展示剩余额度或“未启用次数限制”。

## 水印和追踪

每个测试包必须写入：

- partner id；
- build id；
- license id；
- 过期时间。

package hash、manifest hash 和生成时间保存在 partner manifest 和诊断包摘要中，不必进入每个运行面。

水印位置：

- partner manifest；
- 后端启动日志；
- 脱敏诊断包；
- 报告 metadata；
- 报告页脚弱可见水印。

报告页脚建议：

```text
测试版，仅供 <partner_id> 评估使用，禁止转发或商用。
```

水印不能包含客户 API KEY、完整授权码或其它 secrets。

水印用于追责和泄露归因，不是防复制技术。结构化 metadata 和 partner manifest 优先于页脚弱水印；页脚水印只做提示。

## 未知硬件 preflight

安装前必须运行 `claw-trade-preflight`。`.deb preinst` 只做架构、磁盘、权限这类快速阻塞检查；完整网络、Virbox 和凭证检查由独立 preflight 工具执行，方便合作伙伴把报告发回。

最低要求：

- Ubuntu 22.04 或 24.04 x86_64；
- 8GB RAM；
- 50GB 可用磁盘；
- 可访问 Virbox 授权服务；
- 可访问模型和数据服务；
- systemd 可用；
- 必要端口未被占用。

preflight 结果分三级：

- `PASS`：可以安装或继续测试；
- `WARN`：可继续测试，但报告里必须说明风险，例如 kiosk 依赖缺失；
- `BLOCK`：不能安装或不能进入报告测试，例如架构不匹配、磁盘不足、Virbox 不可用、模型/数据服务不可达。

preflight 检查：

- CPU 架构；
- Ubuntu 版本；
- glibc 版本；
- 磁盘空间；
- 内存；
- 端口占用；
- Virbox runtime 是否可安装或可调用；
- Virbox 授权服务网络连通；
- 模型/API 网络连通；
- 凭证缺失或无效；
- 浏览器/kiosk 依赖是否可用。

preflight 输出 `preflight.json` 和人类可读摘要，进入脱敏诊断包。浏览器/kiosk 缺失在测试版默认是 `WARN`，除非本次测试明确要求 kiosk。

## 安装和运行

第一版测试包不追求完整工控机 kiosk 锁定，只要求无源码安装和后端授权 gate 正确。

最小服务：

- `claw-trade-control.service`；
- `claw-trade-ui.service`；
- `claw-trade-license-heartbeat.timer`；
- 可选 `claw-trade-kiosk.service`。

每个服务必须从 `/opt/claw-trade/current` 启动，不依赖开发仓库、`uv run`、`pnpm build` 或 `.env.local`。

实施计划必须补实以下矩阵：

| unit | 用户 | 端口 | 环境文件 | 依赖 | 健康检查 | 日志 | 失败状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `claw-trade-control.service` | 专用服务用户 | OpenViking/OpenClaw/control 端口 | `/opt/claw-trade/shared/config/*.env` | Mongo/运行时依赖、Virbox runtime | control 和 OpenClaw health | journald + shared logs | UI 显示后端不可用 |
| `claw-trade-ui.service` | 专用服务用户 | UI 端口 | 同上 | control 可选依赖 | UI health | journald + shared logs | 浏览器显示服务不可用 |
| `claw-trade-license-heartbeat.timer` | 专用服务用户 | 无 | 同上 | Virbox runtime、网络 | 最近心跳状态 | journald + license log | UI 显示授权故障 |
| `claw-trade-kiosk.service` | kiosk 用户 | 无 | 浏览器 policy | UI service | 浏览器进程 | journald | 不影响后端测试 |

可选 kiosk 不进入第一版核心验收。未知硬件测试允许合作伙伴登录 Ubuntu 排障。

合作伙伴测试版可以允许合作伙伴登录自己的 Ubuntu 排障；因此不要把“客户不能登录 Ubuntu”作为测试版强制目标。这个目标属于正式工控机生产版。

## 更新

第一版测试包只支持手动安装新 `.deb` 或安装签名完整包。

测试版不交付生产级 updater，不承诺自动回滚。升级规则：

- 新包可以安装到新的 `/opt/claw-trade/releases/<version>`；
- `current` 可以切到新版本；
- `/opt/claw-trade/shared` 必须保留；
- 升级不得覆盖 API KEY、授权缓存、partner manifest、报告、日志和诊断包；
- 升级失败时，人工重装上一个测试包；
- 需要回滚能力时，进入正式工控机生产版 updater 设计，不在测试版第一版里实现。

不做：

- 自动远程更新；
- 多通道更新；
- 远程命令；
- factory/support endpoint；
- 出站运维 agent。

需要更新时重新发一个新的 partner 包，并保留原 partner id 和新的 build id。

## API KEY、日志和诊断包

测试版仍必须满足：

- API KEY 不进安装包；
- API KEY 不进前端响应；
- API KEY 不进日志；
- API KEY 不进诊断包明文；
- 日志导出默认脱敏；
- 诊断包默认只包含版本、授权状态摘要、preflight 结果、服务状态、健康检查和脱敏日志；
- 报告正文和 provider payload 默认不进入诊断包；
- 如必须导出报告正文或 provider payload，必须在本机界面单独确认，并继续脱敏 API KEY 和授权码。

诊断包最小结构：

```text
diagnostics/
  summary.json
  preflight.json
  license-status.json
  services.json
  ports.json
  network.json
  openclaw-health.json
  logs/
    claw-trade-control.log
    claw-trade-ui.log
    license-heartbeat.log
```

必备字段：

- partner id；
- build id；
- license 状态摘要；
- Virbox 错误码和脱敏错误说明；
- 设备指纹摘要；
- preflight `PASS/WARN/BLOCK`；
- 端口占用；
- systemd 服务状态；
- OpenClaw gateway 健康状态；
- 最近一次 `/report` 是否取得 provider payload/tool schema/runtime evidence。

## Virbox Protector / Compiler 策略

第一版不默认启用 Protector 或 Compiler。

先做验证门：

1. Virbox 软许可能在 Ubuntu x86_64 后端稳定读取授权状态；
2. Python/FastAPI 后端能稳定调用授权状态；
3. OpenClaw 报告路径在测试包内仍可运行；
4. 授权失败能锁住报告生成和数据刷新；
5. 诊断包能解释授权失败原因。

以上通过后，再评估 Protector/Compiler。

若启用，优先保护窄边界：

- 授权检查 helper；
- 服务启动入口；
- report gate；
- license heartbeat；
- partner manifest 校验。

不要第一版全量加壳整个 Python/OpenClaw 运行时。未知硬件上出了问题会难排查，且容易把兼容性测试变成加壳测试。

## OpenClaw 边界

测试版不能为了授权而改变报告架构：

- `/report` 仍由 claw-trade 控制工作流顺序；
- 12 个 TradingAgents worker 仍通过 OpenClaw wake 执行；
- OpenClaw 仍是单 agent turn runtime；
- 授权层不能改写 worker prompt、报告结论或 PM 决策；
- 授权失败时阻止进入报告工作流，而不是让 Python 生成替代报告。

测试包验收必须用 packaged `/report` 路径证明：

- 12 个 worker 仍按既有顺序运行；
- provider payload capture 可取得；
- tool schema capture 可取得；
- runtime evidence 可取得；
- 打包后的 agent 运行资产没有被 Python 摘要或重写。

如果打包改变 OpenClaw runtime 行为，必须按现有项目规则做 build、restart、fresh live proof 和 provider payload inspection。

## 验收标准

最小测试路径：

- 安装前运行 `claw-trade-preflight`；
- 安装测试包；
- 导入 partner manifest；
- 激活 Virbox 授权码；
- 配置模型和数据服务凭证；
- 成功跑一次 `/report`；
- 验证断网宽限；
- 验证过期或吊销后不能生成报告；
- 导出脱敏诊断包；
- 核验报告 metadata 或页脚水印。

授权：

- 未激活设备不能生成报告；
- 已激活设备可以生成报告；
- 过期设备不能生成报告；
- 被吊销设备不能生成报告；
- 同一授权码在第二台机器激活或运行时失败，并能在诊断包中脱敏说明原因；
- 如启用报告次数限制，超过次数后不能生成报告；
- 离线超过宽限期后不能生成报告；
- 前端不能伪造授权有效状态。

交付：

- 安装包不包含源码、`.git`、测试文件、开发脚本、`.env.local`、签名私钥和客户 API KEY；
- 安装后从 `/opt/claw-trade/current` 启动；
- 不依赖开发仓库、`uv run`、`pnpm build`；
- partner manifest 存在、签名有效且 hash 可验证；
- `shared/` 在手动升级后保留。

追踪：

- 报告 metadata 包含 partner id 和 build id；
- 脱敏诊断包包含 partner id、build id、license 状态摘要和设备指纹摘要；
- 日志不包含 API KEY 或完整授权码。

兼容：

- preflight 能在未知硬件上给出明确通过/失败原因；
- Virbox runtime 不可用时，产品显示授权故障，不进入报告工作流；
- OpenClaw 报告路径仍可取得 provider payload/tool schema/runtime evidence。

## 停止条件

遇到以下情况停止第一版测试包交付，回到设计评审：

- Virbox Linux x86 SDK/API 不能稳定读取授权状态；
- 测试所需模型、数据服务或行情凭证无法配置和验证；
- 授权失败仍能触发报告生成或数据刷新；
- partner manifest 签名无效仍能启动报告功能；
- 打包后必须依赖开发仓库才能运行；
- 诊断包泄露 API KEY、完整授权码或原始 provider payload；
- 为加壳兼容性修改 OpenClaw 或 worker prompt 边界；
- 合作伙伴要求长期离线、完整本地运行，并要求承诺防专业逆向。
