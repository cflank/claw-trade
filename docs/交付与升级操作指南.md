# claw-trade 交付与升级操作指南

这篇文档只讲一件事：怎么把 claw-trade 从发布机做成可交付的软件包，并在工控机上安装、授权、升级、回滚。

## 0. 先分清三个包

```text
普通生产包：Linux 上构建出来的 tar.gz，能安装运行，但还不是 Virbox 保护包。
Virbox 保护交付包：在普通生产包基础上，替换受保护运行时，并加密 .pyc、md、js 后重新打出的 tar.gz。
远程升级包：可以被目标机在线升级使用的 tar.gz，加了签名、manifest，并上传到七牛 stable/。
```

如果要给厂家测试或量产，默认交付 Virbox 保护交付包，不交付普通生产包。

原因很简单：

```text
普通生产包里的 Python 代码虽然是 .pyc，不是 .py 明文，但这不等于正式加密。
agents 里的 prompt md 如果不加密，厂家拿到包后能直接看。
OpenClaw 入口和插件如果不加密，也会暴露关键逻辑。
```

## 1. 发布机准备

进入仓库：

```bash
cd /home/frank/src/claw-trade
```

看代码状态：

```bash
git status
git branch --show-current
```

确认：

```text
1. 当前分支和代码就是要交付的版本。
2. 要发布的修改已经提交或明确允许带上。
3. 前端能正常构建。
4. 数据种子已经准备好。
```

生产包里会放一个“初始数据文件”。

这个文件的作用是：新机器第一次安装后，系统可以直接恢复一批历史数据，不用从零开始下载。

打包脚本只认当前初始数据文件：

```text
data/current-seed-*.tar
```

当前仓库里有：

```text
data/current-seed-20260626.tar
```

这个包是当前默认交付数据包。除非本次交付专门生成了更新的 `data/current-seed-*.tar`，否则就用它。

它包含 A 股和加密币：

```text
CN_A：daily_bar、valuation_metric、financial_statement、financial_metric、capital_flow、news/social 等。
CRYPTO：daily_bar、valuation_metric、crypto_derivative_metric、crypto_onchain_metric、news/social 等。
```

旧的 `data/a-share-cn-required-300td-20260608.tar` 已经废弃，不再作为备用包，也不再作为打包 fallback。

所以，发布前要先检查有没有最新初始数据文件：

```bash
ls -lh data/current-seed-*.tar
```

如果这里没有文件，不要继续打包。先生成本次要交付的 `current-seed`，或者确认使用现有的 `current-seed-20260626.tar`。

### 1.1 制作新的数据种子

这个动作不是重新下载数据。

它做的是：把当前机器上已经存在的数据打成一个新 seed。

当前历史数据分两部分：

```text
1. Parquet 文件：真正的历史行情、估值、财务、新闻、加密币指标等数据。
2. Mongo 元数据：告诉系统这些 Parquet 文件是什么市场、什么数据集、什么时间范围、文件在哪里。
```

所以制作新 seed 时，必须同时导出这两部分。

如果当前运行环境已经有 `.runtime/dev-services/runtime.env`，直接执行：

```bash
uv run python scripts/production/export_current_seed.py \
  --env-file .runtime/dev-services/runtime.env \
  --output data/current-seed-$(date -u +%Y%m%d).tar
```

如果同名文件已经存在，并且确认要覆盖：

```bash
uv run python scripts/production/export_current_seed.py \
  --env-file .runtime/dev-services/runtime.env \
  --output data/current-seed-$(date -u +%Y%m%d).tar \
  --replace-output
```

脚本成功后会生成两个文件：

```text
data/current-seed-YYYYMMDD.tar
data/current-seed-YYYYMMDD.tar.sha256
```

这个 `tar` 里面必须有：

```text
seed_manifest.json
mongo/raw_payloads.jsonl
mongo/provider_attempts.jsonl
mongo/dataset_manifests.jsonl
data/normalized/**/*.parquet
```

说人话：

```text
seed_manifest.json：这个 seed 的目录。
mongo/*.jsonl：数据库元数据。
data/normalized/**/*.parquet：真正的数据文件。
```

检查：

```bash
tar -tf data/current-seed-$(date -u +%Y%m%d).tar | head
sha256sum -c data/current-seed-$(date -u +%Y%m%d).tar.sha256
```

如果脚本报错 `missing Parquet`，不要继续打包。

这表示 Mongo 里记录了某个数据文件，但当前 Parquet 目录里找不到它。先修数据目录或重新跑数据导入，再重新制作 seed。

## 3. 制作 Virbox 保护交付包

实际流程是：

```text
普通生产包
-> 解包到 D 盘中转目录
-> 替换受保护 Python 和 Node
-> 用 DSProtector 加密 .pyc、OpenClaw 入口、插件 js、agents md
-> 修启动入口
-> 检查没有明文和 .ssp
-> 重新打 tar.gz
-> 上传目标 Ubuntu 真机安装验证
```

做完以后，厂家拿到的是：

```text
1. Python 解释器被 Virbox 保护。
2. Node 运行时被 Virbox 保护。
3. claw-trade Python 应用 .pyc 被 DS 加密。
4. agents 里的 prompt md 被 DS 加密。
5. OpenClaw 入口和插件 js 被 DS 加密。
6. .ssp 配置文件不进交付包。
```

### 3.1 准备 4 个保护文件

这 4 个文件不是 `claw-trade` 仓库生成的，是发布机上提前用
Windows Virbox 工具做出来的保护运行时和 DS 配置。

如果这 4 个文件不存在，不要继续做保护包。先回到 Windows Virbox
工具里准备：

```text
1. 用 Virbox 工具保护普通生产包里的 runtime/python/bin/python。
   输出：protected/python 和 python.ssp。
2. 用 Virbox 工具保护普通生产包里要运行 OpenClaw 的 Node。
   输出：protected/node.bin 和 node.ssp。
3. python.ssp 后面只给 DSProtector 加密 .pyc 用。
4. node.ssp 后面只给 DSProtector 加密 md/js/mjs 用。
```

当前验证过的 Win11 路径：

```text
D:\claw-trade-virbox\resource-test\protect-python-ds\protected\python
D:\claw-trade-virbox\resource-test\protect-python-ds\python.ssp
D:\claw-trade-virbox\node-ds-test\protected\node.bin
D:\claw-trade-virbox\node-ds-test\input\node.ssp
```

WSL 路径：

```bash
ls -lh \
  /mnt/d/claw-trade-virbox/resource-test/protect-python-ds/protected/python \
  /mnt/d/claw-trade-virbox/resource-test/protect-python-ds/python.ssp \
  /mnt/d/claw-trade-virbox/node-ds-test/protected/node.bin \
  /mnt/d/claw-trade-virbox/node-ds-test/input/node.ssp
```

这 4 个文件分别是：

```text
protected/python：交付包里真正运行 Python 代码的解释器。
python.ssp：发布机加密 .pyc 用，不交付给客户。
protected/node.bin：交付包里真正运行 OpenClaw 的 Node。
node.ssp：发布机加密 md/js/mjs 用，不交付给客户。
```

### 3.1.1 推荐：用脚本制作保护包

有了上面 4 个文件以后，不需要一条条执行 3.2 到 3.10。

直接运行：

```bash
scripts/production/build_virbox_protected_delivery_package.sh \
  --input dist/production/claw-trade-production-版本-时间.tar.gz \
  --protected-python /mnt/d/claw-trade-virbox/resource-test/protect-python-ds/protected/python \
  --python-ssp /mnt/d/claw-trade-virbox/resource-test/protect-python-ds/python.ssp \
  --protected-node /mnt/d/claw-trade-virbox/node-ds-test/protected/node.bin \
  --node-ssp /mnt/d/claw-trade-virbox/node-ds-test/input/node.ssp \
  --output-dir /mnt/d/claw-trade-virbox/delivery-output/virbox-protected-时间
```

脚本会做这些事：

```text
1. 解开普通生产包。
2. 替换受保护 Python 和 Node。
3. 用 python.ssp 加密 app/python/claw_trade 下的 .pyc。
4. 用 node.ssp 加密 OpenClaw 入口、agents md、OpenClaw 插件 js。
5. 创建 runtime/openclaw-protected。
6. 修启动脚本，让 UI/control 走受保护 OpenClaw。
7. 检查 .ssp 没进包。
8. 重新打 tar.gz 和 sha256。
```

后面的 3.2 到 3.10 是手工排查路径；正常交付优先用这个脚本。

### 3.2 解开普通生产包

设置变量：

```bash
REL_NAME="claw-trade-production-版本-时间"
PKG="dist/production/${REL_NAME}.tar.gz"
WORK="/mnt/d/claw-trade-virbox/delivery-build/${REL_NAME}"
RELEASE="${WORK}/${REL_NAME}"
```

解包：

```bash
rm -rf "$WORK"
mkdir -p "$WORK"
tar -xzf "$PKG" -C "$WORK"
```

确认关键文件存在：

```bash
ls -lh "$RELEASE/runtime/python/bin/python" "$RELEASE/runtime/node"
ls -lh "$RELEASE/bin/claw-trade-ui" "$RELEASE/bin/claw-trade-control"
```

### 3.3 替换 Python 和 Node

替换 Python：

```bash
cp /mnt/d/claw-trade-virbox/resource-test/protect-python-ds/protected/python \
  "$RELEASE/runtime/python/bin/python"
chmod 0755 "$RELEASE/runtime/python/bin/python"
```

替换 Node：

```bash
cp /mnt/d/claw-trade-virbox/node-ds-test/protected/node.bin \
  "$RELEASE/runtime/node"
chmod 0755 "$RELEASE/runtime/node"
```

### 3.4 加密 Python .pyc

不要直接在 release 目录里边加密边覆盖。先输出到临时目录，全部成功后再覆盖。

```bash
DSP="/mnt/d/sw/senseshield/sdk/Tool/VirboxProtect/bin/dsprotector_con.exe"
PY_SSP="/mnt/d/claw-trade-virbox/resource-test/protect-python-ds/python.ssp"
PY_TMP="${WORK}/_ds_python_out"

rm -rf "$PY_TMP"
mkdir -p "$PY_TMP"
```

加密范围：

```text
app/python/claw_trade/**/*.pyc
```

执行：

```bash
find "$RELEASE/app/python/claw_trade" -type f -name '*.pyc' | while read -r SRC; do
  REL="${SRC#"$RELEASE"/}"
  OUT="${PY_TMP}/${REL}"
  mkdir -p "$(dirname "$OUT")"
  "$DSP" -s "$PY_SSP" -i "$(wslpath -w "$SRC")" -o "$(wslpath -w "$OUT")" < /dev/null
done
```

覆盖回 release：

```bash
cp -a "$PY_TMP/app/python/claw_trade/." "$RELEASE/app/python/claw_trade/"
```

### 3.5 加密 OpenClaw 和 prompt 资源

```bash
NODE_SSP="/mnt/d/claw-trade-virbox/node-ds-test/input/node.ssp"
NODE_TMP="${WORK}/_ds_node_out"

rm -rf "$NODE_TMP"
mkdir -p "$NODE_TMP"
```

只加密：

```text
third_party/openclaw/openclaw.mjs
openclaw_plugins/**/*.js
agents/**/*.md
```

不要加密：

```text
agents/**/*.yaml
node_modules
package.json
普通配置文件
```

执行：

```bash
{
  printf '%s\n' "$RELEASE/third_party/openclaw/openclaw.mjs"
  find "$RELEASE/openclaw_plugins" -type f -name '*.js'
  find "$RELEASE/agents" -type f -name '*.md'
} | while read -r SRC; do
  REL="${SRC#"$RELEASE"/}"
  OUT="${NODE_TMP}/${REL}"
  mkdir -p "$(dirname "$OUT")"
  "$DSP" -s "$NODE_SSP" -i "$(wslpath -w "$SRC")" -o "$(wslpath -w "$OUT")" < /dev/null
done
```

覆盖回 release：

```bash
cp -a "$NODE_TMP/third_party/openclaw/openclaw.mjs" "$RELEASE/third_party/openclaw/openclaw.mjs"
cp -a "$NODE_TMP/openclaw_plugins/." "$RELEASE/openclaw_plugins/"
cp -a "$NODE_TMP/agents/." "$RELEASE/agents/"
```

### 3.6 创建受保护 OpenClaw 入口

```bash
cat > "$RELEASE/runtime/openclaw-protected" <<'SH'
#!/usr/bin/env bash
set -euo pipefail

ROOT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
exec "$ROOT_DIR/runtime/node" "$ROOT_DIR/third_party/openclaw/openclaw.mjs" "$@"
SH
chmod 0755 "$RELEASE/runtime/openclaw-protected"
```

启动脚本要走：

```text
runtime/openclaw-protected
```

不要再直接运行：

```text
third_party/openclaw/openclaw.mjs
```

### 3.7 检查启动脚本

`bin/claw-trade-ui` 和 `bin/claw-trade-control` 要把包内 `runtime` 放进 `PATH`：

```bash
grep -n 'PATH=.*/runtime' "$RELEASE/bin/claw-trade-ui" "$RELEASE/bin/claw-trade-control"
```

OpenClaw 启动命令要指向受保护入口：

```bash
grep -n 'OPENCLAW_GATEWAY_CALL_BIN.*openclaw-protected' \
  "$RELEASE/bin/claw-trade-ui" \
  "$RELEASE/bin/claw-trade-control" \
  "$RELEASE/runtime/claw-trade-control-runtime"
```

control runtime 要用包内受保护 Python，不要用系统 `python3.12`：

```bash
grep -n 'runtime/python/bin/python' "$RELEASE/runtime/claw-trade-control-runtime"
```

## 4. 新 Ubuntu 机器首次安装

假设目标机：

```text
IP：192.168.1.21
用户：frank
密码：目标机自己的登录密码
```

每台机器准备一个自己的授权文件：

```text

```

文件内容只放这一台机器要用的授权码，例如：


注意：

```text

license.key 不提交 git。
license.key 不给多台机器共用。
一台机器一个 license.key。
```



### 4.2 登录目标机


## 5. Virbox 授权

厂家机器必须在目标机上绑定授权。不能在发布机绑定后拿去另一台机器用。

原因：

```text
一机一码绑定的是目标机器指纹。
换机器就要重新激活、转移或重新发码。
```

量产推荐走自动绑定：

```bash
sudo bash /tmp/install_factory_test_ubuntu.sh \
  /tmp/claw-trade-production-版本-时间.tar.gz \
  --license-key-file /tmp/license.key
```

脚本读取：

```text
/tmp/license.key
```

然后调用目标机本机 Virbox 服务：

```text
http://127.0.0.1:12339
```

如果自动绑定失败，再人工排查。

目标机本机能访问时，打开：

```text
http://192.168.1.21:12339/#/license
```

如果 Win11 打不开，但目标机本机服务正常，用 SSH 转发：

```bash
ssh -L 12339:127.0.0.1:12339 frank@192.168.1.21
```

然后 Win11 浏览器打开：

```text
http://127.0.0.1:12339/#/license
```

## 6. 配置目标机远程升级

首次安装后，如果这台机器以后要在线升级，要配置更新源和公钥。

发布机上传公钥：

```bash
scp update-signing-public.pem frank@192.168.1.21:/tmp/
```

目标机配置更新源：

```bash
sudo mkdir -p /opt/claw-trade/shared/config
sudo tee -a /opt/claw-trade/shared/config/claw-trade.env >/dev/null <<'EOF'
CLAW_TRADE_UPDATE_BASE_URL=http://thaef8z8g.hn-bkt.clouddn.com/stable/
CLAW_TRADE_AUTO_UPDATE_INSTALL=1
EOF
```

安装升级公钥：

```bash
sudo install -d -m 0755 /etc/claw-trade
sudo install -m 0644 /tmp/update-signing-public.pem /etc/claw-trade/update-signing-public.pem
```

重启服务：

```bash
sudo systemctl restart claw-trade-control.service claw-trade-ui.service
```

如果测试机没有 systemd 服务，就重跑安装脚本，或重启当前脚本启动的进程。

## 7. 制作远程升级包

远程升级包本质上也是生产包，但多了：

```text
1. 生产包签名。
2. manifest.json。
3. manifest.json 签名。
4. 上传到七牛 stable/。
```

如果产品要求 Virbox 保护，升级用的 tar.gz 也必须是第 3 节做出来的保护包。不要把普通生产包拿去签名发布。

### 7.1 给 tar.gz 签名

发布私钥只放发布机，不放目标工控机。

```bash
openssl pkeyutl -sign \
  -inkey update-signing-private.pem \
  -rawin \
  -in claw-trade-production-版本-时间.tar.gz \
  -out claw-trade-production-版本-时间.tar.gz.sig
```

### 7.2 生成 manifest.json

示例：

```json
{
  "product": "claw-trade",
  "channel": "stable",
  "version": "0.1.4",
  "arch": "linux-x86_64",
  "archive": "claw-trade-production-0.1.4-20260629T114637Z.tar.gz",
  "sha256": "这里填最终 tar.gz 的 sha256",
  "created_at": "2026-06-29T11:46:37Z",
  "min_current_version": "0.1.0",
  "notes": "release note"
}
```

字段要求：

```text
version：新版本号，必须高于目标机当前版本。
archive：只写文件名，不写路径。
sha256：必须是最终上传 tar.gz 的 sha256。
min_current_version：允许升级的最低当前版本。
```

计算 sha256：

```bash
sha256sum claw-trade-production-版本-时间.tar.gz
```

### 7.3 给 manifest 签名

```bash
openssl pkeyutl -sign \
  -inkey update-signing-private.pem \
  -rawin \
  -in manifest.json \
  -out manifest.json.sig
```

最终有 4 个文件：

```text
claw-trade-production-版本-时间.tar.gz
claw-trade-production-版本-时间.tar.gz.sig
manifest.json
manifest.json.sig
```

### 7.4 上传七牛

上传到：

```text
stable/claw-trade-production-版本-时间.tar.gz
stable/claw-trade-production-版本-时间.tar.gz.sig
stable/manifest.json
stable/manifest.json.sig
```

上传顺序必须是：

```text
1. 先传 tar.gz。
2. 再传 tar.gz.sig。
3. 再传 manifest.json。
4. 最后传 manifest.json.sig。
```

不要先传 `manifest.json`。否则目标机可能先看到新版本，但包还没传完。

上传后刷新七牛 CDN：

```text
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json.sig
http://thaef8z8g.hn-bkt.clouddn.com/stable/claw-trade-production-版本-时间.tar.gz
http://thaef8z8g.hn-bkt.clouddn.com/stable/claw-trade-production-版本-时间.tar.gz.sig
```

刷新后打开：

```text
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json
```

确认显示的是新版本、新 archive、新 sha256。

## 8. 在界面执行升级

打开设备界面：

```text
http://目标机IP:5175/
```

进入：

```text
设置 -> 远程更新
```

手动升级：

```text
1. 点击 检查更新。
2. 看到发现新版本。
3. 点击 安装更新。
4. 等待服务重启。
5. 刷新页面确认版本状态。
```

如果目标机配置了：

```text
CLAW_TRADE_AUTO_UPDATE_INSTALL=1
```

系统也可以自动检查并安装更新。

升级安装时，目标机会校验：

```text
manifest 签名
生产包 sha256
生产包签名
包名和目录结构
版本是否高于当前版本
```

校验失败不会安装。

安装后健康检查失败，会回滚到上一版本。

## 9. 回滚、救援页、恢复出厂

升级失败时，目标机会保留上一可用版本。

如果主 UI 起不来，会进入救援页。救援页仍然使用同一个地址：

```text
http://目标机IP:5175/
```

恢复出厂入口：

```text
设置 -> 恢复出厂设置
```

恢复出厂会清空：

```text
应用配置
报告
缓存
队列
会话
临时文件
```

恢复出厂会保留：

```text
Virbox 授权
更新包
当前版本
上一可用版本
更新公钥
```

恢复出厂不是重装 Ubuntu，也不会清空整机磁盘。

## 10. 卸载

只卸载程序，保留 shared 数据：

```bash
sudo bash /tmp/uninstall_factory_test_ubuntu.sh
```

卸载程序，并清空 shared 数据：

```bash
sudo bash /tmp/uninstall_factory_test_ubuntu.sh --purge-shared
```

`--purge-shared` 会删除应用共享数据，包括缓存、报告、运行状态等。客户机器上不要随便执行。

## 12. 常见问题

### 只创建了目录，没有真正安装 release

现象：

```text
/opt/claw-trade/current 不存在
/opt/claw-trade/releases 是空的
浏览器打不开
curl 127.0.0.1:5175 失败
```

处理：

```bash
sudo bash /tmp/install_factory_test_ubuntu.sh /tmp/claw-trade-production-版本-时间.tar.gz
```

不要只手工创建 `/opt/claw-trade` 目录。

### 包能装，但 UI 起不来

检查日志：

```bash
tail -n 120 /tmp/claw-trade-ui.log
tail -n 120 /tmp/claw-trade-control.log
```

检查端口：

```bash
ss -ltnp | grep 5175
```

### Win11 打不开目标机页面

先在目标机本机检查：

```bash
curl -fsS http://127.0.0.1:5175/ | head
ss -ltnp | grep 5175
```

如果本机正常，Win11 打不开，优先查目标机防火墙、IP 是否正确、UI 是否监听 `0.0.0.0:5175`。

### Virbox 授权一台机器成功，另一台机器不能用

这是正常的。

授权码软锁绑定机器指纹。换机器就要重新激活、转移或重新发码。

### 检查更新提示未配置

检查：

```bash
grep CLAW_TRADE_UPDATE_BASE_URL /opt/claw-trade/shared/config/claw-trade.env
```

### 检查更新提示公钥不存在

检查：

```bash
ls -l /etc/claw-trade/update-signing-public.pem
```

### 七牛已经上传，但目标机还是旧版本

先刷新 CDN，再打开：

```text
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json
```

确认看到的是新 `version`、新 `archive`、新 `sha256`。

### 安装更新按钮不可用

先点：

```text
检查更新
```

只有检查到可安装新版本后，`安装更新` 才可用。

### 升级包校验失败

通常是：

```text
1. manifest 里的 sha256 不是最终 tar.gz 的 sha256。
2. tar.gz 签名对应的不是最终 tar.gz。
3. manifest.json 改过后没有重新签名。
4. archive 文件名写错。
5. 包名或顶层目录名不符合 claw-trade-production-版本-时间。
```

处理：

```text
重新计算 sha256。
重新签 tar.gz。
重新签 manifest.json。
重新上传 4 个文件。
重新刷新 CDN。
```

### Virbox 状态检查 SDK 缺失

如果日志提示 Virbox 状态检查 SDK 缺失，说明 UI 授权状态显示可能不可用。

这不等于 Virbox 保护运行时失效。受保护 Python、Node、DS 加密文件仍然按 Virbox 保护逻辑运行。

如果产品要求界面显示授权状态，就把 Virbox 状态检查 SDK 补进生产包，再重新构建和验证。
