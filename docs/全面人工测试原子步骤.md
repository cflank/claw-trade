# 全面人工测试原子步骤（v0.9）

> 基于 `全面人工测试方案.md`，将验收拆分为可直接执行的原子化步骤。每步都给出可核对动作与预期目标，便于不同执行者按同一口径验收。

## 1. 文档用途与适用版本

- 版本基线：`v0.9`
- 用途：将人工验收从“场景描述”变成“可点检步骤”。
- 覆盖范围：P0 / P1 / P2 全量用例（除特殊说明的停止条件）。
- 输出：每步填写一条执行记录，形成阻断-修复-复测闭环。

## 2. 全局执行前置（必须逐条完成）

### 2.1 环境和账号准备

1. 切到待测分支/提交（`main` HEAD）。
2. 启动固定 runtime。
3. 使用真实 Chrome（非 headless、非 WSL Chromium、非临时脚本）。
4. 确认服务端口：  
   - OpenViking：`1933`  
   - OpenClaw gateway：`18789`
5. 准备并确认可用密钥：  
   - Tushare、Coinglass、Finnhub、FRED、Glassnode、CoinGecko Pro
6. 检查公共兜底源可用性：AkShare、EastMoney、mootdx、Yahoo、Binance 等。
7. 在证据目录创建本轮文件夹，结构如下：
   - `screenshots/` 截图
   - `recordings/` 录屏
   - `reports/` 报告页面与下载内容
   - `pdf/` PDF 产物
   - `api/` 数据源调用摘要
   - `gaps/` 数据缺失清单

### 2.2 证据模板（每条用例固定字段）

每条用例必须记录：

1. 用例 ID
2. 执行人
3. 日期时间（精确到分钟）
4. 浏览器截图/录屏链接
5. 输入内容
6. 用户动作
7. 页面结果
8. 后台证据（run id、报告路径、provider attempt 摘要）
9. 结论（通过/失败/阻塞）
10. 失败根因（人话）

## 3. 原子执行节奏（固定）

对每条用例重复执行以下模板：

1. 记录测试前状态（会话、当前运行任务、网络状态）。
2. 执行单一用户动作（一次只做一件事）。
3. 捕获关键截图。
4. 观察结果并记录。
5. 输出 1 句话“预期目标是否满足”。
6. 记录后台证据。
7. 标记 pass/fail/blocked。

## 4. P0 用例：原子步骤

### 4.1 启动与基础 UI（BOOT）

- `BOOT-001` 真实 Chrome 打开 UI  
  1. 启动固定 runtime。  
  2. 在真实 Chrome 打开产品首页。  
  3. 观察是否正常渲染、可点击。  
  4. 预期：页面可用；页面不出现内部端口/服务名/路径等敏感字样。
- `BOOT-002` 刷新页面恢复  
  1. 记录当前会话状态与任务列表。  
  2. 刷新页面一次。  
  3. 观察会话恢复状况。  
  4. 预期：会话和进行中任务状态可恢复。
- `BOOT-003` runtime 健康状态  
  1. 进入设置/状态入口。  
  2. 记录页面可见状态文案。  
  3. 预期：用户侧只看见人话健康状态，不出现 OpenViking、OpenClaw Gateway、MongoDB、端口等内网术语。
- `BOOT-004` 未配置模型阻断报告  
  1. 清空或关闭报告模型。  
  2. 在输入框输入 `/report BTC`。  
  3. 观察反馈。  
  4. 预期：显示模型未配置提示，且未创建报告任务。
- `BOOT-005` 模型配置后可报告  
  1. 配置模型。  
  2. 点击“测试”。  
  3. 测试通过后输入 `/report BTC`。  
  4. 预期：出现报告确认卡，后续可继续确认入队。

### 4.2 设置模块（SET）

- `SET-001` 数据源列表可见性  
  1. 打开数据源设置页。  
  2. 勾选/展开全部数据源列表。  
  3. 预期：仅显示付费源配置项（Tushare、Coinglass、Finnhub、FRED、Glassnode、CoinGecko Pro）。
- `SET-002` 密钥掩码  
  1. 进入已配置源详情。  
  2. 浏览 key / token / URL / 文件路径显示。  
  3. 预期：均为掩码或占位，不明文泄露。
- `SET-003` 替换密钥与代理 URL  
  1. 修改 Tushare key 与代理 URL。  
  2. 保存。  
  3. 点击测试。  
  4. 记录成功/失败原因。  
  5. 预期：返回真实可解释结果；失败不展示内部错误原文。
- `SET-004` 错误密钥拦截  
  1. 输入错误 Coinglass key。  
  2. 点击测试。  
  3. 预期：用户可读错误文案（“凭证无效/权限不足”），不假成功。
- `SET-005` 禁用源后的调用行为  
  1. 禁用 Tushare。  
  2. 发起 A 股报告（`/report 600519.SH`）。  
  3. 记录数据源调用。  
  4. 预期：不再调用 Tushare；出现公共源兜底或明确缺失说明。
- `SET-006` 重启源后的优先级恢复  
  1. 重新启用 Tushare。  
  2. 再发起 A 股报告。  
  3. 记录调用优先级。  
  4. 预期：Tushare 可作为高优先级被调用。
- `SET-007` 微信状态正确性  
  1. 打开微信 ClawBot 设置。  
  2. 检查未登录与已登录两种状态。  
  3. 预期：未登录显示未连接；已登录可发，WeCom 不作为普通微信展示。
- `SET-008` 设置失败文案  
  1. 触发任意数据源测试失败。  
  2. 观察弹窗/错误区域。  
  3. 预期：无 stack trace、provider attempt、内部路径。

  3. 预期：显示市场识别为加密并待确认。

  2. 检查列表与运行队列。  
  3. 预期：无入队、无任务历史新增。
- `CHAT-005` 确认创建  
  1. 再次触发 `/report BTC`。  
  2. 点击确认。  
  3. 预期：任务入队并开始执行。
- `CHAT-006` 运行中插入普通问题

  2. 观察是否影响当前任务。  
  3. 预期：不干扰正在运行任务。
- `CHAT-007` 切回普通聊天  
  1. 点击普通聊天入口或输入“回到普通聊天”。  
  2. 观察任务区。  
  3. 预期：返回普通对话模式，当前报告继续后台运行。
- `CHAT-008` 重复提交幂等提示  
  1. 连续两次输入 `/report BTC`。  
  2. 观察页面提示。  
  3. 预期：提示已有任务或明确创建新任务，不出现隐式重复乱跑。

### 4.10 数据层边界与调用流程（DATA）

## 6. 四市场批次执行顺序（可直接照此跑）

1. B1：A 股链路（含 A 股专项）
2. B2：BTC 链路（含 BTC 数据专项）
3. B3：US 链路
4. B4：HK 链路
5. B5：`/select` 全链（候选缓存 + 四 worker + 交接）

每个批次开始前做一组健康体检；失败时按停止条件中断。

## 7. 统一停止条件（满足任一即暂停）

1. 真实 Chrome 不可用。
2. UI 启动/访问失败。
3. 报告模型无法真实运行且无法修复。
4. 必测付费源密钥缺失。
5. 发现编造数据或假图表。
6. UI 出现敏感字段泄露。
7. worker 暴露 provider/path/api_id/params/fields。
8. `/select` 跳过候选缓存直接拉全市场。
9. PDF 非真实文件。
10. 微信未真实发送却显示成功。
11. 四市场出现 prompt/profile fallback。
