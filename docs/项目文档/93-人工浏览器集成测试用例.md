# 人工浏览器集成测试用例

## 1. 测试目标

本文定义完全模拟人类通过 Chrome 操作 `claw-trade` 的集成测试用例。本文不是自动化脚本，不要求编写脚本，也不以 API 直调、headless 浏览器、mock 页面或静态 HTML 检查替代人工操作。

目标是从用户视角验证：

- 普通聊天不会误入正式报告流程。
- `/report` 能创建、排队、运行、取消、失败提示、完成、进入历史和打开详情。
- `/select` 能生成候选结果，并且只有用户确认后才交接为正式报告。
- 报告详情能展示正文、worker 附录、图表证据、报告问答、worker 聊天、PDF 导出和渠道发送。
- 完整报告能从 Chrome 页面追踪阶段顺序、worker 覆盖、provider payload、tool schema、approved material 和 PM 结论边界。
- 定时报表和价格提醒是普通用户可创建、暂停、恢复、删除和手动触发的业务任务。
- selection 数据刷新、数据维护、报告清理是系统后台任务或维护任务，不是普通用户直接创建的定时任务。
- 设置、模型设置、数据源设置、渠道状态、高级诊断、错误态、运行中状态、权限或配置缺失状态能用普通中文呈现。
- API 404 和 SPA fallback 边界正确：API 不存在应返回接口错误，前端路由刷新应回到应用页面。

覆盖来源包括 `00-项目总体需求.md`、`01-项目总体设计.md`、12 个模块设计、12 个模块测试计划和 `90-集成测试计划.md`。

## 2. 测试前置条件

人工执行前必须明确本次采用哪一种环境：

| 环境 | 用途 | 可验收内容 | 不可验收内容 |
| --- | --- | --- | --- |
| 真实 runtime/provider 环境 | 完整报告、真实材料、provider payload、PDF、渠道发送 | `/report` 完整链路、真实图表或缺口、run id、report id、provider/data 缺口 | 不能绕过 preflight，不能用 fake 成功 |
| runtime 可用但 provider 或凭证缺失 | 失败态、配置缺失态、诊断态 | 数据源配置缺失、权限缺失、provider 不可用、报告失败提示 | 不能声称正式报告已 live 通过 |
| UI 后端可用但 runtime 缺失 | 前端路由、普通聊天失败态、设置页、API 404、SPA fallback | 用户可见错误、等待配置、运行中占位、路由行为 | 不能验收 OpenClaw worker、provider payload、真实报告 |

当前代码可见的主要 Chrome 路由是首页工作台、报告详情重定向、设置页和高级诊断页。本文中“定时报表页面”“价格提醒页面”“维护状态页面”“worker 附录”“运行证据下载”等入口，执行时必须先从这些可见页面或导航中找到真实入口；找不到时记录为 `UI入口缺失` 或 `证据入口缺失`，该用例不能写成通过，不能用后端接口直调、本地文件检查或脚本输出替代。

当前已知需要特别记录的执行边界：

- 定时报表、价格提醒、维护状态如果没有可见 UI 入口，只能判为阻塞或失败。
- 逐 worker provider payload、tool schema、material、receipt、manifest 如果没有 Chrome 可见入口或下载入口，只能判为阻塞或失败。
- worker 附录或阶段详情如果报告详情没有入口，只能判为阻塞或失败。
- “保存为 PDF”如果走 Chrome 打印保存，只能证明浏览器打印路径；不能证明后端 PDF runtime 下载路径。
- `/api/other` 按设计应返回 API 错误；如果当前页面落入 SPA fallback，应记录为产品/路由边界失败。

执行前需要记录：

- 测试日期、执行人、浏览器版本、访问地址。
- 当前环境类型。
- 是否已完成 fixed runtime preflight；如果未执行，写明未执行。
- 是否有可用模型、数据源、渠道凭证。
- 是否准备了测试标的，例如 A 股 `600519.SH`、美股 `AAPL`、港股样例、加密 `BTCUSDT`。
- 是否允许触发真实 provider、真实渠道发送和真实 PDF 下载。

## 3. 证据采集要求

每个用例至少记录：

- 截图：关键页面、输入、点击后状态、错误提示或完成结果。
- 业务标识：报告 id、任务 id、run id、selection run id、定时报表 id、价格提醒 id、渠道发送任务 id。
- 保存文件：PDF 文件名、下载路径、文件大小；必要时记录文件开头是否为真实 PDF。
- 失败消息：用户可见中文文案、失败类型、是否提供可行动下一步。
- 运行证据：需要真实 runtime/provider 的用例要记录 provider payload 路径、OpenClaw/OpenViking 状态、材料或 receipt 路径；只验证失败态的用例要明确写“未验证 provider 成功”。
- 环境差异：如 provider 缺失、权限缺失、渠道未配置、runtime 不可达，必须作为证据记录，不能把失败态写成成功态。

截图命名建议：

```text
yymmdd-用例编号-页面-状态.png
```

## 4. 停止条件

出现以下情况停止当前批次并记录：

- 真实 runtime/provider 用例缺少 preflight 证据。
- UI 无法通过 Chrome 打开，且本批次目标是 UI 验收。
- 报告显示完成但没有 report id 或 run id。
- worker 顺序、PM 结论、材料审批、provider payload 证据出现可信性风险。
- 图表或 PDF 声称成功，但文件、资产或缺失原因无法证明。
- 渠道发送失败却显示成功。
- 普通聊天自动创建正式报告任务。
- selection 未经用户确认就创建正式 `/report` 任务。
- 后台维护任务被普通用户当作可创建的定时任务暴露。
- 需要改代码才能继续，而当前任务只允许测试或文档记录。

## 6. 逐项用例

### TC-01 普通聊天不触发报告

环境要求：UI 后端可用。真实 provider 非必需。

人工步骤：

1. 打开 Chrome，进入应用首页。
2. 在聊天输入框输入普通问题，例如“帮我解释一下市盈率是什么意思”。
3. 点击发送。
4. 观察回复区域、报告队列入口和历史报告入口。
5. 在同一聊天输入框输入“帮我看看 AAPL”这类非 `/report`、非 `/select` 命令请求。
6. 点击发送，观察页面是否只生成确认卡或追问。
7. 如果出现确认卡，等待其过期，或按页面提供的取消/拒绝入口拒绝。
8. 过期后再次点击确认卡的执行按钮。
9. 截图记录聊天回复、确认卡或追问、过期/拒绝后的状态和报告队列状态。

预期结果：

- 页面显示普通聊天回复或明确的聊天失败态。
- 不创建正式报告任务。
- 报告队列不新增 `/report` 任务。
- “帮我看看 AAPL”等非命令请求不能绕过确认直接创建报告。
- 过期或被拒绝的确认卡点击后不能执行。
- 如 runtime 缺失，错误文案说明配置或服务不可用，不伪装为报告成功。

验收证据：聊天截图、队列截图、如有错误则记录错误消息。

### TC-02 `/report` 输入校验和确认

环境要求：UI 后端可用。真实 provider 非必需；完整运行需要真实 runtime/provider。

人工步骤：

1. 打开 Chrome，进入应用首页。
2. 在聊天输入框输入 `/report`，不带标的。
3. 点击发送，观察是否要求补充标的或市场。
4. 截图记录缺少标的时的提示。
5. 在聊天输入框输入 `/report 600519.SH`。
6. 点击发送，观察确认卡片或报告任务创建提示。
7. 如果页面显示确认卡，点击确认按钮。
8. 记录页面展示的 market、ticker、company 信息。
9. 打开报告队列，观察是否出现对应任务或明确失败态。

预期结果：

- 缺少标的时不创建无效任务。
- 有标的时标的解析结果清楚可读。
- 如果系统需要确认，必须等待用户确认后才创建任务。
- 配置缺失时显示失败态或等待配置态，不创建假成功任务。

验收证据：输入截图、确认卡片截图、任务 id 或失败消息。

### TC-03 `/select` 候选发现和刷新入口

环境要求：候选缓存或 selection 服务可用；真实刷新需要数据源和 runtime。

人工步骤：

1. 在聊天输入框输入 `/select`。
2. 点击发送，观察 A 股候选发现入口或运行状态。
3. 输入 `/select 2` 或 `/select CRYPTO`。
4. 点击发送，观察是否进入加密市场候选发现。
5. 在聊天输入框输入 `/select US`。
6. 点击发送，观察不支持提示。
7. 在聊天输入框输入 `/select 3`。
8. 点击发送，观察不支持提示。
9. 输入带 `refresh` 的 selection 命令。
10. 观察刷新状态、候选结果、缺口提示和确认入口。
11. 截图记录候选列表、selection run id、刷新状态和负例提示。

预期结果：

- `/select` 默认 A 股。
- `/select 2` 或 `/select CRYPTO` 使用加密市场语义，不写成股票。
- `/select US` 和 `/select 3` 明确不支持，不能静默回退到 A 股。
- refresh 显示刷新运行中、完成或真实失败原因。
- selection 结果不是正式投资报告。
- 没有用户确认时不创建 `/report` 任务。

验收证据：selection run id、候选截图、缺口或失败消息。

### TC-03A `/select` 命令矩阵和 selection worker 证据

环境要求：UI 后端可用；完整 worker 和工具可见性验收需要真实 runtime/provider，并且页面或诊断页能展示 selection 运行证据。

人工步骤：

1. 打开 Chrome，进入应用首页。
2. 依次输入并发送 `/select`、`/select 1`、`/select A`、`/select CN_A`、`/select A股`。
3. 对每条命令截图记录市场语义、候选运行状态、selection run id 或失败提示。
4. 依次输入并发送 `/select 2`、`/select CRYPTO`、`/select 加密`。
5. 对每条命令截图记录加密市场语义，确认页面不写成股票、公司财报或 A 股交易日历。
6. 输入 `/select refresh` 和 `/select 2 refresh`。
7. 观察刷新状态、候选缓存、lineage 或缺口提示。
8. 打开 selection 结果、候选详情、运行证据或高级诊断入口。
9. 核对候选缓存证据：cache hash 或等价完整性标识、readback 状态、候选评分、字段命中、缺口和候选证据。
10. 核对 selection worker 顺序是否为 `selection_strategist -> selection_skeptic -> selection_manager -> selection_portfolio_manager`。
11. 如页面提供工具可见性或 provider payload 证据，核对 strategist/skeptic 可见候选缓存读取工具，manager/portfolio manager 不暴露模型可见数据工具。
12. 如 UI 没有展示或下载候选缓存或 selection worker 证据的入口，将第 9-11 步记录为阻塞或失败，不能用本地文件 grep、API 直调或脚本输出代替人工 Chrome 验收。

预期结果：

- A 股别名全部进入 A 股候选发现语义。
- 加密别名全部进入 CRYPTO 候选发现语义。
- refresh 命令显示真实刷新中、完成、缺口或失败原因。
- 候选缓存能追踪 hash/readback、评分、字段命中、缺口和候选证据。
- selection 四个 worker 顺序固定，不由 LLM 决定下一步。
- selection manager 和 selection portfolio manager 不重新读取候选缓存工具。
- 证据入口缺失时不能声称 selection runtime 证据已通过。

验收证据：每条命令截图、selection run id、刷新状态、cache hash/readback 截图、评分和字段命中截图、worker 顺序截图、工具可见性或 provider payload 证据截图、阻塞原因。

### TC-04 `/report` 创建、队列和运行中状态

环境要求：完整验收需要真实 runtime/provider；配置缺失时只验失败态。

人工步骤：

1. 打开 Chrome，进入应用首页。
2. 在聊天输入框输入 `/report 600519.SH`。
3. 点击发送。
4. 如果页面显示确认卡，点击确认按钮。
5. 打开报告队列。
6. 观察新任务是否出现，并记录任务 id。
7. 在任务运行时刷新页面。
8. 再次打开报告队列。
9. 观察任务状态、当前阶段、当前 worker 和进度显示。
10. 截图记录任务 id、run id、状态变化。

预期结果：

- 任务进入报告队列。
- 运行中状态不会显示为完成。
- 用户能看到当前 worker 或阶段。
- 失败时显示用户可读原因。
- 真实 runtime/provider 环境下应保留 run id 和 provider/material 证据线索。

验收证据：任务 id、run id、队列截图、运行中截图、失败消息或完成消息。

### TC-04A 四市场 `/report` 最小 Chrome 验收

环境要求：UI 后端可用；完整 worker 和 provider 证据需要真实 runtime/provider。本用例是人工验收用例定义，不表示已经通过。

人工步骤：

1. 打开 Chrome，进入应用首页。
2. 输入 `/report 600519.SH`，点击发送，按页面要求确认或记录失败态。
3. 观察 A 股标的解析、market/profile、任务创建或 fail-closed 提示。
4. 输入 `/report AAPL`，点击发送，按页面要求确认或记录失败态。
5. 观察 US 标的解析、market/profile、任务创建或 fail-closed 提示。
6. 输入一个港股标的，例如 `/report 00700.HK`，点击发送，按页面要求确认或记录失败态。
7. 观察 HK profile 是否明确；如果 HK prompt/profile 未批准，应 fail-closed，不能回退 A 股或 US。
8. 输入一个加密标的，例如 `/report BTCUSDT` 或 `/report BTC`，点击发送，按页面要求确认或记录失败态。
9. 观察 CRYPTO profile 是否明确；加密语义不能写成股票、公司财报或股价估值语义。
10. 分别截图记录四个市场的解析结果、确认卡、任务状态或失败提示。

预期结果：

- A 股、US、HK、CRYPTO 的标的解析清楚可读。
- HK 和 CRYPTO 缺少批准 profile 或 prompt 策略时必须 fail-closed。
- CRYPTO 不能被股票化，页面文案和任务信息不能伪造公司、股票交易所或财报语义。
- 任何市场配置缺失时都显示真实失败态，不静默回退到 A 股。

验收证据：四市场输入截图、解析或确认截图、任务 id 或失败消息、如有真实运行则记录 run id。

### TC-04B 正式报告运行证据核查

环境要求：必须使用真实 runtime/provider，fixed runtime preflight 已通过，且 Chrome 页面、报告详情或高级诊断能展示运行证据。本用例不能在仅 UI 后端环境验收通过。

人工步骤：

1. 在 Chrome 中创建一条 `/report 600519.SH` 或本次指定市场的正式报告任务。
2. 等待任务完成，打开报告详情。
3. 打开任务进度、worker 附录、运行证据或高级诊断入口。
4. 核对正式报告阶段顺序：frontline、investment_debate、investment_decision、trade_decision、risk_debate、portfolio_decision、final_report、report_exporting、completed。
5. 核对 worker 覆盖。CN_A 需要 7 个前线 worker；非 CN_A 至少需要默认 4 个前线 worker；下游需要 bull、bear、research manager、trader、risk challenger、risk guardian、risk moderator、portfolio manager、report polisher。
6. 对页面展示的每个 worker，记录 worker id、stage、run id、dispatch id 或等价标识。
7. 打开或下载 provider payload 证据，核对每个 worker 都有最终 provider request 消息证据。
8. 打开或下载 tool schema 证据，核对当前 worker 可见工具与 stage policy 一致。
9. 打开或下载 material/receipt/manifest 证据，核对下游只读取 approved material，hard-gate-failed material 没有进入下游。
10. 回到报告正文和 PM 结论区域，核对 exporter 或 report polisher 没有改写 PM 最终投资判断。
11. 如果页面没有提供第 7-9 步证据入口，本用例记录为阻塞或失败，不能只凭“报告完成”判断运行证据通过。

预期结果：

- 阶段顺序固定，LLM 没有决定下一 worker。
- worker 覆盖与市场 profile 一致。
- 每个 worker 的 provider payload、tool schema、material/receipt 证据应可由 Chrome 人工追踪；缺失则为阻塞或失败。
- downstream material 只来自 approved material。
- PM 结论没有被 Python、exporter 或 report polisher 改写。
- 缺少运行证据入口时不能验收完整 `/report` live 链路。

1. 打开高级诊断页，并从首页工作台、设置页或高级诊断页查找维护状态入口。
2. 查找 selection 数据刷新、数据维护、报告清理状态。
3. 如果没有维护状态入口，截图记录 `维护状态UI入口缺失`，本用例不能写成通过。
4. 观察是否存在普通用户“新建后台维护任务”的入口。
5. 如页面提供内部触发状态，记录 kind、run id、最近结果和失败原因。
6. 如果页面提供筛选或刷新按钮，点击刷新并观察最近结果是否更新。
7. 查找定时报表入口，对比确认这些维护任务没有作为普通定时报表暴露。
8. 截图记录维护状态、刷新结果和普通定时报表入口状态。

预期结果：

- selection 数据刷新、数据维护、报告清理作为系统后台任务或维护任务展示。
- 普通用户不能像定时报表一样直接创建、暂停、恢复、删除这些维护任务。
- 后台任务有 kind、run id 或等价幂等键。
- 清理任务不能删除发送中或导出中的报告。
- 维护状态入口缺失时，该用例为阻塞或失败。

验收证据：维护状态截图、run id、失败消息、是否无普通用户创建入口。

- 发送中或导出中的报告受到保护。
- 保留期清理是后台维护任务，不是普通用户新建的定时任务。

### TC-19A 数据源保存和数据网关证据

环境要求：设置页和高级诊断页可用；真实 provider 证据需要有效凭证。不得把 cache、空返回或配置缺失写成远端成功。

人工步骤：

1. 打开设置页，进入数据源设置区域。
2. 选择一个测试数据源实例，记录市场、provider 类型、启用状态和当前健康状态。
3. 修改一个允许测试的非敏感配置项，例如启用状态、说明、测试环境开关或测试凭证占位。
4. 点击取消或返回，确认未保存的修改不会污染当前配置。
5. 再次修改测试配置项并点击保存。
6. 观察保存成功、保存失败或鉴权失败状态。
7. 查找未批准或自定义数据源入口；如果页面允许输入 provider 类型，尝试输入一个未批准 provider 名称并保存或测试连接。
8. 确认未批准数据源不能启用、保存成功或用于健康检查；如果页面没有自定义入口，截图记录“无未批准数据源入口”。
9. 点击测试连接或健康检查。
10. 打开高级诊断或数据源证据入口。
11. 核对 provider attempts：计划尝试过哪些 provider、哪些成功、空返回、权限缺失、限流或错误。
12. 核对 raw store、normalized store、Mongo metadata、columnar warehouse、manifest 或等价写入/缺口证据。
13. 核对 data gap 和 chart evidence 摘要，确认影响报告或 selection 的数据缺口可见。
14. 确认诊断页或证据页只读，不改变数据源配置、启用状态、凭证或健康检查结果。
15. 如果页面没有展示或下载 attempts、存储/manifest、data gap 证据的入口，将第 11-14 步记录为阻塞或失败，不能用脚本或本地文件检查替代人工 Chrome 验收。

预期结果：

- 数据源配置可保存、取消和显示保存失败。
- 保存失败、鉴权失败、权限缺失、限流、空返回能区分展示。
- 未批准数据源不能被启用、保存成功或用于健康检查。
- provider attempts 证据可从 Chrome 路径追踪。
- raw/normalized/metadata/columnar/manifest 或等价存储证据可追踪。
- cache 或空返回不能伪装成最新远端成功。
- token、secret 和 raw provider payload 不泄漏给普通用户界面。
- 诊断页和证据页不能修改配置。

验收证据：数据源配置截图、取消前后截图、保存结果、未批准数据源阻止截图、健康检查结果、provider attempts 截图、存储/manifest 证据截图、data gap/chart evidence 截图、诊断只读截图、失败消息。

### TC-20 API 404 和 SPA fallback

环境要求：UI 后端可用。

人工步骤：

1. 在 Chrome 地址栏打开一个不存在的前端路由，例如 `/reports/not-real-client-route`。
2. 观察是否回到应用页面或显示前端可处理页面。
3. 打开 Chrome DevTools Network。
4. 在地址栏打开一个不存在的 API，例如 `/api/ui/not-real-api`。
5. 观察 API 返回页面或错误内容，并记录 HTTP 状态。
6. 在地址栏打开未知 API 前缀，例如 `/api/other`。
7. 观察 API 返回页面或错误内容，并记录 HTTP 状态；如果返回 SPA 页面，应记录为 API 边界失败。
8. 在地址栏打开一个不存在的已声明静态资源路径，例如 `/assets/not-real-file.js`。
9. 观察是否返回静态资源错误，而不是误当成业务成功页面。
10. 截图记录前端路由、API 路径、未知 API 前缀、静态资源路径和 DevTools Network 状态。

预期结果：

- 前端路由刷新应能通过 SPA fallback 进入应用或前端错误页。
- 不存在的 API 应返回接口错误，不应被当作前端页面吞掉。
- `/api/other` 这类未知 API 前缀也应返回接口错误。
- 已声明静态资源路径不存在时应返回资源错误或可识别失败态，不应伪造成业务页面成功。
- API 错误不泄漏内部堆栈或 secret。

验收证据：前端路由截图、API 错误截图、HTTP 状态或页面错误信息。
