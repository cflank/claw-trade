# 集成测试计划

## 1. 计划目标

本文定义 `claw-trade` 当前代码状态下的跨模块集成测试计划。

集成测试目标不是替代单元测试，而是验证模块组合后的业务链路：

- `/report` 正式报告链路。
- `/select` 候选发现与 handoff。
- UI 聊天、队列、历史、问答和 worker 聊天。
- 数据网关、材料仓库、运行证据和报告导出。
- 定时任务、价格提醒、通知和清理。
- live runtime preflight、provider payload 和真实浏览器验收。

本计划不声称本轮已经执行这些测试。本轮主要完成文档重写和静态一致性审计。

## 2. 测试环境分层

| 环境 | 用途 | 限制 |
| --- | --- | --- |
| 本地单元环境 | 快速验证服务逻辑 | 不证明真实 provider |
| 本地集成环境 | 验证模块协作 | 可使用受控 fake，但必须标明 |
| 固定 runtime 环境 | OpenClaw/OpenViking/provider live proof | 必须 preflight |
| 真实浏览器环境 | UI 用户路径验收 | 不替代 provider 数据真实性 |

## 3. 固定 runtime preflight

live/fresh/provider run 前必须检查：

| 检查项 | 预期 |
| --- | --- |
| 启动方式 | `scripts/start-control-runtime.sh` |
| Python 环境 | claw-trade repo `uv` environment |
| OpenViking | `1933` |
| OpenClaw gateway | `18789` |
| invest sidecar | 不使用 |
| OpenViking config | `.runtime/dev-services/openviking/ov.conf` |
| OpenViking data | `.runtime/dev-services/openviking/data` |
| runtime config/cache | `.runtime/dev-services` |
| command mode | 需要 clean runtime 时使用 `scripts/start-control-runtime.sh -- <command>` |

先检查已有 runtime：

1. `runtime.env` 是否存在。
2. `1933/health` 或 `1933/healthz` 是否可达。
3. `18789/health` 是否可达。

三项都通过时复用 runtime，不盲目重启。

## 4. `/report` 集成测试

### 4.1 目标

验证正式报告从 UI/命令入口进入固定工作流，所有 worker 按顺序唤醒，材料被审批，下游只读取 approved material，最终报告可保存和阅读。

### 4.2 流程

```mermaid
flowchart TD
  A[/report 输入] --> B[标的解析]
  B --> C[报告队列]
  C --> D[工作流控制]
  D --> E[OpenClaw worker turn]
  E --> F[数据网关]
  E --> G[provider payload evidence]
  E --> H[材料审批]
  H --> I[下游 prompt material]
  I --> D
  D --> J[最终报告导出]
  J --> K[报告仓库]
  K --> L[UI 历史和详情]
```

### 4.3 覆盖点

- `/report` 明确入口创建 report task。
- 普通聊天不创建 report task。
- worker 顺序固定。
- A 股 profile 包含扩展前线 worker。
- US/HK/CRYPTO profile 不互相 fallback。
- 每个 worker 有 provider payload。
- tool schema 与 stage policy 匹配。
- approved material 进入 downstream。
- hard-gate-failed material 不进入下游。
- PM 结论不被 exporter 改写。
- final report 保存到 repository。

### 4.4 失败验收

- provider payload 缺失：失败。
- stage policy 工具泄漏：失败。
- 下游读取未审批材料：失败。
- PM material 缺失仍导出：失败。
- exporter 改写 PM 结论：失败。

## 5. `/select` 集成测试

### 5.1 目标

验证候选发现链路独立于正式报告，selection 结果只有在用户确认后才 handoff 到 `/report`。

### 5.2 流程

```mermaid
flowchart TD
  A[/select 输入] --> B[命令解析]
  B --> C[候选缓存/refresh]
  C --> D[selection_strategist]
  D --> E[selection_skeptic]
  E --> F[selection_manager]
  F --> G[selection_portfolio_manager]
  G --> H[候选报告]
  H --> I{用户确认}
  I -->|是| J[/report handoff]
  I -->|否| K[停止在候选报告]
```

### 5.3 覆盖点

- `/select` 默认 A 股。
- `/select 2` 和 `/select CRYPTO` 走加密市场。
- 不支持市场明确失败。
- refresh 能生成候选缓存和 lineage。
- candidate cache hash/readback 验证。
- selection 四 worker 顺序固定。
- manager/portfolio manager 不暴露候选缓存读取工具。
- 未确认不创建 report task。
- 确认后 report task 带 selection run 引用。

## 13. 四市场验收

最终市场级验收应覆盖：

| 市场 | 最小样例 | 重点 |
| --- | --- | --- |
| A 股 | `600519.SH` 或等价样例 | TradingAgents-CN、扩展前线、人民币语义 |
| 美股 | `AAPL` 或等价样例 | 原始 TradingAgents、US prompt 边界 |
| 港股 | 明确 HK 样例 | 不 fallback 到 A 股/US |
| 加密 | `BTCUSDT` 或等价样例 | 加密语义、USDT、非股票化 |

四市场测试默认 collect-first，除非遇到证据污染、真实性风险或架构边界风险。

## 15. 验收输出

一次完整验收至少输出：

- 测试命令。
- exit code。
- 关键输出。
- 运行时间。
- run id。
- report task id。
- provider payload 路径。
- artifact/receipt 路径。
- saved report id。
- UI 截图或浏览器状态。
- 失败原因和根因分组。

## 16. 停止条件

出现以下情况必须停止并上报：

- live runtime preflight 失败且无法按 runbook 修复。
- provider payload 证据缺失。
- 数据真实性风险。
- PM 结论被 Python/exporter 改写。
- 未批准 guard 或 hard gate 变化。
- UI 真实浏览器无法访问但任务要求 UI 验收。
- 需要修改代码但当前任务限制为只改文档。
