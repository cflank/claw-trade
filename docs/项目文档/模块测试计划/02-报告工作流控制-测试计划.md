# 报告工作流控制模块测试计划

## 1. 测试目标

证明 `claw-trade` 控制正式报告 DAG，LLM 不能决定下一 worker；上游材料、状态推进、失败记录和导出边界都按合同执行。

## 2. 单元测试

覆盖：

- `decide_next()` 在每种状态下的 decision。
- unknown state fail。
- terminal state wait。
- upstream approved material 缺失 fail。
- target worker/stage 不匹配 fail。
- stage plan for CN_A / non-CN_A。
- collect-first 阶段行为。
- stop point 行为。

建议命令：

```bash
uv run pytest tests/unit/workflow -q
```

## 3. 合同测试

现有相关测试：

```text
tests/contracts/test_runner_batch.py
tests/contracts/test_worker_call_contract.py
tests/contracts/test_artifact_flow_guard.py
tests/contracts/test_stage_policy_contract.py
tests/contracts/test_all_worker_workspaces.py
```

应覆盖：

- 所有 required worker 都有 workspace。
- stage policy 与 worker 所属阶段匹配。
- artifact flow 缺失时阻断。
- batch result 不被误判完成。

## 4. 集成测试

最小集成路径：

1. 构造 fake OpenClaw runner。
2. 构造 fake OpenViking backend。
3. 跑一个完整 state machine。
4. 验证 calls、decisions、state、manifest、reports 都落盘。

注意：fake runner 只证明控制面，不证明 runtime。

## 5. Live 验收

完整 `/report` live 验收必须：

- fixed runtime preflight。
- post-build OpenClaw dist 确认。
- provider payload capture。
- visible tools capture。
- approved material read。
- final report export。

## 6. 回归样本

至少覆盖：

- CN_A 样本。
- US 样本。
- HK 样本。
- CRYPTO 样本。
- 单 worker stop point。
- first response stop point。

## 7. 停止条件

- LLM 输出被用于决定下一 worker。
- Python 代写 worker 内容。
- hard-gate failed artifact 进入 manifest。
- PM 结论被 exporter 改写。
- full chain 只能靠 fake runtime 通过。
