# 材料与证据仓库模块测试计划

## 1. 测试目标

证明 worker 输出只有在 OpenViking L1/L2、receipt、claims、guard 全部满足时才能进入 approved manifest，并且下游/导出只能使用 approved material。

## 2. 单元测试

覆盖：

- material target URI 生成。
- URI 形状校验。
- manifest 添加和重复拒绝。
- manifest 上游选择。
- capability 范围校验。
- claims 解析。

建议命令：

```bash
uv run pytest tests/unit -q
```

可按 artifact/guard 相关测试聚焦。

## 4. Live 测试

需要 fixed runtime：

1. OpenViking `1933` health。
2. worker 写入 L1/L2。
3. receipt/stat/readback 成功。
4. manifest 记录 approved material。
5. 下游通过 capability 读取。
6. final exporter 从 OpenViking 读取 L1。

## 5. 负向测试

必须覆盖：

- receipt worker/stage/call 不匹配。
- L1 是 JSON。
- L1 空文本。
- L2 index hash 不匹配。
- claims 缺 evidence。
- 下游尝试裸 URI 读取。
- hard gate failed material 进入 manifest。

## 6. 停止条件

- 本地审计副本替代 OpenViking L1。
- failed material 进入 manifest。
- export claim 无 material claim 支撑。
- guard 被改造成风格过滤。
