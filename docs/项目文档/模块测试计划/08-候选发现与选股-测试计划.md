# 候选发现与选股模块测试计划

## 1. 测试目标

验证 `/select` 只做候选发现，不替代正式报告；验证命令解析、候选缓存、刷新、worker 顺序、工具收窄、用户确认和 `/report` handoff。

## 2. 单元测试

| 测试点 | 预期 |
| --- | --- |
| `/select` 默认解析为 A 股 | profile 为 `CN_A` |
| `/select 1`、`/select A`、`/select A股` | profile 为 `CN_A` |
| `/select 2`、`/select CRYPTO`、`/select 加密` | profile 为 `CRYPTO` |
| `/select refresh` | refresh flag 为 true |
| `/select US`、`/select 3` | 返回不支持，不回退 |
| 候选缓存 metadata 缺 hash | 读取失败 |
| 候选行为空 | 返回 data gap |
| lineage 缺失 | selection 不继续 |

候选测试文件范围：

- `tests/unit/selection/test_candidate_cache_contract.py`
- `tests/unit/selection/test_columnar_warehouse.py`
- `tests/unit/selection/test_refresh_service.py`
- `tests/contracts/test_selection_command_contract.py`

## 3. 调度合同测试

验证 worker 顺序固定：

```text
selection_strategist
selection_skeptic
selection_manager
selection_portfolio_manager
```

要求：

- LLM 不能决定下一 worker。
- manager 和 portfolio manager 不能看到候选缓存读取工具。
- 上游 worker 失败时下游不运行。
- provider payload 中 worker id、stage、tool schema 与阶段匹配。

相关测试：

- `tests/contracts/test_selection_dispatch_order.py`
- `tests/contracts/test_selection_stage_policy.py`
- `tests/contracts/test_selection_provider_payload.py`

## 4. 数据刷新集成测试

验证：

- refresh 创建数据 job。
- provider attempt 被记录。
- 列式仓库可写可读。
- latest terminal run 可被发现。
- readback hash 一致。
- provider 空返回时写 data gap，不生成假候选。

相关测试：

- `tests/integration/selection/test_data_job_pipeline.py`

## 5. UI 集成测试

验证：

- `/select` 可从聊天入口创建 selection 任务。
- selection 进度快照包含业务状态。
- 候选完成后显示确认入口。
- 用户确认后创建正式 report task。
- 用户取消后不继续 handoff。

相关测试：

- `tests/e2e/ui/test_research_ui_server.py`
- `tests/integration/selection/test_report_handoff_gate.py`

## 6. 失败用例

| 场景 | 预期 |
| --- | --- |
| 无候选缓存且未 refresh | 返回可操作失败 |
| refresh 数据源失败 | 任务失败并记录 provider/data gap |
| worker 调用失败 | 保留阶段证据，不生成 handoff |
| manager 工具 schema 泄漏 | 合同测试失败 |
| 用户未确认 | 不创建正式报告 |
| handoff candidate id 不属于当前 run | 拒绝 |

## 7. Live 验收

Live 验收需要先通过固定 runtime preflight。

验收步骤：

1. 使用 `scripts/start-control-runtime.sh -- <selection command>` 启动。
2. 输入 `/select`。
3. 检查 selection 四个 worker provider payload。
4. 检查候选报告生成。
5. 用户确认一个候选。
6. 检查正式 `/report` 任务创建。

验收产物：

- selection run id。
- candidate cache manifest。
- 四个 worker provider payload。
- 候选报告。
- handoff report task id。

## 8. 不通过条件

- selection 直接生成最终投资报告。
- 未确认就创建 `/report`。
- 不支持市场被静默回退。
- 缓存无 lineage 仍继续。
- manager/portfolio manager 暴露候选缓存工具。
- provider 失败后生成假候选。
