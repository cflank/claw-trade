# 用户界面后端与接口模块测试计划

## 1. 测试目标

验证 UI 后端接口稳定、普通聊天和正式命令边界清楚、报告队列和历史报告投影正确、错误不被吞掉。

## 2. 路由合同测试

| 接口 | 验证 |
| --- | --- |
| `POST /api/ui/send-chat-message` | 普通聊天、确认卡、明确命令三类响应 |
| `GET /api/ui/get-chat-session` | 返回指定会话消息 |
| `GET /api/ui/get-report-queue-snapshot` | 返回队列状态 |
| `POST /api/ui/cancel-report-task` | queued/running/completed 不同取消语义 |
| `GET /api/ui/list-saved-reports` | 只返回摘要 |
| `GET /api/ui/get-report-detail` | 返回正文、图表、appendix |
| `POST /api/ui/delete-saved-report` | 删除单份报告 |
| `POST /api/ui/delete-saved-reports` | 批量删除 |
| `POST /api/ui/internal/scheduled-work/cron-wake` | 内部 wake 分派 |

## 3. 聊天边界测试

用例：

- 用户普通提问：不创建 report task。
- 用户提到“帮我看看某股票”：返回确认卡或追问，不直接跑报告。
- 用户输入 `/report 600519`：创建 report task。
- 用户输入 `/select`：进入 selection，而非 report。
- 用户确认卡过期后点击：拒绝执行。

## 4. 报告队列测试

验证：

- queued 任务显示在队列中。
- running 任务显示当前 stage/worker。
- failed 任务显示用户可读失败原因。
- completed 任务携带 saved report id。
- 取消 queued 任务后状态为 cancelled。
- completed 任务不能取消。

## 5. 历史报告测试

验证：

- 列表接口不返回完整正文。
- 详情接口返回完整正文和图表资产。
- 不存在 report id 返回 404/错误 DTO。
- 删除后列表不再出现。
- 删除失败不影响其他报告。
- 正在发送或导出的报告受保护。

## 6. Worker 聊天测试

验证：

- 普通 worker 聊天携带 worker id。
- 报告阅读 worker 聊天携带 report context。
- worker 聊天失败时返回失败，不伪造回答。
- worker 聊天不写正式报告 manifest。

## 7. API fallback 测试

| 场景 | 预期 |
| --- | --- |
| 未知 `/api/ui/foo` | JSON 404 |
| 未知 `/api/other` | JSON 404 |
| 前端路由路径 | SPA fallback |
| 静态资源路径 | 返回静态资源或资源 404 |

## 8. 真实浏览器验收

UI 面向用户，最终验收必须使用 MCP 控制真实 Chrome，除非人工明确批准替代方法。

验收路径：

1. 打开本地 UI。
2. 发送普通聊天，确认没有 report task。
3. 输入 `/report`，确认队列出现任务。
4. 打开历史报告列表。
5. 打开报告详情。
6. 触发报告问答。
7. 触发 worker 聊天。
8. 验证 API 错误能在 UI 显示为可理解信息。

## 9. 不通过条件

- 普通聊天自动跑正式报告。
- 明确 report command 没有进入队列。
- 失败任务显示为成功。
- 前端 API 拼错被 SPA fallback 吞掉。
- 历史详情暴露内部 provider payload。
- worker 聊天写入正式 report artifact。
