# 运行时调用与运行证据模块测试计划

## 1. 测试目标

证明每个 worker turn 都通过 OpenClaw 执行，并捕获真实 provider payload、visible tools 和 worker 输出；没有用 Python fake LLM 或静态 prompt 替代 runtime evidence。

## 2. 单元测试

覆盖：

- `WorkerCall` 到 OpenClaw command 字段映射。
- evidence reader 读取完整证据。
- evidence 缺失时返回失败。
- stop-after-first-response 行为。
- gateway failure 被正确记录。

建议命令：

```bash
uv run pytest tests/unit/runtime -q
```

## 3. 合同测试

相关测试：

```text
tests/contracts/test_provider_payload_visible_tools.py
tests/contracts/test_worker_provider_payload_no_provider_leak.py
tests/contracts/test_provider_request_guard.py
tests/contracts/test_visible_tools_guard.py
tests/contracts/test_tool_calls_guard.py
tests/contracts/test_openclaw_worker_chat_contract.py
tests/contracts/test_openclaw_worker_chat_seam_missing_stops.py
```

覆盖：

- provider payload 必须存在。
- visible tools 必须等于 stage policy。
- prompt 不能泄漏 provider/audit protocol。
- worker chat seam 缺失时 fail closed。

## 4. OpenClaw source 测试

如果修改 `third_party/openclaw/src/**`：

```bash
cd third_party/openclaw
pnpm test -- <focused test>
pnpm build
```

然后必须回到仓库根目录重启 runtime 并 fresh live proof。

## 5. Live proof

最小 live proof：

1. fixed runtime preflight。
2. 单 worker `FIRST_RESPONSE` run。
3. 检查 provider payload final messages。
4. 检查 tool schema。
5. 检查 worker id、stage、run id、dispatch id、runtime marker。

## 6. 停止条件

- provider payload 只是静态 render。
- `dist` 未 build 却声称 runtime 已变。
- OpenClaw 里出现 claw-trade DAG 业务逻辑。
- Python 直接调用模型代替 OpenClaw。
