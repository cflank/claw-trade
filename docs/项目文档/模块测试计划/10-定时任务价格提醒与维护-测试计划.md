# 定时任务价格提醒与维护模块测试计划

## 1. 测试目标

验证定时报表、价格提醒、系统 wake、数据维护和报告清理的业务语义，确保 cron 只负责唤醒，业务状态由 `claw-trade` 管理。

## 2. 定时报表单元测试

| 场景 | 预期 |
| --- | --- |
| 创建定时报表 | 保存配置并创建 OpenClaw cron |
| cron 创建失败 | 返回 `CRON_PROVISION_FAILED` |
| 暂停报表 | 本地状态和 cron enabled 同步 |
| 恢复报表 | 本地状态和 cron enabled 同步 |
| 删除报表 | 删除 cron 并标记本地删除 |
| 手动运行 | 使用 idempotency key 调用 cron run |

## 3. 定时报表 wake 测试

| 场景 | 预期 |
| --- | --- |
| wake 缺 scheduledReportId | `INVALID_INPUT` |
| wake 缺 cronRunId | `INVALID_INPUT` |
| 报表不存在 | 明确失败 |
| 报表 disabled | 不创建 report task |
| 首次 wake | 创建 report task |
| 重复 cronRunId | 不重复创建 report task |

## 4. 价格提醒测试

| 场景 | 预期 |
| --- | --- |
| 创建提醒 | 保存 alert 和 scan bucket |
| 暂停提醒 | 状态变 paused，扫描跳过 |
| 恢复提醒 | 状态变 active |
| 删除提醒 | 状态变 deleted |
| 手动运行 | 立即读取报价并判断 |
| 报价不可用 | 不触发通知，记录错误 |
| 条件满足 | 发送通知并更新状态 |
| 条件不满足 | 不发送通知 |
| 重复行情点 | 不重复发送通知 |

## 5. 扫描 bucket 测试

验证：

- bucket 不存在时报错。
- active/error alert 被扫描。
- paused/deleted alert 被跳过。
- 多个 alert 共享同一报价。
- scan summary 统计正确。
- 单个 alert 失败不阻断同 batch 其它 alert，除非是全局不可恢复错误。

## 6. 数据维护测试

验证：

- `data_maintenance` wake 缺 market/jobKind 时失败。
- executor 未配置时失败。
- executor 抛错时返回 `DATA_MAINTENANCE_FAILED`。
- 成功时返回维护摘要。

## 7. Selection 自动刷新测试

验证：

- executor 未配置时失败。
- refresh 返回失败 payload 时转换为 `SELECTION_DATA_REFRESH_FAILED`。
- refresh 成功时返回 payload。

## 8. 报告清理测试

验证：

- 默认保留天数正确。
- 保存和读取清理设置。
- 重置为默认值。
- 过期报告被清理。
- 未过期报告保留。
- 正在发送或导出的报告被保护。
- 清理失败时返回失败摘要。

## 9. API 与权限测试

| 场景 | 预期 |
| --- | --- |
| 无内部 token 调 cron wake | 拒绝 |
| token 正确 | 允许分派 |
| 未知 wake kind | `INVALID_INPUT` |
| 外部普通用户调用内部 wake | 拒绝 |

## 10. 集成验收

集成验收需要：

1. 创建定时报表。
2. 触发 cron run。
3. 检查 report task 创建。
4. 创建价格提醒。
5. 用可控 quote provider 验证触发和不触发两类条件。
6. 检查通知结果。
7. 触发报告清理并检查保护中的报告未被删除。

## 11. 不通过条件

- cron wake 重复创建报告任务。
- 报价不可用仍触发提醒。
- 通知失败显示为成功。
- 内部 wake 无 token 可调用。
- 定时任务业务状态只存在 OpenClaw cron 里、本地不可审计。
- 清理删除正在发送或导出的报告。
