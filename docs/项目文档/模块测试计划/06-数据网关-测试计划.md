# 数据网关模块测试计划

## 1. 测试目标

证明数据网关公开请求边界、provider 规划、限流、fetch、ingest、warehouse、gap 和报告证据摘要真实可信。

## 2. 单元测试

建议命令：

```bash
uv run pytest tests/unit/data_gateway -q
```

覆盖：

- public request validate。
- DataNeed planner。
- dynamic rate limit scheduler。
- execution gate。
- single flight。
- managed HTTP。
- fetch engine。
- ingest pipeline。
- warehouse。
- normalized columnar warehouse。
- report evidence。

## 5. Live provider 测试

Live provider 测试必须：

- fixed runtime preflight。
- 明确 market/data type/sample。
- 保留 provider attempt evidence。
- 区分 success/empty/error/permission/rate-limit。
- 不把单样本结果泛化。

可使用：

```text
scripts/validation/provider_plugin_capability_probe.py
scripts/validation/cn_a_source_field_probe.py
scripts/validation/coinglass_project_interface_probe.py
scripts/validation/data_layer_full_chain_market_probe.py
```

## 6. 负向测试

必须覆盖：

- public request 带 provider/path/token 被拒。
- provider empty 不算 success。
- parser missing 产生 gap。
- rate limit budget 产生 evidence。
- columnar hash mismatch fail。
- warehouse missing 返回 gap。

## 7. 停止条件

- 数据层用 fallback 伪造完整结果。
- provider failure 被包装成 ready。
- cache 命中被写成 remote success。
- worker 直接传 provider 执行细节。
