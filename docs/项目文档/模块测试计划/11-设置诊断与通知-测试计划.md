# 设置诊断与通知模块测试计划

## 1. 测试目标

验证设置、诊断、渠道和通知能力真实反映系统状态，不泄漏 secret，不暴露未批准数据源能力，不伪造渠道或 provider 成功。

## 2. 模型设置测试

相关测试：

- `tests/unit/ui/test_llm_settings_bridge.py`
- `tests/unit/runtime/test_settings_projection.py`
- `tests/settings/test_report_model_gate.py`
- `tests/settings/live/test_report_model_gate_live.py`

验证：

- 加载模型设置隐藏 secret。
- 保存设置后投影正确。
- 重置默认值返回明确结果。
- provider health summary 可解释 provider 状态。
- provider 不可用时不显示为可用。

## 3. 数据源设置测试

相关测试：

- `tests/unit/ui/test_data_source_settings.py`
- `tests/unit/ui/test_configured_failed_data_sources.py`
- `tests/settings/test_enhanced_source_health_probes.py`
- `tests/settings/test_enhanced_sources.py`
- `tests/settings/live/test_enhanced_source_approved_scope_live.py`

验证：

- 只允许批准的数据源类型。
- 未知 HTTP/JSON 数据源被阻止。
- health probe 成功时可保存。
- health probe 失败时返回健康事件。
- UI DTO 不包含真实密钥。

## 4. 设置安全测试

相关测试：

- `tests/settings/test_settings_forbidden_surface.py`
- `tests/unit/ui/test_settings_security.py`
- `tests/settings/live/test_settings_no_fake_success_live.py`
- `tests/settings/live/test_settings_preflight_evidence_contract.py`

验证：

- 不返回 forbidden fields。
- 配置失败不写成成功。
- live 设置验收有 preflight evidence。
- scope guard 禁止越界能力。

## 5. 渠道桥测试

相关测试：

- `tests/unit/ui/test_channel_bridge.py`
- `tests/unit/ui/test_channel_inbound_bridge.py`
- `tests/unit/ui/test_channel_text_inbound.py`
- `tests/settings/live/test_wechat_qr_channel.py`

验证：

- 插件未安装、未启用、未登录分别返回不同用户状态。
- 保存渠道配置后重新 probe。
- send text 和 send file 失败时返回失败。
- 入站消息能进入聊天控制器。
- provider channel id 不暴露给 UI。

## 6. 报告通知测试

相关测试：

- `tests/unit/ui/test_report_notification_service.py`
- `tests/unit/ui/test_report_success_pdf_notification.py`

验证：

- 报告不存在时失败。
- 渠道未连接时失败。
- 默认目标缺失时失败。
- 文件发送中 report cleanup 受保护。
- 发送成功返回渠道结果。
- 发送失败不显示成功。

## 7. 高级诊断测试

相关测试：

- `tests/settings/test_advanced_diagnostics_provider_health.py`
- `tests/settings/test_advanced_diagnostics_runtime_status.py`
- `tests/settings/test_live_run_gap_summary.py`
- `tests/settings/test_evidence_failure_reason_summary.py`
- `tests/settings/live/test_provider_health_summary_live.py`
- `tests/settings/live/test_runtime_service_status_summary_live.py`
- `tests/settings/live/test_live_run_gap_summary_live.py`
- `tests/settings/live/test_evidence_failure_reason_summary_live.py`

验证：

- provider health summary 字段完整。
- runtime service status 能反映健康和不可用。
- live run gap summary 能解释缺口。
- evidence failure reason summary 能归类失败。
- 诊断接口不修改配置。

## 8. 重置设置测试

验证：

- 模型、数据源、渠道、报告清理设置都参与重置。
- 单项失败能在返回中体现。
- 重置后 UI 状态与默认值一致。
- 不返回 raw patch result。

## 9. 不通过条件

- secret 明文返回给 UI。
- 未批准数据源类型可保存。
- provider health 失败却显示正常。
- 渠道未连接仍允许报告文件发送成功。
- 通知发送失败显示已送达。
- 诊断接口产生配置副作用。
