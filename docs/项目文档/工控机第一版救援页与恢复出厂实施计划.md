# 工控机第一版救援页与恢复出厂实施计划

日期：2026-06-26
状态：部分实施

当前分支状态：已完成生产包、路径、systemd、kiosk、最小 rescue 服务、`rescue-current` 救援启动链路、systemd 失败后 rescue takeover 触发器、恢复出厂固定删除逻辑、恢复出厂维护锁、主设置页恢复出厂入口、远程更新失败回滚和对应局部测试；尚未完成运行中任务取消、诊断包、授权修复、网络诊断、手动导入签名更新包、VM/systemd/真实 Chrome 验收。

## 目标

在正式工控机生产版中交付最小本地救援页和恢复出厂能力：

- 客户不能登录 Ubuntu 时，仍能在本机界面修复授权、诊断网络、导出脱敏诊断包、手动导入签名更新包；
- 产品主服务连续启动失败时，自动进入最小救援页；
- 用户可从设置页执行恢复出厂设置；
- 恢复出厂清空客户 API KEY、报告、缓存、队列和用户设置；
- 恢复出厂保留 Virbox 激活状态、root-owned 更新公钥 `/etc/claw-trade/update-signing-public.pem`、当前稳定版本和上一可用版本。

恢复出厂不是重装 Ubuntu，也不是清空整机磁盘。它只重置 claw-trade 应用状态。

## 一句话边界

救援页和恢复出厂是项目级恢复，不是 OS 级恢复。

它不重装 Ubuntu，不执行系统还原，不改内核、驱动、分区、用户账号策略或系统包版本。Ubuntu 只负责用 `systemd` 拉起服务，用 kiosk 浏览器打开 `127.0.0.1:5175`。

恢复出厂只处理 `/opt/claw-trade/shared` 下允许清空的应用运行期状态。release 包、`current` 链接、root-owned 更新公钥 `/etc/claw-trade/update-signing-public.pem`、Virbox 激活状态和上一可用版本必须保留。

## 范围

### 交付

- 最小救援页后端和静态前端入口。
- 启动失败计数和救援模式切换。
- 授权状态查看、重新激活或更换授权码入口。
- 网络诊断。
- 脱敏诊断包导出。
- 手动导入签名更新包。
- 恢复出厂设置。
- 当前版本和上一可用版本展示。

### 不交付

- shell。
- 任意命令执行。
- 文件管理器。
- 报告生成。
- 数据刷新。
- OpenClaw worker 调度。
- 独立安全恢复系统。
- 重装 Ubuntu。
- 防 root、拆盘或专业逆向。

## 架构边界

- 救援页只处理产品恢复和诊断，不参与投资报告工作流。
- 恢复出厂只删除应用运行期状态，不删除 release 包、更新公钥或 Virbox 激活状态。
- 救援页不能暴露 provider payload、报告正文、客户 API KEY、完整授权码或原始日志。
- 前端只能触发后端已定义操作；删除范围和保留范围由后端固定。
- 授权无效时允许使用救援页，但仍禁止报告生成和数据刷新。
- 所有本机状态变更 API 必须有后端鉴权、来源校验和 CSRF 防护；kiosk 允许访问的外部网页不能触发授权、诊断、更新导入或恢复出厂操作。

## 本机目录合同

保留：

```text
/opt/claw-trade/current
/opt/claw-trade/releases/
/opt/claw-trade/shared/license/
/opt/claw-trade/shared/updates/
/opt/claw-trade/shared/logs/factory-reset/
```

恢复出厂清空或重建：

```text
/opt/claw-trade/shared/config/
/opt/claw-trade/shared/data/
/opt/claw-trade/shared/reports/
/opt/claw-trade/shared/cache/
/opt/claw-trade/shared/queues/
/opt/claw-trade/shared/sessions/
```

普通 `shared/logs/` 不原样长期保留。恢复出厂前先导出本次脱敏诊断包；恢复出厂后只保留本次 factory-reset 脱敏审计日志，其他普通日志删除或脱敏归档。

如果当前实现还没有上述目录，任务中应先把生产路径集中定义到 `src/claw_trade/production/paths.py`，并列出现有状态文件迁移和归属。不要在多个服务里散写路径。

## 救援模式入口

正常启动：

```text
systemd 启动 claw-trade
-> 后端健康检查通过
-> kiosk 打开主 UI
```

启动失败恢复：

```text
后端健康检查失败
-> 启动失败计数 +1
-> 连续 3 次失败
-> 尝试回滚上一可用 release
-> 回滚失败或仍不健康
-> 启动最小救援页接管 127.0.0.1:5175
```

第一版救援页复用 kiosk 已打开的 `127.0.0.1:5175`。生产 launcher 负责在主服务健康时启动主 UI，在主服务连续失败且回滚失败时停止主 UI 并启动最小 `claw-trade-rescue` 服务接管同一端口。救援页端口和主 UI 端口应固定记录在 systemd/env 中，不能靠前端猜测。

## 恢复出厂流程

```text
设置页或救援页请求
-> 二次确认
-> 创建恢复前脱敏诊断包
-> 维护锁阻断 claw-trade 新报告、选股刷新、定时任务和价格提醒扫描入口
-> 对已知运行中任务做 best-effort 取消，超时则停止恢复出厂并进入救援页
-> 标记 maintenance lock
-> 删除运行期配置、报告、缓存、队列、会话和用户设置
-> 保留 Virbox 激活状态、更新公钥、当前稳定版本和上一可用版本
-> 重建默认配置
-> 清除 maintenance lock
-> 重启服务
-> 健康检查
-> 返回成功或进入救援页
```

删除操作必须是固定 allowlist。禁止接收前端传来的任意路径。

## 诊断包合同

默认包含：

- 产品版本；
- 当前 release 和上一可用 release；
- 授权状态摘要；
- 服务状态；
- 健康检查结果；
- 更新状态；
- 恢复出厂状态；
- 网络诊断摘要；
- 脱敏日志。

默认不包含：

- 客户 API KEY；
- 完整授权码；
- provider payload；
- 报告正文；
- 原始日志片段；
- `.env.local` 明文；
- 数据库原始数据；
- OpenClaw 会话原文。

诊断包只能从固定 allowlist 摘要源收集，禁止递归扫描日志、会话、provider payload 或报告目录。脱敏失败、敏感字段扫描命中、发现 provider payload、报告正文、API KEY、完整授权码或 OpenClaw 会话时，默认拒绝导出。

如果排障必须导出报告正文或 provider payload，必须单独增加本机确认流程；不属于第一版默认诊断包。

## 网络诊断边界

网络诊断是固定探针集合，不是命令执行入口。

第一版只允许：

- DNS 解析固定厂商域名；
- HTTPS 访问 Virbox 授权 endpoint；
- HTTPS 访问对象存储更新 manifest；
- 本机 `127.0.0.1:5175` 健康检查；
- 固定超时和脱敏输出。

禁止：

- 前端传 shell 命令、命令参数数组或可执行路径；
- 前端传任意本机、内网或公网目标；
- ping/traceroute/nslookup 等 shell 拼接；
- 输出原始 header、token、授权码或 API KEY。

## 实施任务

### Task 0：生产包、路径和 rescue 入口基线

- 复用并收敛现有 `scripts/production`、`packaging/production/bin`、preflight、systemd、kiosk 和 `/opt/claw-trade/current -> releases/<version>` 合同。
- 明确 `claw-trade-rescue` 最小服务如何接管 `127.0.0.1:5175`，以及主 UI 和救援页不能同时监听同一端口。
- 明确 `/opt/claw-trade/shared` 下真实运行期状态清单，包括 API KEY、队列、报告、缓存、OpenClaw 状态、UI 设置和临时文件。
- Virbox 未授权相关验收依赖“部署验证门与最小生产包计划”中的授权门完成；本计划不得用假授权补齐。

验收：

- VM 中正常启动时 kiosk 打开主 UI。
- VM 中主服务连续失败且回滚失败时 kiosk 仍停留同一地址并显示救援页。
- 不新增平行安装根目录或第二套生产路径。

当前分支已落地的 Task 0 范围：

- `/opt/claw-trade/current -> releases/<version>` 和 `/opt/claw-trade/shared` 路径基线。
- `clawtrade` 服务用户和 `clawkiosk` kiosk 用户基线。
- systemd control、UI、kiosk unit。
- `claw-trade-rescue` 最小 FastAPI 救援服务入口和 rescue unit。
- rescue unit 从 `/opt/claw-trade/rescue-current` 启动，避免坏 `current` 阻断救援页。
- rescue unit 与主 UI unit 互斥，声明同一端口 `127.0.0.1:5175` 不能同时监听。
- control/UI systemd unit 配置 `StartLimit` 和 `OnFailure=claw-trade-rescue-trigger.service`，连续失败后触发 rescue takeover。
- root-owned update apply 服务使用 `/etc/claw-trade/update-signing-public.pem` 复验 signed manifest/archive，在更新后切换 `current`、重启 control/UI，健康检查失败时回滚上一版本，回滚仍不健康时触发 rescue takeover；服务运行期间持有 `shared/updates/apply.lock`，`rescue-current` 不随浅健康检查自动推进。
- `FactoryResetService` 使用后端固定 allowlist 清空 `/opt/claw-trade/shared` 下的运行期目录。
- `FactoryResetService` 拒绝相对安装根、安装根路径逃逸、`shared` symlink、删除目标 symlink 和 logs symlink。
- 恢复出厂期间写入 `/opt/claw-trade/shared/maintenance.lock`，UI 后端在锁存在时拒绝状态变更 POST。
- 主 UI 新增本机恢复出厂 API 和设置页危险操作入口。
- 最小 rescue 页提供状态查看、恢复出厂按钮和恢复出厂 API。
- 已有局部测试覆盖路径合同、恢复出厂删除/保留范围、rescue API 和主 UI 恢复出厂 API。

当前分支未实现：

- 持久化启动失败计数和可视化失败原因。
- 已运行任务取消。
- 恢复前脱敏诊断包。
- 授权修复、网络诊断和手动导入签名更新包。
- 外部网页不能触发本机状态变更 API 的真实 Chrome 证据。
- 真实 Chrome 和 VM/systemd 验收。

## 停止条件

- 恢复出厂删除路径来自前端参数。
- 恢复出厂可能删除 release、updates、license 或更新公钥。
- 默认诊断包包含 API KEY、完整授权码、provider payload、报告正文或原始日志。
- 诊断包通过递归扫描日志、会话、provider payload 或报告目录生成。
- 救援页能触发报告生成、数据刷新、worker 调度、shell 或任意命令。
- 本机状态变更 API 能被外部网页触发。
- 网络诊断接受任意 host、shell 命令或命令参数。
- 启动失败只能显示白屏，不能进入救援页或导出诊断。
- 为了通过测试加入 mock 成功、假授权、假更新或假健康检查。
