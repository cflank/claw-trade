# 项目总体需求

## 1. 文档定位

本文是 `claw-trade` 当前代码状态下的产品总体需求。它基于：

- 当前代码目录：`src/`、`agents/`、`tests/`、`third_party/openclaw/`。
- 归档旧文档：`docs/项目文档/归档/原有文档/`。
- 提交历史和 `memory/` 实施记录。
- 本轮只读子代理盘点结果。

本文不是运行验收报告。本轮没有启动 OpenClaw、OpenViking、MongoDB、真实 provider 或真实浏览器，因此凡涉及“已实现”的表述都只表示代码和历史记录中存在对应能力，不表示当前本机 runtime 已有 fresh live 验收结论。

## 2. 产品一句话

`claw-trade` 是一个中文投研工作台：用户通过聊天或明确命令发起选股、报告、定时报表和价格提醒；系统用 `claw-trade` 控制工作流，用 OpenClaw 唤醒真实 worker，用数据层取证，用 OpenViking 承载已批准材料，最后生成可审计、可阅读、可追问、可导出和可发送的投资研究报告。

## 3. 产品目标

### 3.1 最高目标

生成真实、证据扎实、有 TradingAgents / TradingAgents-CN 报告感的中文投资报告。

“报告感”不是排版词。它要求：

- 有完整分析链条。
- 有清晰投资主线。
- 有多空辩论。
- 有风险挑战和风险整合。
- 有交易执行条件。
- 有最终组合经理裁决。
- 有图表或数据证据时能展示；没有时能说明真实缺口。
- 不把报告写成内部审计日志、合规免责声明或工程 checklist。

### 3.2 工程目标

系统必须可审计：

- 知道哪个 worker 在哪个阶段被唤醒。
- 知道发送给模型的最终 provider payload。
- 知道模型当时可见的工具 schema。
- 知道每个数据请求尝试过哪些 provider。
- 知道每个 worker 输出如何变成 approved material。
- 知道最终报告引用了哪些 approved material。

系统必须保留权威边界：

- `claw-trade` 控制工作流。
- OpenClaw 执行单 worker turn。
- Agent 配置拥有 prompt / skill / stage policy。
- OpenViking 承载 approved material 和证据链。
- Python 可以调度和搬运材料，但不能假扮 worker 写投资观点。

## 4. 用户类型

### 4.1 普通投研用户

普通用户通过 UI 完成：

- 普通聊天。
- 输入 `/report` 生成正式报告。
- 输入 `/select` 发现候选标的。
- 确认候选后转报告。
- 查看报告生成进度。
- 阅读历史报告。
- 对报告提问。
- 选择 worker 进行上下文聊天。
- 导出 PDF。
- 发送完整报告文件。
- 配置定时报告和价格提醒。
- 配置模型、数据源、通知渠道。

普通用户不应该看到内部实现词作为主要解释，例如 OpenViking URI、provider attempt hash、Mongo collection、OpenClaw payload 等。

### 4.2 系统维护者

维护者负责：

- 配置 OpenClaw、OpenViking、MongoDB、本地列式仓库和 provider 凭证。
- 执行 fixed runtime preflight。
- 跑单元、合同、集成、live 和真实浏览器验收。
- 处理数据源权限、限流、空返回和失败。
- 审查文档、代码、证据是否一致。

## 5. 市场范围

### 5.1 已定义市场

当前产品按 profile 区分市场：

| 市场 | profile | 当前语义 |
| --- | --- | --- |
| A 股 | `CN_A` | TradingAgents-CN 风格中文 A 股研究，前线扩展为 7 个 worker |
| 美股 | `US` | 原始 TradingAgents 风格研究 |
| 港股 | `HK` | 独立港股 profile，不允许回退到 A 股或美股 |
| 加密市场 | `CRYPTO` | 独立加密 profile，不允许伪装为股票市场 |

### 5.2 市场语义要求

- A 股可以使用“股票、公司、政策、资金流、限售解禁”等语义。
- 美股和港股必须使用对应市场数据和 prompt 语义。
- 加密市场使用“标的、交易对、代币价格、USDT、链上/衍生品/资金费率”等语义，不能写成股票。
- HK 和 CRYPTO 缺 prompt/profile 时必须 fail closed，不能自动套用 CN_A 或 US。

## 6. 核心用户场景

### 6.1 普通聊天

用户在 UI 中发送普通消息，系统通过 OpenClaw lightweight/chat agent 回复。

要求：

- 普通聊天不自动进入报告 workflow。
- 普通聊天可以识别意图并生成确认卡片，但必须等用户确认。
- 普通聊天上下文和报告上下文需要区分。

### 6.2 `/report` 正式报告

用户明确输入 `/report` 或通过确认卡片创建报告任务。

要求：

- 报告任务进入队列。
- UI 展示任务状态、当前 worker、失败原因和完成结果。
- 报告流程必须按 `claw-trade` 固定阶段执行。
- 后续 worker 只能读取 approved upstream material。
- 最终报告必须保存到报告仓库并进入历史。

### 6.3 `/select` 候选发现

用户输入 `/select` 发起候选发现。

要求：

- 默认 `/select` 走 A 股。
- `/select 2`、`/select CRYPTO`、`/select 加密` 走加密市场。
- `refresh` token 可以触发数据刷新。
- selection workflow 生成候选报告，但不等同于正式投资报告。
- 用户确认候选后才创建 `/report` handoff。

### 6.4 报告阅读和追问

用户可以打开历史报告，阅读正文、图表、PM 结论和 worker appendix，并继续问问题。

要求：

- 报告问答使用报告上下文，不改写原报告。
- Worker 聊天必须明确 worker。
- 报告阅读 worker 聊天可读取报告材料，但不产生正式 artifact。
- 普通 worker 聊天和报告阅读 worker 聊天是两种模式。

### 6.5 PDF 和渠道发送

用户可以导出 PDF 或把完整报告文件发送到配置好的渠道。

要求：

- PDF 必须是真 PDF 渲染结果，不能把 Markdown 改后缀伪装成 PDF。
- 渠道发送失败时不能伪造成功。
- 发送中的报告应受清理保护。

### 6.6 定时报表、价格提醒和系统后台任务

用户可以创建、暂停、恢复、删除和手动触发的业务任务只包括定时报表和价格提醒。selection 数据刷新、数据维护、报告保留期清理和发送中清理保护属于系统后台任务或维护任务，不是普通用户直接创建的定时任务。

要求：

- OpenClaw cron 只负责按时叫醒。
- `claw-trade` 负责业务任务状态、报价判断、报告队列、通知决策、后台维护状态和证据。
- 同一 cron run、内部 wake、CLI provisioner 运行或同一调度窗口必须幂等，不能重复创建报告、重复通知或重复执行破坏性维护动作。
- 定时报表、价格提醒和系统后台任务失败必须保留失败类型和用户可读原因。
- 报价不可用时 fail closed，不触发假提醒。

## 7. 报告链路需求

### 7.1 阶段顺序

正式报告包含以下阶段：

1. 前线分析。
2. 投资辩论。
3. 研究经理决策。
4. 交易执行计划。
5. 风险辩论。
6. 组合经理最终裁决。
7. 读者版最终报告生成。

### 7.2 Worker 覆盖

默认前线 worker：

- 市场分析师。
- 基本面分析师。
- 新闻分析师。
- 社媒/情绪分析师。

A 股额外前线 worker：

- 政策分析师。
- 资金流跟踪。
- 限售解禁观察。

下游 worker：

- 多头研究员。
- 空头研究员。
- 研究经理。
- 交易员。
- 风险挑战方。
- 风险防守方。
- 风险中立整合方。
- 组合经理。
- 报告润色 worker。

### 7.3 Worker 行为要求

- Worker 必须是 OpenClaw agent，不是 Python 函数。
- Worker prompt 来自 agent 配置，不由 Python 临时手写投资 prompt。
- Worker 可以表达证据支持的强观点、买入/持有/卖出、风险判断和交易条件。
- 真实性红线不能被扩展成“不要强观点”“不要交易建议”“写中性 memo”等风格限制。

### 7.4 PM 权威

组合经理拥有最终投资决策。

要求：

- Python 不改写 PM rating。
- Python 不改写 PM final decision。
- exporter 不新增 unsupported investment conclusion。
- `report_polisher` 生成读者版报告，但不是 PM 决策 owner。

## 8. 数据需求

### 8.1 数据入口

Worker 和 UI 只能表达业务数据需求，不直接指定 provider 执行细节。

允许表达：

- 市场。
- 标的或 universe。
- 数据类型。
- 粒度。
- 时间范围。
- 用途。
- 新鲜度。

禁止表达：

- provider 内部路径。
- API name / API id。
- 原始字段名。
- token。
- HTTP 参数。
- 数据层内部排序策略。

### 8.2 数据真实性

数据层必须记录：

- 规划了哪些 DataNeed。
- 尝试了哪些 provider。
- 哪些成功、空返回、权限缺失、限流、错误。
- 数据写入了哪些 raw/normalized/manifest。
- 哪些数据缺口影响报告或 selection。

不能：

- 把 provider 失败改成成功。
- 用 fake rows 补齐。
- 用 cache 命中伪装最新远端成功。
- 因为报告需要某项数据就发明 PE/PB/ROE、目标价、新闻、情绪或图表。

## 9. Selection 需求

### 9.1 A 股 selection

A 股 selection 面向候选股票发现。

要求：

- 使用后台确定性数据任务生成候选池。
- 使用列式仓库作为行情和特征主存储。
- Mongo 只保存运行状态、manifest、attempt 等元数据。
- 候选缓存必须包含评分、字段命中、缺口和证据。

### 9.2 CRYPTO selection

CRYPTO selection 面向加密标的发现。

要求：

- 使用 CRYPTO profile。
- 当前口径读取 USDT-only 列式历史仓库。
- 不走 A 股交易日历。
- 不新增未经批准的下载器或外部源。
- 输出使用加密市场语义。

### 9.3 Handoff

用户确认 selection 结果后，才能创建正式 report run。

要求：

- handoff 幂等。
- 候选身份和市场必须再校验。
- selection handoff、queue payload、dedupe/idempotency 字段必须纳入用户 DTO 和脱敏合同。

## 10. 定时报表、价格提醒和后台维护需求

### 10.1 定时报表

用户可以配置周期性报告任务。

要求：

- 支持创建、暂停、恢复、删除和手动运行。
- 到点后由 OpenClaw cron 唤醒 `claw-trade`。
- `claw-trade` 根据保存的定时报表配置创建正式 `/report` 任务。
- 重复 wake 必须幂等，不能重复入队。
- cron 同步失败必须显示为失败或同步异常，不能显示为已配置成功。

### 10.2 价格提醒

用户可以配置价格阈值或涨跌幅提醒。

要求：

- 支持创建、暂停、恢复、删除和立即检查。
- 扫描任务按市场和 bucket 批量执行。
- 报价必须来自数据网关报价 provider。
- 报价缺失、陈旧或不可审计时不能触发提醒。
- 通知发送失败时记录失败或 fallback，不伪造渠道送达。

### 10.3 系统后台任务

系统后台任务包括：

- selection 数据自动刷新。
- 数据维护和修复。
- 报告保留期清理。
- 报告发送中的清理保护。

要求：

- 后台任务可由 system cron、内部 wake 或 CLI provisioner 触发，不是普通用户在 UI 中直接创建、暂停、恢复、删除的定时任务。
- 后台任务必须有明确 kind、run id 或等价幂等键。
- 任务结果必须可审计。
- 未配置 executor 时必须失败，不静默忽略。
- 清理任务不能删除正在发送或正在导出的报告。

## 11. UI 需求

UI 是用户工作台，不是 debug console。

必须提供：

- 普通聊天。
- 任务确认卡片。
- 报告队列。
- 报告历史。
- 报告阅读器。
- worker 进度。
- 报告问答。
- worker 聊天。
- 图表证据状态。
- PDF 导出。
- 渠道状态和发送。
- 定时报表管理。
- 价格提醒管理。
- 系统后台任务和维护状态。
- 设置页。
- 高级诊断。
- 报告保留和删除。

UI 文案必须：

- 使用普通中文解释。
- 避免把内部标识当主说明。
- 清楚区分失败、等待配置、运行中、完成。
- 不把数据源不可用写成系统成功。

## 12. 设置和诊断需求

设置页应覆盖：

- 模型配置。
- Embedding 配置。
- 数据源配置和测试。
- 渠道配置。
- 报告 workflow 参数。
- 报告保留时间。
- 高级诊断。

诊断要区分：

- Provider 配置缺失。
- Provider 权限缺失。
- Runtime 服务不可达。
- 最近 live run 数据缺口。
- Evidence failure reason。
- 可选能力不可用。

## 13. 运行和部署需求

### 13.1 本地开发 runtime

固定 runtime 口径：

- 使用 `scripts/start-control-runtime.sh`。
- OpenViking 监听 `1933`。
- OpenClaw gateway 监听 `18789`。
- 不使用 invest sidecar。
- config/data/cache 写到 `.runtime/dev-services`。
- 需要 clean runtime 的测试用 `scripts/start-control-runtime.sh -- <command>`。

### 13.2 关键依赖

运行环境依赖包括：

- Python 3.12+。
- FastAPI / Uvicorn。
- OpenViking `0.3.5`。
- MongoDB client。
- DuckDB。
- pdfkit / pypandoc。
- AkShare、Tushare、Baostock、Mootdx、YFinance 等 provider 依赖。
- vendored OpenClaw Node runtime。

这些依赖存在不代表 provider 凭证或 live 数据可用。

## 14. 验收需求

### 14.1 静态验收

- 文档结构完整。
- 代码目录和文档模块一致。
- 合同测试覆盖边界。
- `git diff --check` 通过。

### 14.2 单元和合同验收

- workflow controller。
- worker workspace。
- stage policy。
- data API contract。
- OpenViking guard。
- provider payload。
- report exporter。
- selection。
- UI DTO。
- guard freeze。

### 14.3 Live runtime 验收

必须证明：

- runtime preflight 通过。
- OpenClaw gateway 可用。
- OpenViking 可用。
- Mongo/列式仓库可用。
- provider payload 捕获是真实最终请求。
- visible tools 符合 stage policy。
- approved material 能被读取。
- final report 能导出。

### 14.4 UI 验收

UI-facing 工作流最终验收必须用真实 Chrome，除非人明确批准替代方式。

至少覆盖：

- 普通聊天不触发报告。
- `/report` 任务创建。
- `/select` 任务和 handoff。
- 报告完成和历史展示。
- 报告详情、问答、worker 聊天。
- PDF 导出。
- 设置和诊断。

## 15. 非目标

当前不做：

- 把 OpenClaw 改造成完整 TradingAgents DAG 引擎。
- 在 Python 里新增 12 个 worker 类。
- 让 Python 生成投资观点。
- 用 fallback/mock/fake 绕过 hard gate。
- 无审批新增表达风格类 runtime guard。
- 把旧任务清单继续当活跃设计入口。
- 用单次 provider 成功证明全市场能力。

## 16. 已知风险

| 风险 | 影响 | 当前处理 |
| --- | --- | --- |
| A 股报告多样本偏卖出 | 投资判断质量风险 | 作为报告质量专项，不归因于数据层缺口 |
| 旧文档路径被归档 | 部分测试和脚本仍读旧路径 | 本轮不改代码，只在测试计划记录迁移项 |
| OpenClaw `src/dist` 不一致 | runtime 证据失真 | runtime seam 改动必须 build/restart/fresh proof |
| Provider 凭证和限流 | live 能力不稳定 | 数据层记录真实 gap 和 attempts |
| `docs/evidence` 进入本轮前已有删除状态 | 历史证据引用可能断裂 | 本轮未恢复，文档不依赖这些证据作为活跃设计 |
