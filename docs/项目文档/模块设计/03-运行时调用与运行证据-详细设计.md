## 2. Request builder

`request_builder.py` 负责运行前校验和 call 构造。

校验项：

- worker id 是否存在。
- worker 所属 stage 是否匹配。
- worker workspace 是否完整。
- profile 是否批准。
- stage policy 是否存在。
- stage policy 是否匹配 worker。
- tool registry 是否可解析。
- manifest 是否能提供上游材料。
- downstream manifest contract 是否满足。

## 3. OpenClaw command

`openclaw_client.py` 将 `WorkerCall` 转为 OpenClaw command。

命令必须包含：

- agent / worker 身份。
- stage。
- profile。
- runtime vars。
- allowed tools。
- upstream materials。
- OpenViking read capabilities。
- material target。
- evidence dir。
- stop-after-first-response。

## 4. Local runner

`openclaw_local_runner.py` 通过 gateway 调用 OpenClaw。

本地默认：

- gateway URL：`127.0.0.1:18789`。
- method：`agent.runSingleWorker`。

调用失败必须作为 runtime failure 记录，不允许返回 fake worker result。

## 5. Evidence reader

`evidence_reader.py` 读取 OpenClaw 证据目录。

必须读取或校验：

- provider payload。
- visible tool schema。
- LLM 输出。
- tool calls。
- first response。
- worker report。
- runtime metadata。

如果 evidence 缺失，应由 guard 或 runner 阻断，不能默默降级。

## 6. OpenClaw schema seam

`/home/frank/src/claw-trade/third_party/openclaw/src/gateway/protocol/schema/agent.ts` 定义 gateway 入参。`agent.runSingleWorker` 需要支持 claw-trade 当前字段。

`/home/frank/src/claw-trade/third_party/openclaw/src/gateway/server-methods/agent.ts` 执行单 worker turn。

这些代码变更需要 build 到 `dist` 才能影响 runtime。

## 7. 与 guards 的关系

OpenClaw 模块提供证据，guards 判断证据是否可信。

相关 guards：

- provider request guard。
- visible tools guard。
- tool calls guard。
- workspace evidence guard。
- OpenViking runtime read guard。

## 8. 与 UI chat 的关系

UI 普通聊天和 worker 聊天也可能通过 OpenClaw gateway，但它们不是正式 `/report` worker call。文档和测试必须区分：

- 报告 worker turn。
- selection worker turn。
- scheduled worker wake。
- ui_chat lightweight agent。
- worker chat agent。

## 9. 已知限制

- 静态 `src` 检查不能证明 `dist` 运行行为。
- 本轮文档未启动 `18789` gateway。
- provider payload 是否真实，只能由 fresh runtime evidence 证明。
