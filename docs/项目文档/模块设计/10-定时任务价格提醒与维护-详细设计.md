# 定时任务价格提醒与维护模块详细设计

## 1. 存储模型

`scheduled_work_store.py` 提供统一存储抽象。

主要对象：

```text
ScheduledReport
  id
  name
  instrument
  market
  schedule
  enabled
  openclaw_cron_job_id
  last_cron_run_id
  last_run_task_id
  sync_error_message

PriceAlert
  id
  instrument
  market
  condition
  state
  scan_bucket
  last_quote
  last_triggered_at
  last_error_message

PriceAlertScanBucket
  bucket_key
  market
  schedule
  openclaw_cron_job_id
  last_scan_summary
```

实现包括内存存储和 JSON 文件存储。生产化部署应优先使用持久化存储。

## 2. Cron adapter

`openclaw_cron_adapter.py` 把业务操作映射到 OpenClaw cron gateway：

| 方法 | 目的 |
| --- | --- |
| `add_job` | 创建 cron job |
| `update_job` | 修改启停或 schedule |
| `remove_job` | 删除 job |
| `run_job` | 手动触发 |
| `list_jobs` | 查询 job |
| `status` | 查询状态 |
| `runs` | 查询运行记录 |

adapter 只封装调用，不改变业务语义。

## 3. 定时报表创建

创建流程：

1. 校验用户输入。
2. 标准化标的和市场。
3. 生成 schedule。
4. 保存 ScheduledReport 草稿。
5. 调用 OpenClaw cron 创建 job。
6. 保存 `openclaw_cron_job_id`。
7. 返回 UI DTO。

cron message 示例语义：

```json
{"kind":"scheduled_report","scheduledReportId":"...","cronRunId":"auto"}
```

## 4. 定时报表 wake 处理

处理步骤：

1. 校验 `scheduledReportId` 和 `cronRunId`。
2. 读取 ScheduledReport。
3. 检查 enabled 状态。
4. 检查 duplicate `cronRunId`。
5. 构造 report queue request。
6. 入队正式 `/report` 任务。
7. 更新 `last_cron_run_id` 和 `last_run_task_id`。

重复 wake 应返回已有 task，而不是创建新任务。

## 5. 价格提醒创建

创建流程：

1. 校验标的、市场、条件。
2. 创建 PriceAlert。
3. 计算 scan bucket。
4. 保存或更新 bucket。
5. 如配置 OpenClaw cron，创建扫描 job。
6. 返回 alert DTO。

条件类型包括价格上穿、价格下破、涨跌幅等由现有 condition 结构表达的触发条件。

## 6. 报价读取和触发判断

价格提醒不直接调外部接口，而是通过 `src/claw_trade/data_gateway/price_quote_provider.py`。

触发判断：

```text
quote unavailable -> mark error / skip trigger
condition true -> notify and update last triggered
condition false -> update checked time
paused/deleted -> skip
```

报价不可用时不能触发提醒。

## 7. 价格扫描 bucket

`PriceAlertScanService.scan_bucket(bucket_key, cron_run_id)`：

1. 读取 bucket。
2. 找到 active/error alert。
3. 按市场和标的分组。
4. 批量读取报价。
5. 对每个 alert 应用条件。
6. 发送触发通知。
7. 保存扫描摘要。

扫描摘要包括：

- bucket key。
- cron run id。
- scanned count。
- triggered count。
- error count。
- skipped count。

## 8. 通知去重

通知 dedupe key 应包含：

- alert id。
- quote timestamp 或 price point。
- condition。

同一行情点重复扫描不能重复发送同一条通知。

## 9. 数据维护 wake

`data_maintenance` wake 至少携带：

- market。
- jobKind。
- cronRunId。

runner 分派到数据维护服务，返回维护摘要或失败 message。

维护作业不能直接伪造 provider 成功；失败应作为 maintenance failure 返回。

## 10. selection 数据刷新 wake

`selection_data_refresh` wake 触发 selection refresh executor。

要求：

- refresh 失败时返回 `SELECTION_DATA_REFRESH_FAILED`。
- 成功时返回 refresh payload。
- 不允许在 executor 未配置时吞掉请求。

## 11. 报告清理详细流程

报告清理：

1. 读取保留策略。
2. 扫描报告 run 目录和 saved report。
3. 排除正在发送/导出的报告。
4. 删除过期产物。
5. 写入清理结果。

清理设置包括 report retention days。重置设置必须恢复默认值。

## 12. 安全边界

- internal cron wake 需要内部 token。
- 业务 API 不应允许外部伪造 cron wake。
- 删除 job 失败时不能把本地记录标记为已完全同步。
- 手动 run 使用 idempotency key。

## 13. 错误分类

| 错误码/类别 | 含义 |
| --- | --- |
| `CRON_PROVISION_FAILED` | OpenClaw cron 创建失败 |
| `CRON_SYNC_FAILED` | cron 更新或删除失败 |
| `INVALID_INPUT` | wake 或用户输入缺字段 |
| `PRICE_ALERT_SCAN_FAILED` | 价格扫描失败 |
| `SELECTION_DATA_REFRESH_FAILED` | selection 数据刷新失败 |
| `DATA_MAINTENANCE_FAILED` | 数据维护失败 |
