# 数据网关模块详细设计

## 1. 文件结构

```text

  public_api.py
  models.py
  runtime.py
  report_evidence.py
  selection_api.py
  _selection_batch.py
  planner/
  coordination/
  execution/
  ingest/
  providers/
  official_catalog/
  warehouse/
  maintenance/
```

## 2. 关键文件职责

| 文件 | 职责 |
| --- | --- |
| `public_api.py` | 公开请求合同和 forbidden keys |
| `api.py` | `DataAPI` 对外入口，保持请求顺序 |
| `models.py` | DataRequest/DataResult/DataGap/provider capability |
| `planner/call_planner.py` | PublicDataRequest -> DataNeed / ProviderCallSpec |
| `coordination/scheduler.py` | deadline、priority、rate limit 调度 |
| `coordination/service.py` | 编排 plan、gate、fetch、ingest、merge |
| `execution/gate.py` | cache/cooldown/single-flight/rate-limit 闸门 |
| `execution/fetch_engine.py` | 调 provider plugin，统一 fetch status |
| `ingest/pipeline.py` | raw、normalized、attempt 写入 |
| `warehouse/warehouse.py` | normalized 仓库查询和 coverage 校验 |
| `runtime.py` | 从环境组装数据网关 runtime |
| `report_evidence.py` | 报告工具数据证据 payload |

## 3. 公开请求校验

`validate_public_request()` 必须：

- 接受业务语义字段。
- 规范 market、symbol、universe、date range。
- 拒绝 provider 执行字段。
- 失败时返回 error result，而不是抛出后让批次丢失顺序。

## 4. Planner 设计

Planner 产出：

- `NeedPlan`
- `DataNeed`
- `ProviderCallSpec`
- execution groups
- skipped needs
- merge evidence
- rate-limit evidence

执行组类型：

- fallback chain：高优先源失败后尝试后续源。
- composition group：多个源共同满足一个业务结果。

## 5. Scheduler 设计

Scheduler 使用：

- priority。
- deadline。
- provider rate limit policy。
- sliding window。
- budget。

无法在预算内执行时，生成 `rate_limited_by_tool_budget` gap 和 evidence。

## 6. Execution gate

Gate 决策：

- `cache_hit`
- `cached_empty`
- `rate_limited`
- `shared_result`
- `cooldown_skipped`
- `owner`

只有 `owner` 才实际抓取远端。

## 7. Fetch engine

Fetch engine 调 provider plugin，并统一为：

- success。
- empty。
- error。
- rate_limited。
- credential_missing。
- permission_denied。
- not_applicable。
- sdk_http_unknown。

不能把 provider empty 或 parser missing 写成 remote success。

## 8. Ingest pipeline

Ingest 保存：

- raw payload。
- normalized rows。
- provider attempt。
- dataset manifest。

只有真实 success 且证据写入成功，才能记录 remote success。

## 9. Warehouse recheck

Warehouse 校验：

- dataset 是否存在。
- fields 是否覆盖。
- date range 是否覆盖。
- freshness 是否满足。
- hash/integrity 是否通过。

Selection 和历史行情可从 columnar warehouse 读取。

## 10. Report evidence

`report_evidence.py` 为 `claw_request_data` 生成：

- model visible text。
- refs。
- data results。
- provider attempts 摘要。
- merge/rate-limit evidence。

它是数据证据摘要，不是 worker 报告正文。

## 11. Runtime 组装

`runtime.py` 从环境读取：

- MongoDB URI。
- seed MongoDB。
- provider credentials。
- columnar root。
- settings store。

未配置时应 fail closed 或返回明确配置缺失。

## 12. 已知限制

- provider 可用性依赖外部 API。
- `DATA_GATEWAY_MONGODB_URI` / `CN_A_MONGODB_URI` 未配置会影响 runtime。
- 本文不声明当前 provider live 可用。
- `report_evidence.py` 部分下划线函数被内部复用，不应写成长期公共 API。
