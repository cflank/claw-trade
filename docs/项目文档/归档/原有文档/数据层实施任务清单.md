# 数据层实施任务清单（当前有效口径）

本文只列当前有效任务。旧的 `历史候选选择器`、`历史请求合并器`、`历史批量规划器`、历史数据入口、历史数据桥接、启动前预取和旧 `DataAPI.get_data/get_data_batch` 任务已经废弃。

## P0 合同

- 公开工具只接受业务数据项、用途、标的、市场、时间范围、粒度、优先级和审计标签。
- DLT-14：最小闭环顺序必须先完成数据层模型、仓库、非远端状态、单 provider fetch、批量、后台维护和四市场合同；不得先实现 report 数据工具、select 控制面、UI display、OpenViking writer 或 truthfulness guard。
- 公开工具不得接受 provider、path、api_name、url、header、token、api_id、内部需求类型字段、fields、字段覆盖声明、source_role、worker/domain/report_section 硬编码限制。
- 数据层内部使用 `DataNeed -> ProviderCallSpec -> execution gate -> fetch -> parser -> ingest`。
- provider 候选不能按 worker、consumer、domain、report section 或 fields 硬编码限制否决。
- 同一业务数据项在 report/select/ui_probe/maintenance 下 provider 候选一致。
- source 级滑动窗口限流必须覆盖 structured provider 和 official raw call。
- single-flight 合并必须早于真实 HTTP 配额消耗。

## P1 任务

- 补齐四市场项目数据项到 provider API 的规划测试。
- 补齐关键 provider/parser 成功样本：A 股盘口、加密衍生品、宏观、事件日历、HK 财报和估值、US 宏观/公告。
- 清理旧历史数据入口入口和旧 候选选择逻辑 文档口径。
- 确认证据模型能表达：凭证缺失、权限失败、provider 空结果、parser 缺失、目录未命中、任务预算限流、SDK 内部 HTTP 风险。

## P2 任务

- 对 SDK 内部 HTTP provider 建风险清单，不能声称子请求级限流已完全可控。
- 为 public API catalog 生成快照和差异检查，避免接口目录无意缩水。
- 为 live/fresh 验证补四市场 collect-first 报告模板。
