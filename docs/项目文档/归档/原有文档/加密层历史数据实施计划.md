## 0. 口径冻结

本计划只执行 `docs/加密层历史数据设计.md` 的 Phase 1：

- Binance spot 当前 active USDT 交易对 `1d`、`1h` 历史包。

- `/report BTC`、`/report SOL` 优先命中本地 normalized warehouse。

当前执行状态：

- 已完成 BTCUSDT、ETHUSDT、SOLUSDT 的 2025-01 spot / USD-M `1d`、`1h` 样本下载、checksum 校验、清洗归一化和本地仓库证明；最终 normalized 写入机制已统一到列式仓库。
- 已完成 Binance 当前 active 交易对 URL manifest、实际下载、checksum 校验、清洗归一化和统一列式导入；原全 quote 混合批次已被当前 USDT-only 批次取代。
- 下载清理结果：当前原始包目录为 `data/crypto-history-full/binance/data`，只剩 USDT 包，32452 个 ZIP、32452 个 checksum、596 个 USDT symbol；非 USDT ZIP 为 0。该目录在项目 `data/` 下，不再放在 `.runtime` 下。
- 列式导入结果：库 `claw_trade_crypto_history_usdt_20260608`，最终 run `crypto-usdt-only-columnar-20260608` 写入 1922 个 import jobs、32452 个 raw payload metadata、2079 个 provider attempts、1921 个 active Parquet manifests；active Parquet rows 为 8001515 行。
- 当前代码结果：加密导入 CLI 已接入统一列式 normalized 写入路径；当前有效 USDT-only 历史批次在 `data/crypto-history-full/normalized-columnar-usdt-only`，Mongo 只保留 raw metadata、provider attempts、dataset manifests/catalog，`normalized_datasets` 为 0。大批量 lineage 已改为 count + sample + hash + prefix，不再把完整逐行 `dataset_refs` 重复写入 Mongo。
- 当前运行时隔离结果：出厂 seed Mongo catalog 只读挂载；live/runtime provider 增量、cache、rate-limit、single-flight 写运行时 Mongo 库。`scripts/start-control-runtime.sh` 已阻止把 `claw_trade_crypto_history_*` seed 库直接当运行时写库。
- 已完成 BTC/SOL 仓库接口级本地优先验收：`local_crypto_prepackaged / binance_public_data_import / local_seed_imported`，无远端 fallback。
- 已完成真实 `/report BTC` 和 `/report SOL` provider-payload 证明：当前项目内 USDT-only seed 仓库已按“运行时写库 + seed 只读库”重跑 live `/report`，BTCUSDT/SOLUSDT 现货日线 371 行、小时线 8904 行，覆盖 2025-06-01 至 2026-06-06，证据见 `docs/evidence/live-crypto-seed-overlay-20260608/summary.md`。

本计划不做：

- Binance `1m` 全量。
- trades / aggTrades / tick / order book 全量。
- COIN-M futures。
- 已下架交易对完整历史。
- Tardis、Kaiko、CoinAPI、Glassnode、Santiment、The Tie、LunarCrush 的采购或接入。
- OpenClaw runtime 修改。
- worker prompt 修改。
- runtime guard 或报告表达 gate。

架构边界：

- data_gateway 仍是数据入口、仓库和证据链所在层。
- importer 不写报告，不调用 OpenClaw，不替 worker 写分析。
- downloader 不写 Mongo。
- `/report` 可以在本地缺口已写入 evidence 后调用远端 provider 增量补数，但远端成功不能替代 Phase 1 的本地仓库验收。
- 本地完全无数据必须显式输出 `local_warehouse_empty`，不能静默 fallback。

## 1. 成功标准

当前拆成两层，避免把数据层完成误写成真实报告链路完成。

### 1.1 数据层完成标准（已完成）

- Binance 当前 active spot / USD-M perpetual USDT 交易对 `1d`、`1h` 已保留在当前有效本地包目录。
- 已保留并 checksum 校验 32452 个 USDT ZIP；非 USDT ZIP 已清理为 0。
- 当前有效历史批次已清洗归一化并写入统一列式 normalized 仓库：8001515 条 active Parquet normalized rows，32452 条 raw payload metadata，2079 条 provider attempts，1921 个 active Parquet manifests。
- 当前代码已接入列式 normalized 写入：normalized rows 写 Parquet，Mongo 保留 catalog/evidence，最终列式验证中 Mongo `normalized_datasets` 为 0。
- `BTCUSDT`、`ETHUSDT`、`SOLUSDT` spot 和 USD-M 的 `1d`、`1h` 覆盖 2025-06-01 至 2026-06-06，日期/小时缺口为 0。

- 本地仓库完全无数据时输出 `local_warehouse_empty`，并且 provider fallback 不能抹掉该缺口。
- normalized refs 沿用当前 `DatasetRepository` 的 `dataset:<dataset>:<market>:...` 口径，不写 legacy `normalized://mongo/...`。
- checksum 失败、CSV schema mismatch、timestamp 单位无法判断、replace-existing 未确认都 fail closed。

### 1.2 报告链路最终验收（已完成）

- `/report BTC` 和 `/report SOL` 真实路径生成 DataNeed 数据结果、provider payload 和证据链。

- `DataResult.gaps` 和 `freshness.coverage_by_request` 能解释 date range 覆盖。
- provider payload 和 worker L1 能看到本地 seed evidence，且不把 Binance 当前 active 交易对写成全球加密全市场。
- 数据结果仍如实记录其它未覆盖域，例如衍生品深度、链上、新闻、社交。

## 6. Mock / Stub / Fake / Fallback 检查

- 单元测试可以使用小型 fixture ZIP，但不得把 fixture 作为 live proof。
- live proof 必须使用真实下载文件、真实 checksum、真实 Mongo、真实 `/report` 路径。
- provider fallback 必须保留本地缺口证据。
- 缺失数据只能写 data gaps，不能生成假 completed data。
- 搜索源、新闻源、社交源不在 Phase 1 完成范围内，不能被本地行情 seed 成功掩盖。
