# 港股详细设计（当前有效口径）

本文已清理旧的历史数据入口设计。当前 HK 数据层与其它市场使用同一合同：worker 调统一数据工具，数据层内部完成接口匹配、限流、合并、调用、解析、入库和证据记录。

## 边界

- `claw-trade` 控制 workflow 和 worker 调度。
- OpenClaw 只执行单个 worker turn，并暴露当前 stage 允许的工具。
- HK worker 可见的数据工具名是 `claw_request_data`。
- Python 不替 worker 写分析结论，不在 worker prompt 里暴露 provider 执行细节。

## 数据流

1. worker 请求业务数据项。
2. 工具层校验公开 payload，拒绝 provider/path/api_name/token/fields/source_role/内部需求类型字段 等执行细节。
3. 数据层生成内部 `DataNeed`。
4. planner 根据项目数据项、市场、标的、粒度和接口目录生成 `ProviderCallSpec`。
5. 执行层按 source 级滑动窗口限流，并用 single-flight 合并同一真实请求。
6. provider/plugin 执行真实调用，parser 写标准行。
7. ingest 写 attempt、raw、normalized、cache 证据。
8. 工具返回自然语言数据结果摘要、refs 和缺口。

## HK 项目数据项

- 行情：日线、分时、实时价。
- 基本面：估值、财务指标、财报。
- 事件：公司新闻、宏观新闻、公告、事件日历、社交情绪。

## 明确废弃

- 历史数据入口。
- 默认远端预取。
- domain 历史数据入口。
- 候选选择逻辑。
- worker/domain/report section 硬编码限制。
- provider executor fallback。
- normalized 数据缓存作为远端请求来源。

## 验收

- HK provider payload 中模型只看到 `claw_request_data`。
- HK 数据项能规划到 provider API。
- HK 出网调用受 source 级滑动窗口限制。
- parser 成功时有标准行；失败时保留真实缺口和证据。
