# 设置模块首版设计

日期：2026-05-22

## 1. 目标

首版设置模块只解决一件事：让用户完成生成报告所需的最小配置。

它不是高级诊断页，也不是 OpenClaw 主界面的复制品。

## 2. 启动检查

项目启动后自动检查两类状态：

- 报告模型
- 微信通知

报告模型是硬前置。没有配置、没有测试通过、或测试失败时，直接进入模型配置表单，不能生成报告。

微信通知是启动引导，不是硬阻断。未配置时直接显示二维码和引导文案，用户可以跳过并进入浏览器工作台。

## 3. OpenClaw 引导项

OpenClaw 负责运行底座能力：

- 模型配置和模型测试
- 设备授权和 scope 处理
- 微信插件、二维码、登录状态和通道能力

普通 UI 不显示 OpenClaw 原始配置、scope 细节、gateway 地址、Channel ID、插件包名或配置路径。

OpenClaw 主界面入口放在聊天界面工具区，不放在设置页。

## 4. 模型设置

报告模型字段：

- 服务商
- 模型
- API key
- 接口地址

状态：

- 未配置
- 已保存未验证
- 测试失败
- 可用

规则：

- 测试通过前不能生成报告。
- 测试失败时显示可操作错误。
- 用户配置优先。
- 不允许测试失败后静默切换到默认模型。

Embedding 是可选项，用于语义检索。未配置或不可用时不阻断报告生成。

## 5. 微信通知

启动引导和设置页都直接展示二维码，不先放“扫码登录”二次按钮。

文案：

```text
请先在微信端启用插件：
我 → 设置 → 插件 → 微信 ClawBot

按微信端提示安装或启用后，返回本页扫描二维码完成连接。
```

操作：

- 刷新二维码
- 稍后设置
- 重新连接
- 解除连接

规则：

- 二维码必须来自真实 OpenClaw 通道。
- 不伪造登录成功。
- 未登录不阻断浏览器工作台。
- 不在 UI 写微信端报告指令用法。

## 6. 增强数据源

设置页只显示内置增强源或付费源。默认免费源隐藏。

字段：

- 名称
- API key
- 接口地址
- 启用开关
- 最近测试结果

规则：

- 启用前必须测试通过。
- 启用后只在系统批准范围内优先尝试。
- 运行时失败不阻断报告。
- 默认源可覆盖时继续生成报告。
- 失败 attempt 必须记录。

不支持：

- 任意 HTTP 数据源
- 自定义 JSON 映射
- 用户调整 provider 优先级
- 用户选择数据源适用范围

## 7. 任务卡片

用户输入标的后，系统自动识别并生成确认卡。

卡片字段：

```text
标的：600519.SH
名称：贵州茅台
市场：[A股 v]
```

用户可以：

- 确认生成报告
- 修改标的
- 切换市场

切换市场后，系统重新校验标的是否匹配。不匹配时提示用户修改标的或选择匹配项。

不显示：

- profile
- 默认币种
- 报告方案
- 计价单位
- worker / debate / risk 细节

## 8. UI 文案边界

普通 UI 不显示：

- profile
- 默认币种
- worker id
- provider attempt
- runtime 细节
- evidence 链路细节
- OpenClaw 内部 Channel ID
- OpenClaw 插件包名

任务卡片允许显示“市场”，因为这是用户确认和纠错所需字段。

## 9. 阻断规则

阻断报告生成：

- 报告模型未配置
- 报告模型未测试通过
- 报告模型测试失败

不阻断报告生成：

- Embedding 未配置
- 微信未登录
- 增强数据源运行失败但默认源可覆盖

## 10. 后续高级诊断

以下不进首版普通设置页，已放入 `todolist.md`：

- provider 健康
- runtime 服务状态
- 最近 live run 缺口
- 证据链失败原因
