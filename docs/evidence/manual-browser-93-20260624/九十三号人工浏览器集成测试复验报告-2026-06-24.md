# 93 号人工浏览器集成测试复验报告（2026-06-24）

## 测试对象

- 测试用例文档：`docs/项目文档/93-人工浏览器集成测试用例.md`
- 测试页面：`http://127.0.0.1:5175/`
- 测试方式：真实 Windows Chrome，通过 `playwright-win-chrome` MCP 操作页面。
- 自动化脚本和 subagent 只作为辅助证据；最终结论以真实 Chrome 看到的页面结果为准。

## 一、结论

这轮没有全部通过。

主要已经通过的部分：

- `/report AAPL` 可以在聊天里确认任务。
- 右侧任务栏能看到任务 `task-1`，能看到阶段和 worker 进度，最后能完成并进入历史。
- AAPL 报告详情页能看到正文、组合经理结论、图表状态和 PDF 状态。
- 报告里的 worker 聊天可以基于当前报告回答问题，没有误开新的 `/report`。
- `/select` 默认 A 股选股在后续复验记录中标为可返回候选结果；`/select US` 和 `/select 3` 已经给出明确提示，不再只是“回复失败”。
- `/select CRYPTO` 没有再出现“选股不可用”或“回复失败”。它进入了补数流程，但等待时间超过单次 MCP 请求限制，本轮没有拿到最终候选列表。
- `/sched` 和 `/alert` 可以通过聊天创建任务。右侧任务栏能看到定时报表和价格提醒管理入口。
- 价格提醒可以暂停、恢复、立即检查。
- 高级诊断页能看到维护类任务明细。
- API 404、未知 API、静态 404、SPA 回退行为符合预期。

主要没有通过或没有完整验证的部分：

- TC-04B 没通过。AAPL 报告详情页和高级诊断页没有提供“每个 worker 的运行证据入口”，也就是看不到 provider payload、tool schema、approved material、receipt、manifest 等证据。
- TC-05 只验证到停止按钮和确认弹窗。MCP 原生确认弹窗两次都卡住，没有拿到取消后的页面状态。
- TC-10、TC-12、TC-12B、TC-17 涉及微信真实转发、外部入站消息、删除报告、真实 PDF 保存或下载。本轮是无人值守测试，没有执行这些会影响外部渠道或已有数据的成功路径。
- TC-19A 没通过。页面上看不到 provider attempts、raw/normalized store、manifest、数据缺口、图表证据等运行证据入口。
- 额外补测发现一个后端单测失败：worker 聊天的一个旧单测还在期待旧调试标记，实际返回的是中文 worker 聊天提示。

## 七、最终判断

本轮复验结果是：部分通过，不是全部通过。

已经能证明的用户主流程包括：打开页面、创建 AAPL 报告、查看报告详情、worker 聊天、默认选股、定时报表创建、价格提醒创建和管理、高级诊断、未知 API 错误处理。

还不能算通过的部分集中在三类：

1. 运行证据入口不足：TC-04B 和 TC-19A 要求 UI 能看到底层运行证据，本轮没有看到。
2. 无人值守下不能安全执行的外部或破坏性动作：微信转发、外部入站、删除报告、真实 PDF 保存或下载。
3. 停止任务只验证到入口和确认弹窗，没有拿到停止后的最终状态。

因此，这份报告不能写“93 号文档全部通过”。准确说法是：核心用户主流程大多可用，但运行证据、外部渠道、破坏性操作和部分长链路验证还没有完整通过。
