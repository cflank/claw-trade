## 总结

- 总体原因：CN 原图节点更接近 TradingAgents-CN 的 analyst/tool loop，输出偏短；claw 通过 OpenClaw worker、资料包和 approved L1 边界运行，报告会吸收更多工具证据和格式约束。
- 本报告只比较 Markdown 归档证据；runtime JSON、provider 原始包和日志没有进入 `docs/evidence`。

### Prompt 差异解释

- CN final prompt 来自 TradingAgents-CN 原生 LangChain/LangGraph 调用边界，保留该项目的系统消息、工具绑定和节点输入形态。
- claw final prompt 来自 OpenClaw provider payload，worker 身份、prompt profile、stage policy、工具可见性和上游 approved L1 材料都由本项目控制面组织。
- 因此 prompt 不应只看模板句是否相同，还要看模型实际看到的上游材料体量、工具 schema 和提交边界是否改变。

### LLM Back 差异解释

- CN LLM back 是原生节点调用返回内容；遇到 tool-call 型节点时，第一轮返回可能是工具调用意图而不是最终自然语言报告。
- claw LLM back 本次按 approved L1 正文口径归档，代表项目 hard gate 后进入材料链的 worker 输出。
- 如果本层和 report 完全一致，说明该 worker 的返回正文直接成为报告；如果不一致，应优先以 report 观察最终可传递材料。
