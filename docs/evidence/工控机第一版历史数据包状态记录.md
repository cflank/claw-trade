## 交付原则

- 历史数据包必须独立于程序包和 Virbox 保护包交付。
- 历史数据包必须白名单导出，不能整库 dump 后再删除敏感字段。
- 历史数据包必须带 manifest 和 checksum 或签名。
- 首次安装时只能在空库或首次初始化时导入，不得覆盖客户 API KEY、授权状态、报告、日志、用户配置或运行期数据。

## 第一版数据范围

- A 股：`daily_bar`、`valuation_metric`，最近 300 个交易日。
- A 股实际覆盖：2025-03-03 到 2026-05-27。
- A 股实际行数：`daily_bar` 1,626,559 行；`valuation_metric` 1,626,559 行。
- CRYPTO：USDT-only，596 个 symbol。
- CRYPTO 实际覆盖：2025-06-01 到 2026-06-06。
- CRYPTO 实际行数：`daily_bar` 355,791 行；1h `intraday_bar` 8,536,045 行。
- US/HK：默认联网刷新，不预置历史 seed；如厂家测试要求，再单独制作白名单 seed。

## 禁止项

历史数据包不得包含：

- API KEY、token、secret、password、cookie、session、OAuth 凭证；
- 授权码、Virbox 授权缓存、设备指纹原始值；
- 用户配置、用户登录信息、报告、日志、诊断包；
- 开发运行库 `claw_trade`；
- UI settings / UI secrets；
- provider result cache；
- 未经白名单批准的 collection、table 或字段。
