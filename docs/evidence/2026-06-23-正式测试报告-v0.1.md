## 4. 逐项测试结论

### 4.1 报告主链路

#### 4.1.1 `/report` 创建与执行

结果：部分通过

已验证：

- 可以通过 `/report` 发起正式报告请求
- 报告可进入运行或排队
- 已存在真实完成报告可进入历史和详情
- 四市场解析真实可见：
  - `600519.SH` 解析为 `CN_A / 贵州茅台`
  - `AAPL` 解析为 `US`
  - `00700.HK` 解析为 `HK`
  - `BTCUSDT` 解析为 `BTC/USDT / Bitcoin / CRYPTO`

未完整验证：

- 全市场、全失败态、全配置缺失态矩阵
- 失败态文案分类

#### 4.1.2 报告取消

结果：通过

真实结果：

- `/report 600519.SH` 运行中出现“停止任务”
- 点击后返回 `0 运行中 · 0 排队中`

结论：

- 基本取消能力存在

缺口：

- 未完成取消后审计记录保留的完整页面取证

### 4.2 selection 主链路

## 5. 明确缺陷列表

### BUG-02 渠道转发真实发送失败，UI 卡在“发送中”

严重性：中

复现：

1. Chrome 打开正式报告历史
2. 点击任一报告的“转发”
3. 等待外发完成

实际结果：

- UI 按钮状态变为 `发送中`
- 12 秒后仍未恢复
- 网关日志记录真实失败：
  - `send ... errorCode=UNAVAILABLE`
  - `CDN upload server error: status 500`

预期结果：

- 成功发送并回到稳定成功状态，或
- 明确向用户展示失败原因并结束 `发送中`

影响：

- 真实渠道发送链路当前不可用
- UI 会把用户卡在持续 `发送中` 的错误状态
