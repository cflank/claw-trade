# claw-trade 交付包制作流程

这份文档讲三件事：

```text
1. 第一次给厂家装机用的交付包怎么做。
2. 后续远程升级包怎么做。
3. 以前在新 Ubuntu 机器上怎么安装和验证。
```

先把概念分清楚：

```text
交付包：第一次给厂家或新工控机安装用。通常通过 scp 传到目标机，然后执行安装脚本。
升级包：已经装过 claw-trade 的机器后续在线升级用。它要有签名、manifest，并上传到七牛 stable/。
Virbox 保护包：在普通生产包基础上，把运行入口做 Virbox 保护后的交付包。
```

普通生产包不是 Virbox 加壳包。它里面的 claw-trade Python 代码会编译成 `.pyc`，不是 `.py` 明文，但这不等于正式加密。要防厂家直接复制破解，交付给厂家前要做 Virbox 保护。

## 1. 发布机准备

在发布机进入仓库：

```bash
cd /home/frank/src/claw-trade
```

看当前代码状态：

```bash
git status
```

确认三件事：

```text
1. 当前代码就是要交付的版本。
2. 前端已经能正常构建。
3. 生产包需要的数据种子已经放在 data/ 目录。
```

生产包脚本会优先带上：

```text
data/current-seed-*.tar
```

如果没有这个文件，才会退回带上老的：

```text
data/a-share-cn-required-300td-20260608.tar
```

所以，如果要把最新历史数据放进包里，先确认最新数据种子文件存在：

```bash
ls -lh data/current-seed-*.tar
```

如果这里没有文件，说明当前包不会带最新种子数据。

## 2. 制作普通生产包

执行：

```bash
scripts/production/build_production_package.sh
```

这个脚本会做这些事：

```text
1. 构建前端页面。
2. 复制 agents、openclaw_plugins、OpenClaw 运行文件。
3. 复制 Python 运行环境和依赖。
4. 把 src/claw_trade 编译成 .pyc，放进 app/python/claw_trade。
5. 复制数据种子。
6. 复制本地 MongoDB 运行时，如果 .runtime/mongodb/current 存在。
7. 执行生产包检查。
8. 生成 tar.gz 和 sha256。
```

成功后会生成类似：

```text
dist/production/claw-trade-production-0.1.4-20260628T171737Z.tar.gz
dist/production/claw-trade-production-0.1.4-20260628T171737Z.tar.gz.sha256
```

包名里的版本号来自：

```text
pyproject.toml
```

包名里的时间是构建时间。

检查包是否合格：

```bash
python3.12 scripts/production/validate_production_archive.py dist/production/claw-trade-production-版本-时间.tar.gz
python3.12 scripts/production/audit_production_package.py dist/production/claw-trade-production-版本-时间.tar.gz
```

这一步通过，只能说明普通生产包结构没问题。它还不是 Virbox 正式保护包。

## 3. 制作 Virbox 保护交付包

当前推荐方式是：

```text
先用 Linux 构建普通生产包。
再在 Win11 Virbox 开发者工具里保护 Linux Python 解释器。
然后把保护后的 python 放回生产包。
最后重新打包、检查、交付。
```

### 3.1 解开普通生产包

创建一个临时目录：

```bash
mkdir -p .runtime/virbox-delivery-work
```

解开普通生产包：

```bash
tar -xzf dist/production/claw-trade-production-版本-时间.tar.gz -C .runtime/virbox-delivery-work
```

进入解开的 release 目录：

```bash
cd .runtime/virbox-delivery-work/claw-trade-production-版本-时间
```

确认包里有 Python 运行入口：

```bash
ls -l runtime/python/bin/python
```

### 3.2 把 Linux Python 复制到 Win11

回到仓库根目录：

```bash
cd /home/frank/src/claw-trade
```

创建 Win11 中转目录：

```bash
mkdir -p /mnt/d/claw-trade-virbox/python-for-virbox
```

复制要保护的 Linux Python：

```bash
cp .runtime/virbox-delivery-work/claw-trade-production-版本-时间/runtime/python/bin/python /mnt/d/claw-trade-virbox/python-for-virbox/python
```

在 Win11 里看到的路径是：

```text
D:\claw-trade-virbox\python-for-virbox\python
```

### 3.3 在 Win11 Virbox 开发者工具保护 python

打开 Win11 的 Virbox 开发者工具。

选择要保护的文件：

```text
D:\claw-trade-virbox\python-for-virbox\python
```

输出目录使用：

```text
D:\claw-trade-virbox\python-for-virbox\protected
```

保护成功后，应看到：

```text
D:\claw-trade-virbox\python-for-virbox\protected\python
```

如果工具显示的是试用保护，交付前要注意：试用保护有天数限制，不能当正式量产包。

### 3.4 把保护后的 python 放回生产包

在 WSL 仓库根目录执行：

```bash
cd /home/frank/src/claw-trade
```

替换包里的 python：

```bash
cp /mnt/d/claw-trade-virbox/python-for-virbox/protected/python .runtime/virbox-delivery-work/claw-trade-production-版本-时间/runtime/python/bin/python
chmod 0755 .runtime/virbox-delivery-work/claw-trade-production-版本-时间/runtime/python/bin/python
```

验证保护后的 python 能启动：

```bash
.runtime/virbox-delivery-work/claw-trade-production-版本-时间/runtime/python/bin/python --version
```

验证它能导入 claw-trade：

```bash
PYTHONPATH=".runtime/virbox-delivery-work/claw-trade-production-版本-时间/app/python:.runtime/virbox-delivery-work/claw-trade-production-版本-时间/runtime/python-site-packages" \
  .runtime/virbox-delivery-work/claw-trade-production-版本-时间/runtime/python/bin/python \
  -c 'import claw_trade; from claw_trade.web import app; print("ok")'
```

看到 `ok`，说明保护后的 python 至少能加载项目。

### 3.5 重新打成正式交付包

不要随便改包内顶层目录名。安装脚本和升级校验要求它保持这种格式：

```text
claw-trade-production-版本-时间
```

重新打包：

```bash
cd /home/frank/src/claw-trade
tar --dereference --hard-dereference \
  -C .runtime/virbox-delivery-work \
  -czf dist/production/claw-trade-production-版本-时间.tar.gz \
  claw-trade-production-版本-时间
```

重新生成 sha256：

```bash
cd dist/production
sha256sum claw-trade-production-版本-时间.tar.gz > claw-trade-production-版本-时间.tar.gz.sha256
cd /home/frank/src/claw-trade
```

重新检查：

```bash
python3.12 scripts/production/validate_production_archive.py dist/production/claw-trade-production-版本-时间.tar.gz
python3.12 scripts/production/audit_production_package.py dist/production/claw-trade-production-版本-时间.tar.gz
```

这时得到的 `tar.gz` 才是可以给厂家测试的 Virbox 保护交付包。

## 4. 制作远程升级包

远程升级包本质上还是同一个生产包，但多了：

```text
1. 包签名。
2. manifest.json。
3. manifest.json 签名。
4. 上传到七牛 stable/。
```

先准备生产包：

```bash
scripts/production/build_production_package.sh
```

如果这个版本要做 Virbox 保护，先按上面的第 3 节替换保护后的 python，再继续下面步骤。

### 4.1 给生产包签名

发布私钥只放发布机，不要放目标工控机。

签名：

```bash
openssl pkeyutl -sign \
  -inkey update-signing-private.pem \
  -rawin \
  -in dist/production/claw-trade-production-版本-时间.tar.gz \
  -out dist/production/claw-trade-production-版本-时间.tar.gz.sig
```

### 4.2 生成 manifest.json

创建 `manifest.json`：

```json
{
  "product": "claw-trade",
  "channel": "stable",
  "version": "0.1.4",
  "arch": "linux-x86_64",
  "archive": "claw-trade-production-0.1.4-20260628T171737Z.tar.gz",
  "sha256": "这里填生产包 sha256",
  "created_at": "2026-06-28T17:17:37Z",
  "min_current_version": "0.1.0",
  "notes": "release note"
}
```

填 `sha256`：

```bash
sha256sum dist/production/claw-trade-production-版本-时间.tar.gz
```

注意：

```text
archive 只写文件名，不写路径。
version 必须高于目标机当前版本。
sha256 必须和最终上传的 tar.gz 一致。
```

### 4.3 给 manifest 签名

```bash
openssl pkeyutl -sign \
  -inkey update-signing-private.pem \
  -rawin \
  -in manifest.json \
  -out manifest.json.sig
```

最终有 4 个升级文件：

```text
claw-trade-production-版本-时间.tar.gz
claw-trade-production-版本-时间.tar.gz.sig
manifest.json
manifest.json.sig
```

### 4.4 上传到七牛

上传到七牛对象存储：

```text
stable/claw-trade-production-版本-时间.tar.gz
stable/claw-trade-production-版本-时间.tar.gz.sig
stable/manifest.json
stable/manifest.json.sig
```

上传顺序必须是：

```text
1. 先传 tar.gz。
2. 再传 tar.gz.sig。
3. 再传 manifest.json。
4. 最后传 manifest.json.sig。
```

不要先传 `manifest.json`。否则目标机可能看到新版本，但包还没传完。

上传后刷新七牛 CDN：

```text
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json.sig
http://thaef8z8g.hn-bkt.clouddn.com/stable/claw-trade-production-版本-时间.tar.gz
http://thaef8z8g.hn-bkt.clouddn.com/stable/claw-trade-production-版本-时间.tar.gz.sig
```

刷新后打开：

```text
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json
```

确认显示的是新版本。

## 5. 新 Ubuntu 机器首次安装

假设目标机信息是：

```text
IP：192.168.1.21
用户：frank
密码：目标机自己的登录密码
```

每台机器准备一个单独授权文件：

```text
license.key
```

文件内容只放这一台机器要用的授权码，例如：

```text
NWFY-XXXX-XXXX-XXXX
```

注意：

```text
license.key 不放进软件包。
license.key 不提交 git。
license.key 不给多台机器共用。
一台机器一个 license.key。
```

### 5.1 从发布机把文件传到目标机

在发布机执行：

```bash
scp dist/production/claw-trade-production-版本-时间.tar.gz frank@192.168.1.21:/tmp/
scp scripts/production/install_factory_test_ubuntu.sh frank@192.168.1.21:/tmp/
scp scripts/production/uninstall_factory_test_ubuntu.sh frank@192.168.1.21:/tmp/
scp scripts/production/validate_production_archive.py frank@192.168.1.21:/tmp/
scp license.key frank@192.168.1.21:/tmp/license.key
```

如果第一次连接提示：

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入：

```text
yes
```

这只是 SSH 记录这台机器的指纹，不是报错。

### 5.2 登录目标机

```bash
ssh frank@192.168.1.21
```

### 5.3 执行一键安装

在目标机执行：

```bash
sudo bash /tmp/install_factory_test_ubuntu.sh \
  /tmp/claw-trade-production-版本-时间.tar.gz \
  --license-key-file /tmp/license.key
```

安装脚本会做这些事：

```text
1. 安装系统依赖。
2. 创建 /opt/claw-trade。
3. 解压生产包到 /opt/claw-trade/releases/。
4. 把 /opt/claw-trade/current 指向当前版本。
5. 创建 /opt/claw-trade/shared/。
6. 安装 Virbox 状态检查配置。
7. 读取 /tmp/license.key。
8. 调用本机 Virbox 服务绑定授权码。
9. 启动 control runtime。
10. 恢复包内自带的数据种子。
11. 启动 UI。
12. 检查 http://127.0.0.1:5175/ 是否能打开。
```

成功时会看到类似：

```text
[OK] claw-trade installed
UI: http://127.0.0.1:5175/
Log: /tmp/claw-trade-ui.log
Control log: /tmp/claw-trade-control.log
```

### 5.4 验证本机访问

在目标机执行：

```bash
curl -fsS http://127.0.0.1:5175/ | head
```

能返回 HTML 内容，说明目标机本机 UI 正常。

### 5.5 验证局域网访问

在 Win11 浏览器打开：

```text
http://192.168.1.21:5175/
```

能打开页面，说明厂家局域网访问正常。

如果浏览器打不开，先在目标机检查：

```bash
curl -fsS http://127.0.0.1:5175/ | head
ss -ltnp | grep 5175
tail -n 120 /tmp/claw-trade-ui.log
tail -n 120 /tmp/claw-trade-control.log
```

## 6. 目标机绑定 Virbox 授权码

厂家机器必须在目标机上绑定授权。不能在发布机上绑定后拿去另一台机器用。

原因很简单：

```text
一机一码绑定的是目标机器指纹。
换机器就要重新激活、转移或重新发码。
```

量产模拟流程使用 `license.key` 自动绑定，不让厂家手动打开页面。

标准安装命令是：

```bash
sudo bash /tmp/install_factory_test_ubuntu.sh \
  /tmp/claw-trade-production-版本-时间.tar.gz \
  --license-key-file /tmp/license.key
```

脚本会读取：

```text
/tmp/license.key
```

然后调用目标机本机 Virbox 服务：

```text
http://127.0.0.1:12339
```

完成授权码绑定。

如果自动绑定失败，再用页面手工排查。

如果目标机能直接打开 Virbox LCC 页面，就打开：

```text
http://192.168.1.21:12339/#/license
```

如果 Win11 打不开这个地址，但目标机本机服务正常，用 SSH 转发：

```bash
ssh -L 12339:127.0.0.1:12339 frank@192.168.1.21
```

然后在 Win11 浏览器打开：

```text
http://127.0.0.1:12339/#/license
```

在页面里添加授权码，完成绑定。

绑定后再打开 claw-trade：

```text
http://192.168.1.21:5175/
```

确认授权状态正常。

## 7. 目标机配置远程升级

首次安装后，如果这台机器以后要从七牛升级，目标机还要配置升级源和公钥。

先在发布机把升级公钥传到目标机：

```bash
scp update-signing-public.pem frank@192.168.1.21:/tmp/
```

在目标机执行：

```bash
sudo mkdir -p /opt/claw-trade/shared/config
sudo tee -a /opt/claw-trade/shared/config/claw-trade.env >/dev/null <<'EOF'
CLAW_TRADE_UPDATE_BASE_URL=http://thaef8z8g.hn-bkt.clouddn.com/stable/
CLAW_TRADE_AUTO_UPDATE_INSTALL=1
EOF
```

安装升级公钥：

```bash
sudo install -d -m 0755 /etc/claw-trade
sudo install -m 0644 /tmp/update-signing-public.pem /etc/claw-trade/update-signing-public.pem
```

重启服务：

```bash
sudo systemctl restart claw-trade-control.service claw-trade-ui.service
```

如果测试安装没有 systemd 服务，就先重启安装脚本启动的进程，或者重跑安装脚本。

在页面里操作：

```text
设置 -> 远程更新 -> 检查更新 -> 安装更新
```

## 8. 卸载

只卸载程序，保留 shared 数据：

```bash
sudo bash /tmp/uninstall_factory_test_ubuntu.sh
```

卸载程序，并清空 shared 数据：

```bash
sudo bash /tmp/uninstall_factory_test_ubuntu.sh --purge-shared
```

`--purge-shared` 会删除应用共享数据，包括缓存、报告、运行状态等。不要在客户机器上随便执行。

## 9. 最终交付给厂家前检查

交付前至少确认：

```text
1. tar.gz 能通过 validate_production_archive.py。
2. tar.gz 能通过 audit_production_package.py。
3. 包里有 runtime/python/bin/python。
4. 如果是 Virbox 保护包，runtime/python/bin/python 已经是保护后的文件。
5. 包里有需要的数据种子。
6. 每台机器有自己的 license.key。
7. 新 Ubuntu 机器能通过 --license-key-file 一键安装并自动绑定授权码。
8. http://127.0.0.1:5175/ 返回正常。
9. http://目标机IP:5175/ 能从 Win11 打开。
10. Virbox 授权码已经在目标机绑定成功。
11. 测试账号和授权有效期符合本次交付要求。
```

## 10. 常见错误

### 只创建了目录，没有真正安装 release

现象：

```text
/opt/claw-trade/current 不存在
/opt/claw-trade/releases 是空的
浏览器打不开
curl 127.0.0.1:5175 失败
```

处理：

```bash
sudo bash /tmp/install_factory_test_ubuntu.sh /tmp/claw-trade-production-版本-时间.tar.gz
```

不要只手工创建 `/opt/claw-trade` 目录。

### 包能装，但 UI 起不来

检查：

```bash
tail -n 120 /tmp/claw-trade-ui.log
tail -n 120 /tmp/claw-trade-control.log
```

再检查端口：

```bash
ss -ltnp | grep 5175
```

### Virbox 授权在一台机器成功，另一台机器不能用

这是正常的。

授权码软锁会绑定机器指纹。目标机不同，就要在目标机上重新激活，或者按 Virbox 的转移流程处理。

### 远程升级提示公钥不存在

检查：

```bash
ls -l /etc/claw-trade/update-signing-public.pem
```

### 七牛已经上传，但目标机还是旧版本

先刷新 CDN，再打开：

```text
http://thaef8z8g.hn-bkt.clouddn.com/stable/manifest.json
```

确认看到的是新 `version` 和新 `archive`。

### 升级包校验失败

通常是下面之一：

```text
1. manifest 里的 sha256 不是最终 tar.gz 的 sha256。
2. tar.gz 签名对应的不是最终 tar.gz。
3. manifest.json 改过后没有重新签名。
4. archive 文件名写错。
5. 包名或顶层目录名不符合 claw-trade-production-版本-时间。
```

处理方式：

```text
重新计算 sha256。
重新签 tar.gz。
重新签 manifest.json。
重新上传 4 个文件。
重新刷新 CDN。
```
