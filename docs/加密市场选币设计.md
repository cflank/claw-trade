# 加密市场选币设计

状态：已批准设计
日期：2026-06-17

## 1. 目标

在现有 `/select` 选股流程里增加加密市场入口，复用已经完成的加密历史列式仓库。不要重写下载器，不要新增第二套 selection workflow，不要把 worker 决策权移到 Python。

最小完整链路：

```text
/select 2 或 /select CRYPTO
  -> 读取现有加密历史列式仓库
  -> 构建确定性加密特征行
  -> 用批准后的加密策略选 top 20
  -> 写 approved candidate cache
  -> 运行现有 selection workers
  -> 等用户确认后再进入 /report
```

## 2. 命令合同

`/select` 默认仍然是 A股。

支持命令：

- `/select` -> `CN_A`
- `/select 1` -> `CN_A`
- `/select CN_A`、`/select A`、`/select A股` -> `CN_A`
- `/select 2` -> `CRYPTO`
- `/select CRYPTO`、`/select crypto`、`/select 加密` -> `CRYPTO`

刷新仍然显式触发：

- `/select refresh`
- `/select 1 refresh`
- `/select 2 refresh`
- `/select CRYPTO refresh`

不支持裸 `select 1` 和 `select 2`。产品入口保持 slash command，避免普通聊天误触发 selection workflow。

## 3. 已确认事实

加密历史数据层已经完成，本设计只复用它。

当前有效口径：

- 历史行情行在列式仓库：`data/crypto-history-full/normalized-columnar-usdt-only`
- 列式存储格式是 Parquet。
- Mongo 库 `claw_trade_crypto_history_usdt_20260608` 只是 seed catalog / evidence / attempt / manifest 存储。
- Mongo `normalized_datasets` 为 0；历史 normalized rows 不在 Mongo 里。
- provider lineage 是 `local_crypto_prepackaged`。
- Binance public-data 导入 endpoint 是 `binance_public_data_import`。
- 当前 seed 是 USDT-only、columnar-first。
- `/report BTC` 和 `/report SOL` 已通过 seed overlay 读到当前列式 seed 数据。

因此，文档和实现都不能说“历史数据在 Mongo 下”。准确说法是：历史行情数据在 Parquet 列式仓库里，Mongo 保存只读 seed catalog 和证据索引。

## 4. 架构边界

保持现有边界：

- `claw-trade` 控制命令解析、workflow state、确定性 selection data job、candidate cache、dispatch 顺序和 report handoff。
- OpenClaw 只运行单个 worker turn。
- selection workers 只评审 approved top 20 candidate cache。
- Python 不写投资理由，不写最终 selection 决策。

复用现有模块：

- `SelectionController`
- `SelectionDataJob`
- candidate cache 构建和批准流程
- 固定 selection worker dispatch 顺序

加密历史行情读取必须走 data gateway seed overlay：

- 运行时写入留在 runtime Mongo 库和 runtime columnar root。
- seed catalog 通过 `DATA_GATEWAY_SEED_MONGODB_DATABASE=claw_trade_crypto_history_usdt_20260608` 或等价测试 fixture 只读挂载。
- runtime 不能把 `DATA_GATEWAY_COLUMNAR_ROOT` 指向 `data/crypto-history-full/normalized-columnar-usdt-only`。
- `SelectionColumnarWarehouse` 只可用于 selection feature/cache 层，不能作为加密 seed 历史行情来源。
- `/select` 期间不得写 factory seed Mongo catalog，也不得写 factory seed Parquet 文件。

## 5. 数据流

`CN_A` 保持现有行为不变。

`CRYPTO` 流程：

1. 解析为 `SelectionMarket.CRYPTO` / `SelectionProfile.CRYPTO`。
2. 构建 supported CRYPTO selection data plan，替换当前 `target_design / mongo_missing` 旧路径。
3. 通过只读 seed overlay 读取 spot USDT 日线。
4. 从日线构建每个交易对的特征行。
5. 运行 `crypto.selection_strategy.v1`。
6. 构建并批准 candidate cache。
7. 让现有 selection workers 评审 top 20。

## 6. 加密特征范围

第一版只用 spot USDT 日线可推导字段：

- 最新 open / high / low / close / volume / amount
- 20 / 60 / 120 日收益
- 基于 20 / 60 / 120 日收益的 RPS
- 成交量比率
- 波动率或区间振幅
- 最大回撤或近期最差日收益
- 基于 quote volume 的流动性分数
- 历史不足导致的数据缺口扣分

不得使用 A股专属字段：

- 涨停 / 跌停
- 定增
- PE / PB / ROE
- A股交易所规则
- 直接复制 A股成交额阈值

## 7. 加密策略

新增 `crypto.selection_strategy.v1`。

第一版策略保持简单：

- 硬过滤：历史长度足够，quote volume 达到最低流动性要求。
- 趋势：20 / 60 / 120 日收益为正，或价格接近滚动高点。
- 相对强度：在加密 universe 里的 RPS 靠前。
- 波动：惩罚极端回撤或不稳定行情。
- 流动性：优先高且稳定的 quote volume。

输出仍是 top 20 candidate cache。它不是买入清单，也不是自动交易信号。

## 8. 错误处理

加密 seed 证据缺失或不可读时 fail closed。

预期失败状态：

- seed catalog 不可用
- seed Parquet 文件缺失或损坏
- 无 spot USDT 日线
- 全部 symbol 历史不足
- strategy config 缺失或不匹配
- candidate cache 完整性失败

当列式 seed 仓库可读时，旧的 `crypto_select_history_missing` 不能再触发。若仓库不可读，错误必须说明具体是 seed catalog、Parquet 文件、spot USDT 行或历史覆盖问题。

## 9. 测试要求

最小测试集：

1. 命令解析：
   - `/select` -> `CN_A`
   - `/select 1` -> `CN_A`
   - `/select 2` -> `CRYPTO`
   - `/select CRYPTO refresh` -> `CRYPTO` 且 `force_refresh=True`

2. 数据计划：
   - CRYPTO supported path 不再返回 `target_design / mongo_missing`。

3. 数据作业：
   - 使用小型 CRYPTO 日线 fixture，`SelectionDataJob` 能生成 approved candidate cache。
   - 不要求 A股专属策略字段。
   - fixture 必须证明 `return_20d`、`return_60d`、`return_120d`、`rps20`、`rps60`、`rps120` 由 spot USDT 日线派生。
   - 测试不能靠预填 strategy signals 或预填 RPS 字段假通过。

4. candidate cache：
   - CRYPTO cache 包含 CRYPTO market/profile 和 source lineage。
   - candidate cache body、summary、manifest、data-job evidence 包含 `crypto.selection_strategy.v1`。
   - candidate cache body、summary、manifest、data-job evidence 不含 `cn_a.selection_strategy.v1`、`cn_a.selection_weights.v1`、`myhhub/stock`、`Sequoia-X`、`limit_up`、`limit_down`、`private_placement`、`涨停`、`跌停`、`定增`。
   - 估值字段不得作为独立 JSON key、独立 token、标签或策略字段出现：`pe`、`pb`、`roe`、`PE`、`PB`、`ROE`、`市盈率`、`市净率`、`净资产收益率`。
   - 不要做 substring scan；`open`、`type`、`scope` 等正常字段允许出现。

5. 命令流程：
   - `/select 2` 的 request evidence 是 CRYPTO。
   - 如果没有 CRYPTO candidate cache，响应必须是具体的数据或缓存不可用信息，不能伪装完成。

6. 完整命令合同：
   - `/select`、`/select 1`、`/select CN_A`、`/select A`、`/select A股` 解析为 `CN_A`。
   - `/select 2`、`/select CRYPTO`、`/select crypto`、`/select 加密` 解析为 `CRYPTO`。
   - `/select 1 refresh` 和 `/select 2 refresh` 保留对应 market，并设置 `force_refresh=True`。
   - 裸 `select 1` 和 `select 2` 不启动 selection。

7. 替换旧断言：
   - 删除或改写仍断言 CRYPTO 是 `target_design / mongo_missing` 的测试。
   - 新负例覆盖 seed catalog missing、Parquet 文件 missing、无 spot USDT rows、历史不足。
   - 负例返回具体 seed/catalog/columnar 原因，不返回旧 blanket `mongo_missing`。

## 11. 停止条件

如果实现需要以下动作，停止并询问：

- Python 编造 CRYPTO candidate 投资理由。
- 把 A股策略阈值套到 CRYPTO。
- 运行时写入 seed catalog 或 seed Parquet。
- 新增 guard 或 hard gate。
- 把 selection worker 逻辑搬进 Python。
- 绕过 candidate cache approval。
