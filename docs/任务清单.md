目标：补齐文本情绪来源，或明确只做热度报告。

任务：

- `T-TST-003`：fresh 验收脚本已实现，真实 fresh run 仍待执行。

验收：

- 有文本时可写情绪。
- 无文本时只写热度。
- 不编造社交结论。

### P5：Fundamental EPS / 估值口径

目标：避免目标价混算。

任务：

- 在 data pack 中保留 EPS 与 TTM EPS 口径。
- 在 reader brief 中说明估值字段来源和日期。
- fundamental report 使用一致口径。

验收：

- PE/PB/ROE 有来源。
- 目标价框架引用口径一致。
- 缺字段时报告缺口，不补假数。

### P6：Guard 收敛

目标：guard 只防造假，不压扁报告；prompt 不再把真实性红线扩展成审慎、合规、memo 化或禁止强观点/交易建议的风格系统。

任务：

- 检查 hard gate 是否仍存在“报告语气误杀”。
- 删除重复 prompt 约束。
- 保留 claim/source/tool/receipt/PM 最终裁决权边界。
- 删除或改写所有没有原版依据的表达层禁令，包括禁止 final proposition、禁止证据支持的 BUY/HOLD/SELL、默认 limitation report、过度审慎、过度合规、memo 化语气。
- 为 bull/bear/risk/research manager/PM 增加 prompt 风格合同：保留原版强观点辩论室和自然语言决策风格，同时继续拦截编造事实。

验收：

- analyst 可以有观点。
- PM 仍是最终结论 owner。
- fake/fallback 仍 hard fail。
- evidence-supported final proposition、交易条件、目标情景、风险判断、直接反驳不会被 prompt 或 guard 禁掉。
- 对比报告必须明确区分“真实性增强”与“原版风格漂移”，不得把前者当作后者的借口。

## 5. 停止条件

停止并问人类：

- GitHub push 远端不明确。
- 需要 force push。
- OpenClaw 子模块提交未推送但主仓库要引用它。
