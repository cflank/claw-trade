# UI 需求分析

## 1. 目标定位

本项目 UI 的定位是面向普通用户的极简投研产品，而不是 OpenClaw 控制台。

核心目标：

- 用户不需要理解 OpenClaw、worker、provider、OpenViking、MongoDB 等内部概念。
- 用户可以像聊天一样提交投研任务、定时任务和价格提醒。
- 投研报告必须保持 TradingAgents / TradingAgents-CN 风格的完整报告感。
- 普通聊天不进入投研 workflow，直接透传给 OpenClaw。
- 投研 workflow 必须显式创建，并且创建前需要用户确认。
- UI 只负责产品交互、配置引导、任务状态展示和报告阅读，不接管 OpenClaw 的 LLM 配置和 Channel 实现。

参考对象：

- `claw-invest` 的 UI 骨架：左侧报告历史、中间消息流、右侧活任务栏。
- `claw-invest` 的任务栏状态展示：阶段、当前角色、进度、当前操作。
- `TradingAgents-CN` 的报告导出思路：Markdown 报告导出 PDF，但不能照搬其报告重组逻辑。

## 2. 产品边界

### 2.1 claw-trade 负责

- 投研 workflow 入口和状态展示。
- 报告任务队列。
- 定时报告和价格提醒的 UI。
- 数据源配置 UI。
- 报告阅读、报告追问、报告历史。
- 报告完成摘要。
- PDF 文件生成和保存。
- 调用 OpenClaw 的 Channel 和 LLM 配置能力。

### 2.2 OpenClaw 负责

- 普通聊天运行时。
- LLM 服务商、密钥、接口地址、默认模型的实际保存和测试。
- Channel 管理、微信 ClawBot 接入、消息发送。
- 单 agent turn 执行。

### 2.3 不允许

- UI 自动把普通聊天识别成投研 workflow。
- UI 在报告运行中把用户插话直接写入正在执行的 worker。
- UI 暴露 OpenViking、MongoDB、worker id、provider attempt 等内部词给普通用户。
- 为报告完成摘要新增简报 worker。
- PDF 导出重新总结、重写或补充报告内容。
- 未验证数据源进入投研报告证据链。

## 3. 总体布局

目标设备是集成在工控机中的硬件产品，不考虑移动端适配。

采用固定三栏布局：

```text
左侧：正式报告历史
中间：聊天 / 报告生成跟进 / 报告阅读
右侧：当前任务状态 / 当前报告详情
```

## 4. 视觉设计方向

视觉参考 `claw-invest` 的浅色三栏工作台，但需要更克制、更像专业投研终端。

整体气质：

- 安静、专业、清晰。
- 不做科技大屏。
- 不做深色驾驶舱。
- 不做营销首页。
- 第一屏就是可用的投研工作台。

颜色：

- 主背景使用浅灰蓝或冷白。
- 主色使用深蓝灰，表达专业和稳定。
- 辅色使用少量金色，只用于最终结论、报告完成、重要提示。
- 红色只用于失败、数据源失效、风险提醒。
- 绿色只用于报告完成、连接成功。

布局视觉：

- 左侧像报告档案柜，密度高、少装饰。
- 中间像正式报告阅读器和聊天工作区。
- 右侧像任务状态仪表板。
- 三栏之间使用清晰边框，不依赖强阴影。

字体：

- UI 控件使用无衬线中文字体。
- 报告正文使用中文衬线字体，增强正式报告感。
- 标题、摘要、表格和正文层级必须清晰。

控件和动效：

- 圆角控制在 6-8px。
- 少阴影，重边界和信息密度。
- 只保留轻量进度动效。
- 右侧当前任务可使用小圆点或细进度条。
- 不使用复杂动画、闪烁、跑马灯。

对 `claw-invest` 的调整：

- 保留浅色、蓝灰、报告字体、任务进度这些方向。
- 减少背景渐变和装饰光效。
- 报告页不单独跳走，要和聊天追问共存。
- 右侧状态比 `claw-invest` 更重要，需要明确显示当前角色和数据源异常。

## 5. 左侧：正式报告历史

左侧只显示成功保存的正式报告。

显示规则：

- 只显示已完成且保存成功的报告。
- 不显示排队中任务。
- 不显示运行中任务。
- 不显示失败任务。
- 不显示取消任务。
- 不显示普通聊天。
- 不显示定时任务和价格提醒。

每条报告显示：

- 标的。
- 报告标题。
- 生成时间。
- 核心结论摘要。

支持：

- 按标的搜索。
- 点击报告后，在中间主区域打开完整报告。

左侧的产品含义是“已经沉淀下来的正式成果”，不是任务管理器。

## 6. 中间：主区域

中间是唯一的聊天和报告阅读区域。

### 6.1 普通聊天状态

- 显示 OpenClaw 普通聊天消息流。
- 输入框消息直接透传给 OpenClaw。
- 不创建投研任务。
- 不进入 report workflow。

### 6.2 报告生成中

用户提交投研任务并确认后，中间默认进入该任务的跟进上下文。

显示内容：

- 用户提交的请求。
- 系统确认卡。
- 任务进入队列或开始生成的消息。
- 简洁进度消息。

输入框允许：

- 询问当前进度。
- 说明补充需求。
- 请求完成后重新生成。

输入框不允许：

- 直接改写已经运行中的 workflow。
- 直接插入正在执行的 worker prompt。

如果报告已经运行，用户提出新要求时，应提示：

```text
当前报告正在生成，无法中途修改。是否在完成后重新生成一份包含该要求的报告？
```

### 6.3 报告阅读状态

点击左侧报告或报告完成卡后，中间显示完整正式报告。

要求：

- 显示完整报告正文。
- 底部保留追问输入框。
- 追问默认围绕当前报告。
- 追问不影响其他正在运行的报告任务。
- 用户可说“回到普通聊天”切回普通聊天。

### 6.4 报告成功

报告生成并保存成功后：

- 左侧出现正式报告。
- 中间聊天出现报告完成卡。
- 卡片只显示报告摘要，不显示全文。
- 用户点击“查看完整报告”后，中间打开完整报告。

### 6.5 报告失败

报告失败后：

- 左侧不显示。
- 右侧不保留失败任务。
- 中间聊天显示一条可读失败提醒。

示例：

```text
这次报告没有生成成功。原因：数据源连接失败。请检查数据源设置后重新生成。
```

## 7. 聊天上下文规则

提交投研任务后，聊天框默认进入该任务的跟进上下文，但这不代表可以中途修改正在执行的 workflow。

上下文类型：

- 普通聊天：直接透传 OpenClaw。
- 任务跟进：围绕一个投研任务显示进度、接收补充需求。
- 报告追问：围绕一份已完成报告进行问答。

离开报告上下文的方式：

- 用户明确点击“普通聊天”。
- 用户说“回到普通聊天”“退出这个报告”“聊别的”。
- 用户点击另一份报告或另一个任务。

上下文状态必须在 UI 上可见，不能只靠 LLM 猜。

## 8. 右侧：任务状态与报告详情

右侧根据当前中间主区域状态变化。

### 8.1 普通聊天时

显示：

- 运行中和排队中的报告任务。
- 微信 ClawBot 状态摘要。
- 最近完成报告摘要。

不显示：

- 失败任务。
- 内部服务状态。
- MongoDB、OpenViking、OpenClaw Gateway。

### 8.2 报告生成中

右侧显示当前任务状态，参考 `claw-invest` 的活任务栏。

默认显示：

- 状态：排队中 / 生成中。
- 标的。
- 队列位置。
- 当前阶段。
- 当前角色。
- 当前操作。
- 进度条。
- 已完成角色。
- 等待角色。
- 操作：排队中可取消；生成中不显示取消入口。

当前阶段中文示例：

- 前线信息采集中。
- 投资辩论中。
- 投资决策中。
- 交易决策中。
- 风险辩论中。
- 风控裁决中。
- 报告生成中。

当前角色中文示例：

- 市场分析员。
- 基本面分析员。
- 新闻分析员。
- 社交情绪分析员。
- 多头研究员。
- 空头研究员。
- 研究经理。
- 交易员。
- 风险挑战员。
- 风险守护员。
- 风险主持员。
- 投资组合经理。

禁止显示：

- `market_analyst` 这类 worker id。
- `provider_attempts`。
- `OpenViking artifact write`。
- 内部路径、hash、runtime marker。

### 8.3 报告阅读时

右侧显示：

- 报告目录。
- 数据源状态。
- 图表状态：只来自已保存的图表资产、数据缺口、导出结果和报告里的图片引用。
- 导出状态。
- 操作：导出、重新生成、设为定时报告、添加价格提醒。

## 9. 数据源状态提醒

右侧详情需要显示数据源状态，但只提醒“已配置但本次失效”的数据源。

提醒条件：

- 用户已配置 Key、URL 或代理地址。
- 本次报告实际尝试调用。
- 调用失败、密钥无效、代理不可达、限流、返回格式异常。

不提醒：

- 从未配置 Key 的数据源。
- 本来不需要 Key 的公开数据源。
- 当前任务没有用到的数据源。
- 被用户关闭的数据源。

提醒内容：

- 数据源名称。
- 失效原因。
- 影响范围。
- 提醒用户去设置页更新。

示例：

```text
CoinGlass：代理地址无法访问，衍生品和清算数据可能缺失。请到设置里的数据源更新代理地址。
Tushare：密钥可能无效，A股财务数据可能缺失。请到设置里的数据源更新密钥。
NewsAPI：已配置密钥，但请求被限流，新闻覆盖可能不完整。
```

右侧只提醒，不放“去更新”“重新测试”“忽略”等操作按钮。配置统一在设置页完成。

## 10. 任务创建

任务通过自然语言创建，但必须确认。

支持用户输入：

```text
帮我做一份 BTC 投研报告
每天早上 8 点给我一份 BTC 报告
茅台跌到 1500 提醒我
ETH 24 小时涨跌超过 5% 提醒我
```

系统识别到报告、定时报告或价格提醒意图时，不直接创建任务，而是在聊天中生成确认卡。

确认卡显示：

- 类型：投研报告 / 定时报告 / 价格提醒。
- 标的。
- 市场。
- 触发条件或频率。
- 通知方式：微信 ClawBot / 站内提醒。
- 数据源状态摘要。
- 操作：确认 / 取消。

用户确认后才创建任务。

普通聊天不生成确认卡，直接透传 OpenClaw。

## 11. 报告队列规则

报告生成必须串行。

规则：

- 不并行生成完整报告。
- 所有完整报告任务进入同一个队列。
- 队列上限默认 10 个任务。
- 手动报告优先于定时报告。
- 手动报告不打断当前正在运行的报告。
- 同标的排队报告可合并或去重。
- 运行中的报告不允许中途改写。

## 12. 定时报告

第一版只支持完整报告，不支持简报 worker。

支持频率：

- 每天。
- 每周。

不支持：

- 每小时生成完整报告。
- 高频周期报告。

如果用户要求每小时报告，直接拒绝并提示支持选项：

```text
当前只支持每天或每周生成完整报告。请选择每天或每周。
```

定时报告到点后进入完整报告队列。

## 13. 价格提醒

第一版支持：

- 价格阈值提醒。
- 百分比涨跌提醒。

不支持：

- 技术指标触发。
- 自动生成报告。
- AI 解释。

触发规则：

- 默认只发提醒。
- 通过配置好的 Channel 通知用户。
- 如果没有配置 Channel，则在 UI 聊天流里弹出消息。
- 价格提醒触发后默认自动关闭。

任务管理支持：

- 暂停。
- 删除。
- 立即执行。

立即执行含义：

- 对定时报告：立即进入完整报告队列。
- 对价格提醒：立即检查当前条件；若满足则发送提醒并关闭。

## 14. 微信 ClawBot 通知

默认通知 Channel 是微信 ClawBot。

产品认知：

- 用户看到的是“微信通知”或“微信 ClawBot”。
- 不要求用户理解 OpenClaw Channel。
- 不展示 npm 包、插件目录、配置路径。

实现认知：

- 普通微信内部映射到 OpenClaw 外部插件 `openclaw-weixin`。
- 企业微信 / WeCom 不是普通微信 ClawBot，不能混用。
- 发送完整报告前必须检查当前 Channel 是否已安装、已登录、支持文件或媒体发送。
- 微信里回复“报告”时，`claw-trade` 只接 OpenClaw 转来的消息通知/回调，不自己实现微信协议。
- 首版推荐接入方式是腾讯 `@tencent-weixin/openclaw-weixin` 插件；不走 Wechaty、逆向登录或自建微信协议。
- 产品文案不得承诺“绝对不封号”；只说明“使用微信 ClawBot 插件接入”。
- 2026-05-19 本机实现前探测：npm 包 `@tencent-weixin/openclaw-weixin@2.4.3` 存在且可安装，插件声明 Channel ID 为 `openclaw-weixin`，能力包含私聊和媒体。当前本机/项目运行态仍未按官方路径完成 clean 验收，真实扫码登录、在线状态、文件发送和入站消息实测仍未完成。
- 同一轮探测确认：`scripts/start-control-runtime.sh` 是 dev/fixed 测试 runtime，会重建 `.runtime/dev-services/openclaw-state/openclaw.json`；它当前只保留 claw-trade 前线工具插件，不会自动把外部微信插件带进 Gateway。这个现象只说明“该测试脚本不能证明微信已接通”，不得外推为生产级配置必须每次重建。实现前仍需定义生产/正式 UI runtime 如何保留并加载 `openclaw-weixin`。

接入流程：

1. 用户在微信中启用 ClawBot 插件。
2. 设备上安装并启用 OpenClaw 微信插件。
3. 启动或重启 OpenClaw Gateway。
4. 用户在设备上扫码绑定微信。
5. UI 设置页显示“已连接 / 未连接 / 连接异常 / 文件发送不可用”。

内部消息路径：

```text
微信用户
-> 微信 ClawBot 插件
-> OpenClaw Gateway
-> claw-trade UI 后端
-> claw-trade 报告队列 / 报告仓库 / PDF 服务
-> OpenClaw Gateway
-> 微信 ClawBot 插件
-> 微信用户
```

微信内首版命令：

| 用户输入 | 产品行为 |
|---|---|
| `/report BTC` / `报告 BTC` | 生成报告确认卡，不直接创建 workflow |
| `确认` | 对当前确认卡创建完整报告任务 |
| `取消` | 只取消排队中的任务；生成中回复“报告正在生成，不能中途取消” |
| `进度` | 返回当前报告的中文阶段进度 |
| `发送完整报告` | 发送已保存 PDF；不可用时给可读失败 |

失败提示：

| 场景 | 用户文案 |
|---|---|
| 微信插件未安装 | 请先安装微信 ClawBot 插件。 |
| 微信插件未启用 | 请先启用微信 ClawBot 插件。 |
| 未扫码绑定 | 请用微信扫码连接 ClawBot。 |
| 当前账号或灰度不可用 | 当前微信账号暂不可用 ClawBot，请在设备界面查看报告。 |
| 已连接但不能发文件 | 微信文字通知可用，完整 PDF 暂不可发送。 |
| 生成中取消 | 报告正在生成，不能中途取消。 |

首次启动：

- 提示连接微信 ClawBot。
- 用户可以跳过。
- 跳过后仍可进入产品。

设置页：

- 保留微信连接设置。
- 状态：未连接 / 已连接 / 连接异常。
- 操作：连接微信 / 重新连接 / 解除连接。
- 引导用户打开微信：`我 -> 设置 -> 插件 -> 微信 ClawBot`。

边界：

- 微信登录、凭据、消息发送由 OpenClaw 负责。
- `claw-trade` 只做 UI 引导和调用。
- 如果微信不可用，通知落回 UI 聊天流。

## 15. 报告完成通知

完整报告生成成功后，不主动推送完整报告全文。

流程：

1. workflow 串行生成完整正式报告。
2. 报告保存成功。
3. 立即生成 PDF 文件。
4. 左侧报告历史出现该报告。
5. 中间聊天显示报告完成卡。
6. 微信 ClawBot 发送同样的完成摘要。
7. 用户选择查看后才返回完整报告。

完成摘要内容：

- 标的和报告时间。
- 最终结论。
- 2-3 条核心理由。
- 1-2 条主要风险。
- 已配置但本次失效的数据源提醒。
- 查看完整报告提示。

摘要来源：

- 已保存正式报告。
- PM 最终结论。
- 报告元数据。

禁止：

- 为摘要新增简报 worker。
- 在完整报告未生成前先编摘要。
- 摘要补写正式报告中不存在的数据。

## 16. 完整报告文件发送

用户在微信里选择查看完整报告时，默认发送 PDF 文件。

规则：

- 用户回复“报告”或点击“发送完整报告”。
- 系统发送已保存 PDF 文件。
- Markdown 可作为高级导出，不作为微信默认发送格式。
- 文件发送失败时，在微信和 UI 聊天里提示失败。

失败提示示例：

```text
完整报告文件发送失败，请在设备界面中查看。
```

## 17. PDF 生成方案

PDF 生成参考 TradingAgents-CN 的导出思路，但不照搬其报告重组逻辑。

输入：

- 已保存的完整正式 Markdown 报告。

流程：

1. 保存正式 Markdown 报告。
2. 清理 Markdown，避免 YAML 元数据误判。
3. 渲染为 HTML。
4. 优先使用 `pdfkit + wkhtmltopdf` 生成 PDF。
5. 备选使用 `weasyprint`。
6. 处理中文字体、横排文本、表格分页、图片缩放。
7. 保存 PDF 文件路径和生成状态。

要求：

- PDF 只是格式导出，不改变报告内容。
- 不重新总结。
- 不重写 PM 最终结论。
- 不补写缺失数据。
- PDF 生成失败不影响报告保存。

PDF 生成失败时：

- 报告仍然保存成功。
- 左侧仍显示报告。
- UI 显示完整报告。
- 完成摘要提示 PDF 暂不可用。

## 19. 错误文案

错误文案必须面向普通用户。

推荐文案：

- 密钥没填。
- 密钥无效。
- 接口地址不可访问。
- 代理地址不可访问。
- 返回格式不符合要求。
- 访问太频繁，被限流。
- 当前网络无法访问，建议使用代理地址。

避免文案：

- provider attempt failed。
- schema invalid。
- credential missing。
- runtime marker mismatch。
- artifact write failed。

内部错误可以进入诊断日志，但普通 UI 应翻译成人话。

## 20. 首版明确不做

- 移动端布局。
- 并行报告生成。
- 小时级完整报告定时任务。
- 简报 worker。
- 运行中 workflow 插话改写。
- 失败任务管理页。
- 任意未知 HTTP/JSON 数据源接入。
- 数据源字段映射平台。
- 在 `claw-trade` 内实现微信协议。
- 在 UI 暴露 OpenClaw / OpenViking / MongoDB 内部配置。

## 21. 已决策点、已查清事实和运行时检查点

已决策：

- 报告完成摘要只从已保存报告、PM 最终结论和报告元数据确定性摘取。
- PDF 只格式化已保存 Markdown，采用浅色中文横排投研报告风格；不得重写、总结、补写报告。
- 数据源实例配置首版由 claw-trade 后端受控读写 `.env.local`；前端、普通 UI API 和 workflow controller 不直接读写。
- 排队任务可取消；运行中 workflow 首版不取消。

已查清：

- 普通微信 ClawBot 后端内部映射到 OpenClaw 外部插件 `openclaw-weixin`；企业微信 / WeCom 不等同普通微信。
- LLM 设置通过 OpenClaw config/models 能力完成；`claw-trade` 不保存真实密钥，不自造 LLM 保存/测试接口。
- 图表状态只来自已保存的图表资产、数据缺口、导出结果和报告 Markdown 图片引用。
- “已配置但本次失效”只提醒 configured + enabled + usedInRun + failed 的数据源。

实现前运行时检查点：

- 发送完整报告前，必须检查当前 OpenClaw 微信 Channel 是否已安装、已登录、支持文件或媒体发送，以及 PDF 大小是否允许。
- 微信里回复“报告”要能进入 `claw-trade`，必须先确认 OpenClaw 是否提供可接入的入站消息通知/回调。
- 仅确认官方插件存在与安装路径，不把本机 CLI 静态能力输出当成接通证据；没有真实二维码登录、真实 status、真实发送和真实入站证据前，微信状态只能显示未连接或不可用。

不得用 mock/stub/fake/fallback 证明文件发送成功或微信入站回调成功。
