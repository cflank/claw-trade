# claw-trade 详细设计

本文是当前详细设计入口：它归并旧文档中的模块职责、数据合同、gate、测试和部署验证口径，但不是旧文档全文替代。删除前旧文档全文已恢复到 `docs/reference/legacy/`，索引见 [旧文档恢复索引](reference/legacy/README.md)。

港股独立 profile 的专项详细设计见 [港股详细设计](港股详细设计.md)。该文档对齐 [港股总体设计](港股总体设计.md)，覆盖 HK 输入解析、prompt、stage tools、provider evidence、Tushare Pro HK、HKEXnews、四个前线数据服务、下游材料边界、PM/export 和验收矩阵。

## 1. 设计原则

详细设计遵循以下规则：

- worker 是 OpenClaw agent，不是 Python 函数。
- Python 调度 worker，但不替 worker 写报告。
- provider 真实调用，失败真实暴露。
- worker 间主传递链使用已批准的完整自然语言 report；artifact ref/capability 只用于追踪、校验和必要时深读 L2。
- JSON 只用于内部工具协议、缓存、测试证据和机器校验，不进入正式 worker handoff。
- Hard gate 只拦截造假、越权和证据破坏，不压扁正常报告表达。
- frontline 四个 worker 完成后直接进入投资辩论：先唤醒 bull，再由 bear 看到 bull 的发言并反驳；不新增总 gate。
- 后半段按 TradingAgents-CN 串行轮转：`research_manager -> trader -> risk_challenger -> risk_guardian -> risk_moderator -> portfolio_manager`；风险三人组是接力，不是 collect-first 并列批次，也不是新 gate。

## 2. control plane 模块

### 2.1 workflow models

位置：`src/claw_trade/workflow/models.py`

负责：

- `RunRequest`
- `WorkflowState`
- `StagePlan`
- `StageBatch`
- `WorkerCall`
- `WorkerResult`
- `FailureRecord`
- `ExportResult`
- `OpenClawCommand`

设计要求：

- state machine 可序列化。
- worker、stage、run id、dispatch id 可追踪。
- 不把投资决策逻辑写入模型对象。

### 2.2 controller

位置：`src/claw_trade/workflow/controller.py`

负责：

- 根据 state 决定下一批 worker。
- 固定 12-worker 顺序。
- running / ready / failed / report exporting 状态推进。
- 不让 LLM 决定流程。

### 2.3 runner

位置：`src/claw_trade/workflow/runner.py`

负责：

- boot run。
- 调用 request builder。
- 调用 OpenClaw client。
- 读取 OpenClaw evidence。
- 执行 guards。
- 写入 manifest。
- 推进 state。

### 2.4 store

位置：`src/claw_trade/workflow/store.py`

负责：

- run state 持久化。
- evidence 路径登记。
- audit / failure records 保存。

## 3. OpenClaw 调用模块

### 3.1 request builder

位置：`src/claw_trade/runtime/request_builder.py`

负责把 `WorkerCall` 转成 OpenClaw 单 worker command。

只允许注入：

- worker id。
- stage。
- ticker。
- company name。
- market/profile。
- currency。
- date range。
- allowed tools。
- runtime markers。
- 已批准上游 L1 report 正文。
- artifact ref / capability 作为审计和深读权限随行，不替代 CN/原版 prompt 里的完整上游报告。

不允许注入：

- Python 手写业务 prompt。
- 控制流日志。
- 调试 JSON。
- 非本阶段 provider 原子结果。

### 3.2 OpenClaw client

位置：`src/claw_trade/runtime/openclaw_client.py`

负责：

- 调用 OpenClaw gateway。
- 获取机器可读结果。
- 定位 provider payload、visible tools、tool calls、raw output、receipt。

### 3.3 evidence reader

位置：`src/claw_trade/runtime/evidence_reader.py`

负责把 OpenClaw evidence bundle 读回 claw-trade hard gate。

## 5. Guard 模块

位置：`src/claw_trade/guards/`

关键 guards：

- workspace evidence。
- provider request。
- visible tools。
- tool calls。
- OpenViking receipt。
- OpenViking access。
- L1/L2。
- fundamental claim。
- PM 最终裁决权：以 PM 已批准自然语言 L1 为权威，export 不能改写；不要求额外 sidecar。
- export claims。

### 5.1 guard 边界

guard 要防造假，不负责把报告写成模板。
guard 也不负责把 TradingAgents / TradingAgents-CN 的强观点辩论室改成审慎合规 memo。原版对齐优先于未经批准的风格收敛。

runtime guard 清单默认冻结。新增、恢复或加严 runtime guard、hard-gate category、early-stop category、输出语义 validator、claim dictionary 或 exporter 拒绝规则，必须先有三类来源之一：原版 TradingAgents / TradingAgents-CN 证据、本文档的活跃设计条款、或人类对这个具体 gate 的明确批准。否则不能写代码，不能先写测试把新规则固化。

如果问题是角色声线、辩论强度、memo 化、谨慎化、Hold/Buy/Sell 措辞、交易动作表达、报告结构或 PM 自然语言裁决表达漂移，只能修 prompt、材料边界或 workflow，并用 provider payload 证明；不能新增 runtime gate。

当前批准的 guard 文件集合和 early-stop 类别由 `tests/contracts/test_guard_change_requires_approval.py` 锁定。改这个 allowlist 本身就是需要人类批准的边界变更。

应该 hard fail：

- 编造 provider 成功。
- 编造数据源。
- 编造图表。
- 编造新闻。
- unsupported PE/PB/ROE。
- Python 改写 PM 结论。
- receipt 缺失。

PM 最终裁决合同：

- 所有已批准 profile 下，PM 最终裁决都以 `portfolio_manager` 的自然语言 L1 report 为权威。
- 系统只认 PM 已批准自然语言 L1 report，不要求额外机器裁决文件。
- 无论 profile，非 PM worker 不能冒充 PM 决策身份，export 不能改写 PM 结论。

不应该 hard fail：

- analyst 有依据地提出建议。
- analyst 有依据地提出估值框架。
- market worker 写技术条件。
- report 语气更像研究报告而不是工程摘要。
- bull/bear/risk worker 使用直接反驳、强观点、final proposition 或辩论式语气。
- worker 给出 baseline 允许且证据支持的 BUY/HOLD/SELL、风险判断、目标情景或交易条件。

禁止把以下内容作为无审批 guard 或 prompt 规则加入：

- “更审慎”“更合规”“避免强观点”“避免 final recommendation”“禁止 FINAL TRANSACTION PROPOSAL”。
- 有证据时也默认写 limitation report。
- 用 portfolio manager 最终裁决权边界限制前台、debate 或 risk worker 的证据支持观点表达。
- 为了让测试更容易通过，把 worker 输出改成工程摘要、合规备忘录或 checklist。
- 未经明确批准恢复 `pm-decision.json` 这类 PM sidecar 决策要求。
- 未经明确批准新增 Hold/Buy/Sell 动作语义 hard gate。

## 6. Report exporter

位置：`src/claw_trade/reports/exporter.py`

负责：

- 读取 approved worker reports。
- 组装最终 reader-facing Markdown。
- `final-report.md` 只排版已批准 L1 自然语言正文：先放 `portfolio_manager` 最终裁决原文，再按章节放其他 worker 原文；Python 不总结、不改写、不反推 PM 结论。
- 机器审计字段（如 URI/hash/L1/L2/material_id/capability/receipt/provider payload）只保留在 `export-claims`、`export-result` 或审计文件，不进入 `final-report.md`。
- 复制图表资产。
- 写入相对图片路径。
- 不添加 unsupported 投资结论。

PM 导出边界：

- 导出阶段直接呈现 PM 已批准 L1 原文作为最终裁决段，不从自然语言反推评级或最终结论。
- `CN_A` 下若导出阶段出现 `export_report_assets`（例如未发现可复制图表或复制失败），必须写入 export 失败证据；但该失败属于产品导出问题，不得把已完成的 12-worker workflow/PM 决策改写为 failed。

图片发现路径包括 OpenClaw call evidence 中的：

```text
pack-tool-evidence/techlab/charts-local/
```

## 7. Frontline OpenClaw plugin

位置：`openclaw_plugins/claw-trade-frontline-tools/`

职责：

- 把 CN_A frontline 数据包能力注册成 OpenClaw 工具。
- 适配 Python 数据包构建器。
- 输出 worker 可读材料。
- 保存 provider evidence。

插件不是 MCP 服务本体；它是 OpenClaw 普通插件形态，用来给 OpenClaw worker 暴露 claw-trade frontline tools。

## 8. 统一资料包外壳

内部资料包采用统一 envelope，包含：

- profile。
- ticker。
- company。
- date range。
- quality status。
- provider attempts。
- domain data。
- reader brief。
- evidence refs。

质量状态：

- `complete`：核心字段达到 worker 可用标准。
- `partial`：有真实材料但缺关键字段。
- `failed`：无可用真实材料或关键依赖失败。

注意：envelope 是工具内部结构，不是 worker 间主传递链。

### 9.1 入口

- `agents/market_analyst/skills/cn-a-market-data/`
- `agents/market_analyst/skills/alphaear-stock/`

- `openclaw_plugins/.../market_data_pack.py`

### 9.2 数据

market 需要：

- Tushare / AkShare 行情。
- K 线。
- 成交量。
- 均线。
- 技术指标。
- 图表。

### 9.3 图表

AlphaEar TechLab 负责技术指标和图表生成。图表作为 evidence 文件存在，最终报告导出时复制，不进入 worker handoff。

### 9.4 prompt

CN_A market prompt 主体对齐 TradingAgents-CN 技术面报告，不写工程材料摘要。

工具参数 market 必须传 `CN_A`，避免模型写“中国A股”导致工具参数不匹配。

## 10. Fundamental 详细设计

### 10.1 入口

位置：

- `agents/fundamental_analyst/skills/cn-a-fundamental-data/`
- `src/claw_trade/data_gateway/providers/tushare_client.py`
- `openclaw_plugins/.../fundamentals_data_pack.py`

### 10.2 provider

主源：

- Tushare。

补充源：

- AkShare。
- Eastmoney。
- 其它明确批准源。

### 10.3 字段

核心字段：

- PE。
- PB。
- PS。
- 股息率。
- EPS。
- TTM EPS。
- ROE。
- 毛利率。
- 净利率。
- 营收。
- 净利润。
- 经营现金流。
- 资产负债关键字段。

### 10.4 complete 口径

估值核心齐全，加上财务或现金流至少一组真实数据，可以 complete。

若只有估值或只有零散财务，则 partial。

### 10.5 claim gate

Fundamental claim gate 只防无证据硬写，不禁止 analyst 在证据基础上给估值框架。

## 11. News 详细设计

### 11.1 入口

位置：

- `agents/news_analyst/skills/cn-a-news-data/`
- `openclaw_plugins/.../news_data_pack.py`
- `openclaw_plugins/.../news_matcher.py`

### 11.2 provider

可用源：

- Tushare news / announcements。
- AkShare 东方财富新闻。
- 财联社等公开源。
- Bocha。
- Tavily。
- Jina。
- NewsNow。
- MiniMax 国内 API。

### 11.3 匹配

News 需要区分：

- 公司直连新闻。
- 行业背景。
- 宏观背景。
- 关键词弱相关。

弱相关材料可以作为背景，不得写成公司事实。

### 11.4 输出

如果没有强相关新闻，但 provider 正常返回空，报告应自然说明“未检索到强相关新闻”。

如果 provider 失败，应说明数据源失败原因。

### 12.1 入口

位置：

- `agents/social_analyst/skills/cn-a-social-data/`
- `openclaw_plugins/.../social_sentiment_pack.py`
- `openclaw_plugins/.../social_matcher.py`

### 12.2 数据

Social 支持：

- 关键词热度。
- 热度排名。
- 平台讨论文本。
- 文本情绪。
- source coverage 缺口说明。

优先补齐的文本源包括雪球和股吧；未接通前不能把热度数据写成文本情绪。

### 12.3 降级表达

如果只有热度数据，没有文本情绪源：

- 写热度报告。
- 不写情绪指数。
- 不写短期价格预测。

## 13. MongoDB 详细设计

MongoDB collection 按服务域隔离：

- fundamental cache。
- news cache。
- social cache。
- provider raw payload。
- normalized pack cache。

索引应覆盖：

- profile。
- ticker。
- provider。
- query hash。
- date range。
- freshness。
- schema version。

TTL 只清理缓存，不清理 approved artifact。

## 14. 配置详细设计

`.env.example` 是模板，`.env.local` 是本地 secret。

Tushare 私有 endpoint 通过：

```text
TUSHARE_HTTP_URL
CN_A_TUSHARE_HTTP_URL
```

MiniMax 国内 endpoint：

```text
CN_A_NEWS_MINIMAX_BASE_URL=https://api.minimaxi.com/v1
CN_A_NEWS_MINIMAX_MODEL=MiniMax-M2.7
```

## 15. 测试详细设计

测试分层：

- unit：单模块逻辑。
- contract：架构边界、tool schema、prompt/write contract、guard。
- integration：MongoDB、OpenViking、OpenClaw plugin、frontline CLI。
- live gate：fresh OpenClaw worker run。
- eval：与 TradingAgents-CN 做 final prompt / LLM back / report 对比。

小改动先跑 focused tests。完整 live gate 只在阶段验收时跑。
