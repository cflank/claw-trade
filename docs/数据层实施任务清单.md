# 数据层实施任务清单

状态：PARTIAL（DLT-01 到 DLT-14 的合同、单元、数据层集成和 cutover 验收为当前可验收范围；CRYPTO `daily_bar` 已按 Binance Public Data / REST Kline 完成 live 增量证明；CN_A/US/HK 已有 managed_http provider 实现但仍需现场 provider smoke；UI 人流、OpenClaw/OpenViking runtime 证明不属于数据层完成证据）。

唯一详细实现依据：`docs/数据层详细设计.md`。`docs/数据层总体设计.md` 和 `docs/架构设计.md` 只作为边界依据。`memory/2026-05-29.md` 不再作为数据层实施来源。

当前详细设计范围只有 `§1` 到 `§16`。本清单不使用旧覆盖编号，不引用不存在的后续章节作为覆盖矩阵来源。

## 1. 设计来源与硬边界

- 数据层核心合同是 `DataRequest -> DataResult`。
- 数据层的主产出是数据引用和缺口：`dataset_refs`、`raw_refs`、`attempt_refs`、`gaps`。`DataResult` 可保留详细设计授权的轻量 `rows`、`freshness`、`source_summary` 字段，但它们不能替代 refs/gaps，不能承载 worker 资料包或 reader brief。
- 数据层不生成 worker 资料包、读者简报、报告计划、选股计划或 UI 展示决策。
- 数据层不决定 report 是否继续，不决定 select 是否成功、失败或重跑。
- 数据层不调用 OpenViking，不写 approved material，不保存 worker 可读材料。
- 数据层不新增 runtime guard，不新增报告表达 guard。anti-fake 只用于数据真实性、证据完整性和设计边界。
- Provider 能力来自 `ProviderPlugin.capabilities()`，不是独立顶层能力模块。
- 已删除数据网关 本体不是目标运行时依赖；旧 已删除数据网关 前缀不得作为新目标表名、模块名或证据链名。
- MongoDB 目标 collection 只采用详细设计 `§11` 的 8 个名称：`normalized_datasets`、`raw_payloads`、`provider_attempts`、`provider_rate_limits`、`single_flight_calls`、`provider_result_cache`、`dataset_manifests`、`maintenance_jobs`。
- CRYPTO `daily_bar` 行情主源是 `docs/加密币选币讨论纪要.md` 记录的 Binance Public Data / Binance REST Kline；CoinGecko Pro 是设置页中的增强数据源，可用于元数据、市值、供应量等补充，不替代 Binance 原始交易所 K 线作为主行情源。

## 2. 当前目录隔离策略

- 旧数据层目录：`src/claw_trade/data_gateway_bak`。
- 新数据层目录：`src/claw_trade/data_gateway`。
- 旧实现是备份和隔离对象，不是新数据层实现来源。
- 新数据层必须按 `docs/数据层详细设计.md` 在新的 `src/claw_trade/data_gateway` 下重新开始。
- 旧 `packs/**`、`mcp/runtime_wrapper.py`、`providers/removed_data_gateway_runtime.py`、旧 `store/removed_data_gateway_*` 只能作为 forbidden legacy path 或 negative test target 出现。
- 新代码不得从旧目录导入业务逻辑，不得通过兼容开关把新入口失败切回旧路径。

每条任务必须在实现 PR 中列出：设计来源、目标实现文件/目录、目标测试文件、验收方式、状态。本文状态只表达数据层合同范围；不得把 live provider、UI、report/select 业务验收或 OpenViking runtime proof 写成数据层完成证据。

### DLT-01：接口合同与核心模型

- 设计来源：详细设计 `§4`、`§5`、`§16`。
- 目标：实现 `DataAPI.get_data`、`DataAPI.get_data_batch`、`DataRequest`、`DataResult`、`DataGap`、`DataPlan`、`ProviderCapability`、`ProviderBatchPlan`、`FetchResult`、`IngestResult`，以及详细设计 `§5` 列出的枚举和 validator。
- 边界：`DataResult.status` 只表达数据可用性，不表达 report/select 成败。
- 状态：VERIFIED（合同/单元验收范围）。

### DLT-02：6 层目录和模块边界

- 设计来源：详细设计 `§2`、`§16`。
- 目标：在 `src/claw_trade/data_gateway` 下建立接口层、协调层、仓库层、执行层、插件层、入库与证据层。
- 边界：不得把 provider 选择、出网、入库、报告材料生成混进同一模块。
- 状态：VERIFIED（合同/单元验收范围）。

### DLT-03：固定 10 步数据请求流程与 QueryPlanner

- 设计来源：详细设计 `§3`、`§6`、`§16`。
- 目标：`QueryPlanner` 负责校验/规范化 symbol、market、calendar、timezone、date range，生成 warehouse checks、required coverage 和 expected outputs；`DataService` 串联固定流程：请求校验与规范化、仓库检查、覆盖度与新鲜度判断、缺口生成、候选 provider 选择、同源合并、批量计划、执行闸门、指定 provider fetch、入库后 recheck 并返回 `DataResult`。
- 边界：`QueryPlanner` 不生成 provider candidate 或 `ProviderBatchPlan`；`DataService` 不直接 HTTP、不直接写 Mongo、不生成 worker 材料。
- 状态：VERIFIED（合同/单元验收范围）。

### DLT-04：仓库层与 freshness 判断

- 边界：不得用 A 股日线满足分钟、实时、财务、公告、新闻、舆情或其它数据集需求。

### DLT-05：Provider 插件和能力声明

- 目标：实现 `ProviderPlugin` 协议、`ProviderRegistry`、`capabilities()` schema、batch policy、credential policy、license policy 和 market support。
- 边界：provider 不写仓库，不决定 report/select 业务结果，不内部切换到其它 provider 冒充成功。

## 5. Boundary Audit / Unsupported Content Removed

以下内容不得作为数据层实施任务、目标模块或验收成功条件：

- `DomainPack`、worker pack、reader brief、材料层自然语言渲染。
- report plan、select plan，以及任何 report/select 成败裁决。
- `ProviderDisplayDecision`、UI display policy、UI provider show/hide 规则。
- `write_openviking_material`、OpenViking material writer、approved material 写入。
- truthfulness guard、报告表达 guard、投资结论或 worker/PM 语言约束。
- CryptoLens、price alert、未由详细设计授权的数据层模块。
- 旧覆盖编号和不存在的后续章节口径。
- 旧 `removed_data_gateway_*` collection 目标表、旧 evidence 链名或旧模块名。它们只能出现在 forbidden legacy path / negative test target 语境中。

## 7. Stop Conditions

遇到以下情况必须停止并请主 agent 或人类确认：

- 需要让数据层生成 worker 资料包、读者简报、report plan、select plan 或 OpenViking material。
- 需要让数据层决定 report/select 成败。
- 需要新增不在详细设计 `§11` 的目标 Mongo collection。
- 需要把旧 `removed_data_gateway_*` 名称恢复为新目标表名、模块名或证据链名。
- 需要从 `src/claw_trade/data_gateway_bak` 复用旧业务逻辑作为新实现来源。
- 需要将 cache_hit、shared_result、rate_limited、cached_empty、cooldown_skipped、sdk_http_unknown、evidence_write_failed 写成远端成功。
- 需要用兜底成功掩盖 provider 失败或仓库缺口。
- 需要把搜索线索、UI probe、旧 completed evidence、旧本地文件读取当正式事实源或主链路证据。
- 需要新增 runtime guard 或报告表达 guard，而不是修复数据/证据事实。
- 需要扩展 HK/US select、Crypto 全量历史包、CryptoLens、price alert 或其它详细设计未授权范围。
