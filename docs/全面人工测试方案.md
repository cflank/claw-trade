# 全面人工测试方案

版本基线：`v0.9` / `a45b408 待全面测试`

本文档用于 v0.9 之后的完整人工验收。这里的“人工测试”不是跑脚本、不是直接调 API、不是只看单元测试结果，而是用真实浏览器像真实用户一样操作产品，再用后台证据核对数据层、worker、报告和导出结果是否可信。

## 1. 测试原则

1. 验收入口必须是 UI。
2. 页面操作必须使用真实 Chrome。若由 agent 代测，只能通过 `playwright-win-chrome` MCP 模拟真实点击、输入、等待和截图，不能用 headless、WSL Chromium、临时脚本或直接 API 调用冒充用户。
3. 启动服务、查看日志、检查证据可以用命令辅助，但这些只算核对证据，不算用户验收动作。
4. 某功能没有 UI 入口时，结论是“产品缺口”，不能用 CLI 或 Python 函数替代通过。
5. 数据源失败不能改成假成功；没有数据就写清楚缺失原因。
6. 报告不能编造 PE、PB、ROE、目标价、新闻、来源、情绪、图表或工具成功。
7. 普通 UI 不能暴露内部词：MongoDB、OpenViking、OpenClaw Gateway、worker id、provider attempt、run id、hash、artifact、本地路径、端口、token、credentialRef。
8. 全链测试按 collect-first 执行：同一批次内可恢复失败先收集完，再按根因分组修复。

## 2. 测试范围

必须覆盖以下全部功能：

| 范围 | 必测内容 |
|---|---|
| 启动与运行态 | 固定 runtime、真实 Chrome、UI 可访问、健康状态、刷新恢复 |
| 设置 | 模型、数据源、微信、报告默认参数、密钥掩码、错误提示 |
| 普通聊天 | 普通问题不触发报告、不创建任务、不污染报告历史 |
| 报告创建 | `/report`、自然语言报告意图、确认卡、取消、排队、重复提交 |
| 四市场报告 | A股、加密、US、HK 的完整报告链路 |
| 数据层 | 项目数据项、数据源 API 调用、兜底、限流、缓存、缺口证据 |
| A股数据 | Tushare、AkShare、EastMoney、mootdx、行情、盘口、财报、资金、公告等 |
| 加密数据 | Coinglass、Glassnode、CoinGecko Pro、Binance、FRED、资金费率、OI、清算、CVD 等 |
| US/HK 数据 | Finnhub、FRED、Tushare HK、Yahoo/公共源等 |
| `/select` | 候选缓存、top20、四个 selection worker、确认后转 `/report` |
| 报告阅读 | 历史列表、打开报告、追问、重新生成、上下文过长处理 |
| PDF | 真 PDF、中文、图表、表格、页码、不可伪造 |

| 失败恢复 | 数据源失败、LLM 失败、运行中刷新、重启后恢复 |
| 安全脱敏 | 页面、网络响应、导出物、错误文案不泄密 |

| 项目 | 要求 |

| 证据目录 | 每轮保存截图、录屏、最终报告、PDF、数据源调用摘要、缺口清单 |

## 4. 通过标准

1. 所有 P0 用例通过。
2. P1 用例没有阻断级缺陷；若失败，必须有明确根因、影响范围和修复计划。
3. 四市场至少各完成一次从 UI 发起的报告全链。
4. A股和 BTC 必须额外做数据专项核对。
5. `/select` 必须完成一次“读取候选缓存 -> selection worker -> 用户确认 -> 报告交接”。
6. PDF 必须由真实用户入口导出，能打开，内容完整。
7. 微信如未完成真实登录和真实发送，只能标记为阻塞或未接通，不能通过。
8. 普通 UI 不得出现内部字段或内部错误原文。
9. 数据层不得把 provider/path/api_name/api_id/params/fields 暴露给 worker 或普通用户。
10. 任何“数据缺失”必须能追到具体原因：凭证、权限、限流、provider 空结果、parser 缺失、外部错误、预算不足或项目未接接口。

### 6.10 数据层边界和调用流程

| ID | 用例 | 操作 | 预期 |
|---|---|---|---|
| DATA-001 | worker 工具边界 | 检查 provider payload | worker 只看到业务数据工具，不看到 provider/path/api_name/api_id/params/fields |
| DATA-002 | 数据项到 API | 核对每个缺失或成功数据项 | 能追到具体数据源 API、参数和返回 |
| DATA-003 | 高优先级成功即停止 | 让 Tushare 或 Coinglass 成功返回 | 不继续无意义调用低优先级等价源 |
| DATA-004 | 高优先级失败后兜底 | 禁用或让高优先级失败 | 调用后续真实源；无源则明确缺失 |
| DATA-005 | 非等价接口不乱排 | 请求清算或 CVD | 只排能产出该数据项的接口，不排几十个无关接口 |
| DATA-006 | parser 缺失 | 源返回 raw 但没 parser | 标记 parser 缺失，不能变成 provider_error |
| DATA-007 | provider 空结果 | 源返回空 | 标记空结果，不能说系统成功拿到数据 |
| DATA-008 | 权限不足 | 源返回权限错误 | 标记权限不足，不能静默换成假数据 |
| DATA-009 | 缓存命中 | 重复请求同一数据项 | 可复用缓存，但报告仍要显示数据时间和来源 |
| DATA-010 | single-flight | 多 worker 同时要同一源同一接口 | 真实出网只应合并，不重复打爆 |

### 6.11 限流

| ID | 用例 | 操作 | 预期 |
|---|---|---|---|
| RATE-001 | 同源全局计数 | 连续触发 Coinglass 多数据项 | 所有 worker 合并计入同一个源限流桶 |
| RATE-002 | 连续 60 秒窗口 | 观察任意连续 60 秒请求数 | 不超过配置值，例如 10 次 |
| RATE-003 | 非自然分钟 | 跨分钟边界连续请求 | 不能因为分钟翻页就重置超发 |
| RATE-004 | 等待或跳过 | 超过预算 | 能等待则等待；预算不够则低优先级跳过并写证据 |
| RATE-005 | 不硬编码源名 | 对 Tushare、Coinglass、Finnhub 等分别验证 | 所有限流源使用同一机制，不是只对 Coinglass 特判 |
| RATE-006 | 429 处理 | 真实或模拟远端 429 | 不全链崩溃；有退避、失败证据和兜底 |

## 11. 最终验收报告格式

测试完成后输出一份验收报告，至少包含：

1. 测试版本和提交。
2. 测试时间。
3. 测试人。
4. 环境说明。
5. 全部用例结果统计：通过、失败、阻塞、未测。
6. 四市场报告 run id 和最终报告路径。
7. PDF 文件路径和打开结果。
8. 微信真实发送结果。
9. `/select` 候选缓存和报告交接结果。
10. 数据源调用摘要。
11. 数据缺失清单。
12. 限流证据。
13. 安全脱敏检查结果。
14. P0/P1/P2 缺陷列表。
15. 是否允许进入下一阶段。

## 12. 停止条件

遇到以下情况必须停止继续验收，先修复或让人类决策：

1. 真实 Chrome 路径不可用。
2. UI 无法启动或无法访问。
3. 模型无法配置，导致报告不能真实运行。
4. 数据源密钥缺失且该批次必须验证付费源。
5. 报告出现明显编造数据或假图表。
6. 普通 UI 泄露密钥、路径、run id、hash、artifact 或 provider attempt。
7. worker 可见 provider/path/api_name/api_id/params/fields。
8. `/select` 现场拉全市场或跳过候选缓存。
9. PDF 是伪文件。
10. 微信未真实发送却显示成功。
11. 四市场 prompt/profile fallback 到错误市场。
12. 发现方向性设计问题，需要人类确认。
