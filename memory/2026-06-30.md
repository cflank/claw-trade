## select-current-seed-company-name-regression

- Root cause: `/select 2026-06-29` reused default `data/current-seed-20260626.tar`, not the previously identity-enriched `data/a-share-cn-required-300td-20260608.tar`.
- Prior memory showed the 2026-06-08 A-share seed was rebuilt with real identity sources and `daily_bar company-name missing rows: 0`.
- Current runtime seed facts:
  - `A_SHARE_FACTORY_SEED_PACKAGE=data/current-seed-20260626.tar`.
  - `.runtime/factory-seeds/current-seed-20260626/.../daily_bar` has 244,014 CN_A rows.
  - All 244,014 CN_A `daily_bar.row_json` rows are missing `company_name`.
  - Current seed has no other CN_A dataset carrying company name fields.
- Why UI appeared stuck: after daily bars were loaded, selection tried to resolve missing company names for the full universe; the old repository path performed per-symbol DuckDB/parquet lookups, so the UI stayed in "补数据中" after "读取本地全市场历史日线 1/1".
- Code fix:
  - `DatasetRepository.find_company_names_by_symbol_ids()` now batches large normalized company-name lookups instead of scanning parquet once per symbol.
  - `validate_cn_a_daily_bar_company_names()` now rejects CN_A factory/current seed parquet with missing `company_name`.
  - `restore_a_share_factory_seed.py` and `export_current_seed.py` both use that check, so bad current seed packages fail during export/restore instead of surfacing later in `/select`.
- Live proof against the current bad package now fails explicitly: `missing=244014, rows=244014`, sample symbols `000001.SZ`, `000002.SZ`, `000004.SZ`, `000006.SZ`, `000007.SZ`.
- Remaining data fix: rebuild or replace `data/current-seed-20260626.tar` with real company identity. Do not fill ticker as company name. The extracted 2026-06-08 seed identity covers 5,522 symbols but the current 2026-06-26 seed has 5,566 symbols, leaving 44 symbols requiring another approved identity source such as Baostock/AKShare/Tushare or a local identity file.

## select-cached-empty-and-universe-ref-regression

- Root cause: `/select` 2026-06-30 的全市场补数据链路有三层问题叠加：
  - Tushare `tushare.daily` 对当天 `2026-06-30` 早先返回 HTTP 200 但空数据，provider attempt 记录为 `provider_empty` / `empty_result`，后续被 `cached_empty` 拦住。
  - 旧读取逻辑在 `universe_ref=all_a_shares` 查不到数据时会退到 `universe_ref=None`，导致单票报告数据也可能被误当成全市场选股数据。
  - 修掉兜底后暴露出更深问题：Tushare 全市场刷新实际能返回 5508 行，但 batch 入库时没有带 `universe_ref=all_a_shares`，写出的 columnar manifest `universe_refs=[]`，严格读取仍看不到全市场数据。
- Fix:
  - Selection 全市场 universe refresh batch 设置 `ignore_provider_cache=True` 和 `ignore_cached_empty=True`，不再被旧空缓存或旧成功缓存挡住。
  - Selection universe refresh 生成 provider batch 时写入 `universe_ref=all_a_shares`，normalizer/columnar manifest 会保留该归属。
  - Full-market feature rows 不再从 unscoped/latest single-symbol 数据兜底。
