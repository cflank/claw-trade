## A 股 hot_money_tracker 数据源优先级与 Tushare 修复

- 目标：修复 A 股 frontline 单 worker 测试中 Tushare 成功后仍继续打 AkShare/EastMoney，导致低优先级失败污染数据状态的问题。
- 根因 1：DataNeed planner 把不同 provider 交错排序，导致同一高优先级来源的多个接口没有成组执行。
- 根因 2：执行层拿到满足结果后直接停止，没有“同一成功来源剩余接口继续、换到低优先级来源停止”的逻辑。

- 已改：
  - `src/claw_trade/data_gateway/planner/call_planner.py`：删除 provider 交错排序，改为按来源优先级成组排序。
  - `src/claw_trade/data_gateway/report_evidence.py`：同一 provider 已满足需求后继续执行同 provider 剩余接口，遇到低优先级 provider 停止；`sector_snapshot` 可满足 `sector_flow`。
  - `src/claw_trade/data_gateway/providers/plugins/official_api.py`：补 Tushare 资金流别名与单位默认。
  - 测试更新：`tests/unit/data_gateway/test_data_need_planner.py`、`tests/unit/data_gateway/test_report_evidence.py`、`tests/unit/data_gateway/test_official_api_plugin.py`。

## Coinglass BTC 数据缺口根因修复

- 根因：不是 Coinglass 没能力，也不是远端 10/min 被打爆；数据层在出网前已经生成了错误或不完整的 Coinglass 调用。
- 具体问题：
  - `realtime` 被直接传给 Coinglass 历史类接口的 `interval`，而这些接口需要 `1h/1d` 这类官方 interval。
  - Coinglass symbol 规则用 long-short 文本关键词猜，导致 Hyperliquid / Bitfinex 也被错误传成 `BTCUSDT`。
  - 宽业务项 `链上` 只绑定 Glassnode，没有绑定 Coinglass 的交易所余额和大额转账链上接口。
  - Coinglass CVD 专门 parser 返回 `granularity=1h`，normalizer 使用标准粒度 `hourly`，导致 raw 成功后被误判粒度不一致并丢行。
- 已改：
  - `call_planner.py`：Coinglass `realtime` interval 映射为 `1h`；symbol 是否用合约对改为按真实 path 判断。
  - `coinglass.py`：Coinglass 交易所余额、大额转账同时绑定 `crypto.onchain_metric`。
  - `official_api.py`：CVD parser 输出标准粒度 `hourly`；交易所余额行补 `metric=exchange_balance`。
- 验证：
  - focused：5 个 Coinglass 根因测试通过。
  - 相关回归：`tests/unit/data_gateway/test_data_need_planner.py tests/unit/data_gateway/test_official_api_plugin.py tests/unit/data_gateway/test_report_evidence.py tests/unit/data_gateway/test_dynamic_rate_limit_scheduler.py tests/unit/data_gateway/test_rate_limit_policy.py tests/unit/data_gateway/test_rate_limiter.py tests/contracts/test_official_provider_catalog_contract.py tests/contracts/test_public_data_api_contract.py -q` -> 193 passed。
  - `py_compile` 通过。
