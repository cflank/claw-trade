## Playwright MCP 重复连接事故

- 错误：已有 Chrome 扩展连接时，把 `browser_tabs`、导航和 console 检查分别作为一次性命令执行；每条命令都重新启动 `npx playwright-mcp --extension`，造成重复连接和新页面。
- 根因：把相同 extension token 误当成相同 MCP 会话。token 只负责授权，进程和 client session 才决定是否复用连接。
- 已确认次数：同类错误在对话中至少发生 3 轮；本轮有证据确认连续启动了 3 个一次性 MCP 进程。更早的进程总数无完整日志，不编造精确数字。
- 强制规则：扩展模式只允许一个持久 MCP 进程和一个持续复用的 client session；禁止用多个 one-shot wrapper 串接一个 UI 流程。现有会话不能复用时立即停止，未经人类当轮明确批准不得新建 MCP 进程、Chrome profile、页面或标签。
- 当前验收状态：本轮没有再启动或连接 Chrome。真实微信入站绑定、直接出站和定时报告完成通知均已通过；生产尚未部署。

## 定时通知后回复“发送完整报告”找不到报告

- 根因：定时任务按逻辑主微信投递，任务本身没有固定微信会话来源；通知成功记录保存了报告编号，但微信入站处理只读取聊天内的 `activeReportId`，没有读取“实际成功投递给当前主微信的最新报告”，因此在调用 PDF 之前就错误返回“没有找到可发送的完整报告”。
- 修复：完整报告回复在没有聊天内报告编号和选股报告时，按当前 `account_id + sender_id` 查询成功投递记录；只允许解析到当前绑定后实际投递的报告。以后成功投递同时记录实际收件账号与聊天，换微信后不会继承旧微信报告；历史记录只在投递时间严格晚于当前绑定时间时兼容解析。
